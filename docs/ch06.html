地理定位博客

一个以地图为中心的博客：用户用 Google 账号登录，在地图上点一下就能在那个位置发一篇帖子，点击标记查看帖子和评论。 这一章的主角是状态管理 —— 我们用 Vue 官方推荐的 Pinia 取代原书的 Vuex， 还会学习集成第三方库、作用域插槽、渲染函数和函数式组件。

本章目标

  • 理解为什么需要集中式状态管理，掌握 Pinia 的 state / getters / actions
  • 知道 Vuex 的概念如何对应到 Pinia，以及为什么 mutations 消失了
  • 用 OAuth 弹窗 + postMessage 实现第三方登录
  • 在 Vue 组件里集成命令式的地图库（Leaflet），理解 markRaw / 非响应式变量的必要性
  • 自己实现一个带作用域插槽的组件
  • 在 Vue 3 中写渲染函数、JSX 和函数式组件
  • 写一个 Pinia 插件，让地图位置在刷新后保留补充
  • 用 shallowRef 应对大量数据，在小屏幕上用 Teleport 弹窗显示内容补充

应用全貌

  • 登录页要求用户用 Google 账号登录；
  • 主页面是一张大地图，每篇帖子是一个标记；
  • 点击标记，右侧面板显示地点、帖子内容、评论；
  • 点击地图空白处，右侧面板变成发帖表单，帖子就发在点击的位置；
  • 顶部栏显示当前用户的头像和名字，以及“回到我的位置”和“登出”按钮。

为什么需要状态管理

前两个项目里，我们用一个 reactive() 对象当全局状态。这在小项目里够用，但应用变大后会遇到问题。 想象一个按钮埋在组件树深处，它要打开树另一侧的一个侧边栏：

问题不只是麻烦：当两个组件各自持有一份需要同步的数据时，就有了两个真相来源，一旦不同步，没人知道谁是对的。 集中式状态管理的思想来自 Facebook 的 Flux 架构（React 社区的 Redux 也源于此）：共享数据只放在一个地方（store），并且用规定好的方式修改它。

ⓘ 不是每个项目都需要

原型、小组件、只有几个页面的应用，用第 3、5 章那种 reactive() 对象或组合式函数就够了。当多个页面/组件开始共享复杂的数据和逻辑时，再引入 store。

从 Vuex 到 Pinia

原书使用 Vuex。Pinia 最初是 Vue 核心团队成员 Eduardo（也就是本书的技术审校）为探索 Vuex 5 而写的实验，后来成为 Vue 官方推荐的状态管理库。 Vuex 目前处于维护模式，新项目应使用 Pinia。先看两者的结构差异：

Vuex 概念Pinia 对应说明
new Vuex.Store()createPinia() + defineStore()Pinia 是“很多个小 store”，每个独立定义
statestate（或 setup 写法中的 ref）一样
gettersgetters（或 computed）一样
mutations没有了action 里直接改 state
actions + dispatch('type')actions，直接调用 store.action()就是普通函数
模块 modules + namespaced每个 store 天然独立store 之间直接 import 互相调用
mapGetters / mapActionsstoreToRefs() 或直接 store.xxx组合式 API 下基本不需要辅助函数
strict 模式不需要没有“必须通过 mutation”的规则
vuex-router-sync不需要useRoute() 本身就是响应式的
🔍 mutations 为什么可以去掉

Vuex 要求“只能在同步的 mutation 里改状态”，原因是 DevTools 需要在每次 mutation 前后给状态拍快照，以实现时间旅行调试。 Pinia 借助 Vue 3 的响应式系统直接追踪 state 的每一次变化，并把它们归属到触发它的 action 上， 所以既保留了可追踪性，又省掉了“为每个字段写一个 mutation”的样板代码。

第一个 store：当前用户

Pinia 有两种定义 store 的写法。选项式写法和 Vuex 很像，方便迁移：

import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    user: null,
  }),
  getters: {
    userPicture: (state) => state.user?.profile.photos?.[0]?.value ?? null,
  },
  actions: {
    login() { /* ... */ },
    logout() {
      this.user = null      // 直接修改 state，this 指向 store
    },
  },
})

setup 写法则和组件的 <script setup> 一模一样：ref 就是 state，computed 就是 getter，函数就是 action。本教程使用这种写法：

import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  // state
  const user = ref(null)

  // getters
  const userPicture = computed(() => user.value?.profile.photos?.[0]?.value ?? null)

  // actions
  function logout() {
    user.value = null
  }

  // 必须把所有 state 都返回，DevTools 和 SSR 才能正确处理
  return { user, userPicture, logout }
})
ⓘ 命名约定

defineStore 的第一个参数是 store 的唯一 id（DevTools 里显示的名字）。返回值是一个函数，约定命名为 useXxxStore， 在组件里调用它就能拿到 store 实例 —— 和组合式函数的用法一致。

解构 store：storeToRefs

store 是一个 reactive 对象，直接解构会丢失响应性。要解构 state 和 getter，用 storeToRefs；action 则可以直接解构：

import { storeToRefs } from 'pinia'

const userStore = useUserStore()
const { user, userPicture } = storeToRefs(userStore)   // ✓ 得到 ref，保持响应性
const { logout } = userStore                           // ✓ action 是普通函数，直接取

// const { user } = userStore                         // ✗ 得到的是当时的值，不会更新

用户登录：Google OAuth

在 Google Cloud 控制台配置

⚠ 原书的步骤已经失效

原书第一步是启用“Google+ API”来获取用户资料。Google+ 已在 2019 年关闭，相关 API 不复存在。 现在获取用户的名字和头像，使用的是标准的 OpenID Connect 作用域 openid profile email，不需要单独启用任何 API。

  1. 打开 Google Cloud 控制台，新建一个项目。
  2. 进入 API 和服务 → OAuth 同意屏幕（新版界面叫 Google Auth Platform），填写应用名称、支持邮箱，用户类型选“外部”，测试阶段把自己的账号加为测试用户。
  3. 进入凭据 → 创建凭据 → OAuth 客户端 ID，类型选“Web 应用”：
    • 已获授权的 JavaScript 来源：http://localhost:3000
    • 已获授权的重定向 URI：http://localhost:3000/auth/google/callback（服务器上的回调路由）
  4. 保存后得到客户端 ID和客户端密钥。密钥不要提交到 Git，也不要放进前端代码。

登录流程：弹窗 + postMessage

登录按钮会打开一个弹窗，整个流程如下：

<script setup>
import { onMounted, onBeforeUnmount } from 'vue'
import { useUserStore } from '../stores/user'

const SERVER_ORIGIN = 'http://localhost:3000'
const userStore = useUserStore()

function openGoogleSignin() {
  window.open(`${SERVER_ORIGIN}/auth/google`, 'google_login', 'width=500,height=600')
}

function handleMessage({ data, origin }) {
  // 安全：只接受来自我们服务器的消息
  if (origin !== SERVER_ORIGIN) return
  if (data === 'success') {
    userStore.login()
  }
}

onMounted(() => window.addEventListener('message', handleMessage))
onBeforeUnmount(() => window.removeEventListener('message', handleMessage))
</script>

<template>
  <div class="welcome">
    <h1>欢迎</h1>
    <div class="actions">
      <button @click="openGoogleSignin">使用 Google 登录</button>
    </div>
  </div>
</template>
⚠ 永远检查 postMessage 的 origin

任何网页都能向你的窗口 postMessage。不检查 origin，恶意页面就能伪造“登录成功”之类的消息。

✓ 别忘了清理

在 onMounted 里加到 window 上的监听器，一定要在 onBeforeUnmount 里移除，否则组件销毁后监听器还在，会造成内存泄漏和重复执行。 VueUse 的 useEventListener(window, 'message', handleMessage) 会自动帮你清理。

完整的用户 store

import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { $fetch } from '../plugins/fetch'
import router from '../router'
import { usePostsStore } from './posts'

export const useUserStore = defineStore('user', () => {
  const user = ref(null)

  const userPicture = computed(() => user.value?.profile.photos?.[0]?.value ?? null)

  async function login() {
    try {
      user.value = await $fetch('user')
      if (user.value) {
        // 跳回原本想去的页面
        router.replace(router.currentRoute.value.query.redirect || { name: 'home' })
        // 通知帖子 store：用户登录了
        usePostsStore().onLoggedIn()
      }
    } catch (e) {
      console.warn(e)
    }
  }

  function logout() {
    user.value = null
    $fetch('logout')
    usePostsStore().reset()     // 清空帖子数据
    const current = router.currentRoute.value
    if (current.meta.private) {
      router.replace({ name: 'login', query: { redirect: current.fullPath } })
    }
  }

  // 应用启动时调用：只检查是否已有会话，不做跳转
  async function init() {
    try {
      user.value = await $fetch('user')
    } catch (e) {
      console.warn(e)
    }
  }

  return { user, userPicture, login, logout, init }
})
★ store 之间互相调用

原书用 Vuex 的“根级 action”技巧：在 posts 模块里声明 logout: { root: true, handler }，这样 dispatch 全局的 'logout' 时它也会被调用。 Pinia 里不需要这种隐式机制 —— 在 action 里调用 usePostsStore() 拿到另一个 store，直接调用它的方法，调用关系一目了然。

命令式库 vs. 声明式 Vue

Leaflet 是命令式的：你调用 map.setView()、marker.addTo(map) 来改变地图。Vue 是声明式的：你修改数据，界面自己更新。 集成的关键就是在两者之间搭一座双向的桥：

地图 store

import { defineStore } from 'pinia'
import { ref } from 'vue'
import { usePostsStore } from './posts'

export const useMapStore = defineStore('map', () => {
  // 注意：只存普通的 { lat, lng } 对象，不存 Leaflet 的类实例
  const center = ref({ lat: 48.8538302, lng: 2.2982161 })   // 巴黎埃菲尔铁塔
  const zoom = ref(15)
  const userPosition = ref(null)

  function setCenter(value) { center.value = value }
  function setZoom(value) { zoom.value = value }

  function setUserPosition(value) {
    const first = !userPosition.value
    userPosition.value = value
    if (first) centerOnUser()          // 第一次拿到位置时，自动居中
  }

  function centerOnUser() {
    if (userPosition.value) setCenter({ ...userPosition.value })
  }

  // 地图移动结束：让帖子 store 去加载可见范围内的帖子
  function setBounds(bounds) {
    usePostsStore().fetchPosts({ mapBounds: bounds })
  }

  return { center, zoom, userPosition, setCenter, setZoom, setUserPosition, centerOnUser, setBounds }
})

地图组件

<script setup>
import { ref, watch, onMounted, onBeforeUnmount } from 'vue'
import L from 'leaflet'
import 'leaflet/dist/leaflet.css'
import { useMapStore } from '../stores/map'
import { usePostsStore } from '../stores/posts'

const mapStore = useMapStore()
const postsStore = usePostsStore()

const el = ref(null)   // 模板引用：地图容器
let map = null         // ⚠ 普通变量，不要放进 ref/reactive（原因见下文）
let postsLayer = null
let draftMarker = null

// Leaflet 对象 → 普通对象
const toLatLng = ({ lat, lng }) => ({ lat, lng })
const toBounds = (b) => ({ ne: toLatLng(b.getNorthEast()), sw: toLatLng(b.getSouthWest()) })

// 用 Material Icons 做标记图标（也顺便绕开了 Leaflet 默认图标在打包工具里的路径问题）
const icon = (name, cls = '') => L.divIcon({
  className: `map-marker ${cls}`,
  html: `<i class="material-icons">${name}</i>`,
  iconSize: [32, 32],
  iconAnchor: [16, 32],
})

onMounted(() => {
  // ① 创建地图
  map = L.map(el.value, { zoomControl: false })
    .setView(mapStore.center, mapStore.zoom)

  L.tileLayer('https://tile.openstreetmap.org/{z}/{x}/{y}.png', {
    maxZoom: 19,
    attribution: '&copy; OpenStreetMap contributors',
  }).addTo(map)

  postsLayer = L.layerGroup().addTo(map)

  // ② 地图事件 → store
  map.on('moveend', () => {
    mapStore.setCenter(toLatLng(map.getCenter()))
    mapStore.setZoom(map.getZoom())
    mapStore.setBounds(toBounds(map.getBounds()))
  })
  map.on('click', (e) => {
    postsStore.setDraftLocation({ position: toLatLng(e.latlng) })
  })

  // 用户位置（浏览器会请求定位权限）
  map.on('locationfound', (e) => mapStore.setUserPosition(toLatLng(e.latlng)))
  map.locate({ watch: true })

  mapStore.setBounds(toBounds(map.getBounds()))
  renderPosts()
})

// ③ store → 地图
watch(() => mapStore.center, (c) => {
  if (!map) return
  const cur = map.getCenter()
  if (cur.lat !== c.lat || cur.lng !== c.lng) map.setView(c)   // 避免和 moveend 互相触发
})

function renderPosts() {
  postsLayer.clearLayers()
  for (const post of postsStore.posts) {
    const selected = post._id === postsStore.currentPost?._id
    L.marker(post.position, { icon: icon('face', selected ? 'selected' : ''), zIndexOffset: 5 })
      .on('click', () => postsStore.selectPost(post._id))
      .addTo(postsLayer)
  }
}
// 列表被替换、新增一项、或选中项变化时重画（length 让 push 也能触发）
watch(() => [postsStore.posts, postsStore.posts.length, postsStore.currentPost], renderPosts)

// 草稿的“虚影”标记
watch(() => postsStore.draft?.position, (pos) => {
  draftMarker?.remove()
  draftMarker = pos
    ? L.marker(pos, { icon: icon('add_circle', 'draft'), opacity: 0.75, interactive: false }).addTo(map)
    : null
})

// ④ 清理
onBeforeUnmount(() => {
  map.remove()
  map = null
})
</script>

<template>
  <div class="blog-map" ref="el"></div>
</template>

⚠ 为什么地图实例不能放进 ref()

ref() / reactive() 会把对象深度包装成 Proxy。Leaflet 的地图对象内部有成千上万个属性和 DOM 引用， 被代理后不仅性能很差，库内部 this === map 之类的身份比较还可能失败，导致各种诡异 bug。第三方库的实例要么用普通变量保存， 要么用 shallowRef()（只追踪 .value 的替换）或 markRaw(obj)（标记为永不代理）。 同理，store 里只存 { lat, lng } 这样的普通数据。

Pinia 插件：记住地图位置补充

每次刷新页面，地图都会跳回埃菲尔铁塔。如果能记住用户上次看的位置和缩放级别就好了。最直接的办法是在 map store 里写一个 watch 存到 localStorage —— 但以后别的 store 也想持久化时，又要再写一遍。Pinia 的插件机制可以把这种“每个 store 都可能需要”的能力抽出来： 

// 一个极简的持久化插件
export function persistPlugin({ store, options }) {
  const config = options.persist           // 读取 defineStore 第三个参数里的自定义选项
  if (!config) return

  const key = config.key ?? `pinia-${store.$id}`
  const pick = (state) => config.pick
    ? Object.fromEntries(config.pick.map((k) => [k, state[k]]))
    : state

  // ① 创建时：恢复上次保存的值
  const saved = localStorage.getItem(key)
  if (saved) store.$patch(JSON.parse(saved))

  // ② 之后每次变化：保存
  store.$subscribe((_mutation, state) => {
    localStorage.setItem(key, JSON.stringify(pick(state)))
  })
}

import { persistPlugin } from './stores/plugins/persist'

const pinia = createPinia()
pinia.use(persistPlugin)
app.use(pinia)

export const useMapStore = defineStore('map', () => {
  // ……和之前完全一样……
}, {
  persist: { pick: ['center', 'zoom'] },   // 只保存这两项，userPosition 不保存
})
  • store.$patch(obj)：一次性修改多个 state；
  • store.$subscribe(cb)：state 每次变化都会调用（类似对整个 store 的 watch）；
  • store.$id：defineStore 的第一个参数。
✓ 现成的插件

社区插件 pinia-plugin-persistedstate 做的就是这件事，还支持选择存储方式（sessionStorage、Cookie）、序列化方式、SSR 等。 插件还可以给每个 store 加上新的属性或方法（比如统一的 $reset、日志、撤销重做），是扩展 Pinia 的标准方式。

import { ref, onMounted, onBeforeUnmount } from 'vue'

export function useMediaQuery(query) {
  const matches = ref(false)
  let mql
  const update = () => { matches.value = mql.matches }

    mql.addEventListener('change', update)

  return matches
}

加载帖子：处理竞态条件

每次地图移动结束，都要加载可见范围内的帖子。这里有一个经典问题： 

const sameBounds = (a, b) => a && b &&
  a.ne.lat === b.ne.lat && a.ne.lng === b.ne.lng &&
  a.sw.lat === b.sw.lat && a.sw.lng === b.sw.lng

async function fetchPosts({ mapBounds: bounds, force = false }) {
  if (!force && sameBounds(mapBounds.value, bounds)) return   // 范围没变，不重复加载

  const requestId = ++fetchPostsUid
  const { ne, sw } = bounds
  const query = new URLSearchParams({
    ne: `${ne.lat},${ne.lng}`,
    sw: `${sw.lat},${sw.lng}`,
  })
  const result = await $fetch(`posts?${query}`)

  // 期间又发起了新的请求？那这个结果已经过期了
  if (requestId === fetchPostsUid) {
    posts.value = result
    mapBounds.value = bounds
  }
}
✓ URLSearchParams

原书手动拼接查询字符串并调用 encodeURIComponent。浏览器内置的 URLSearchParams 会自动编码，更不容易出错。

帖子很多时：shallowRef补充

ref([]) 是深层响应式的：每个帖子对象、帖子里的每个字段（包括 position、author 里的嵌套对象）都会被包装成 Proxy。 帖子只有几十条时毫无问题；但如果地图缩小到整个城市、一次返回几千条帖子，这些代理的创建和追踪开销就会变得明显。

我们的帖子列表正好符合“整体替换”的特点：fetchPosts 每次都用新数组替换旧数组。改成 shallowRef 只需改一处，再把唯一一处“逐项修改”的地方改成替换：

import { ref, shallowRef, computed } from 'vue'

const posts = shallowRef([])        // 只追踪整体替换

// createPost 里原来是 posts.value.push(result)：浅层 ref 检测不到 push
posts.value = [...posts.value, result]
⚠ 用之前先测量

shallowRef 的代价是：以后在模板里修改某个帖子的属性（比如点赞数 +1）界面不会更新，必须替换整个对象或调用 triggerRef(posts)。 不要预先到处使用它。先用 Vue DevTools 的性能面板或浏览器 Performance 面板确认响应式开销真的是瓶颈，再有针对性地优化。 同类的工具还有 shallowReactive 和 markRaw（本章地图一节已经用过“不要把第三方实例变成响应式”的思路）。

地点信息与作用域插槽

右侧面板顶部要显示帖子所在地点的名称和地址。原书使用 vue-googlemaps 提供的 <googlemaps-geocoder> 组件，它通过作用域插槽把地理编码结果交给你。 我们没有现成的组件 —— 那就自己写一个，这正是理解作用域插槽的最好方式。

什么是作用域插槽

普通插槽：父组件决定“放什么内容”，但内容只能使用父组件的数据。 作用域插槽：子组件在 <slot> 上绑定属性，把子组件的数据传给插槽内容使用。

实现一个无渲染的地理编码组件

我们用 OpenStreetMap 的 Nominatim 服务做“反向地理编码”（坐标 → 地址）：

<script setup>
import { ref, watch, onWatcherCleanup } from 'vue'

const props = defineProps({
  position: { type: Object, required: true },   // { lat, lng }
})

const result = ref(null)
const loading = ref(false)

watch(() => props.position, async ({ lat, lng }) => {
  const controller = new AbortController()
  onWatcherCleanup(() => controller.abort())   // 位置变了：取消上一次请求（Vue 3.5+）

  loading.value = true
  result.value = null
  try {
    const params = new URLSearchParams({ format: 'jsonv2', lat, lon: lng, 'accept-language': 'zh-CN' })
    const response = await fetch(`https://nominatim.openstreetmap.org/reverse?${params}`,
                                 { signal: controller.signal })
    result.value = await response.json()
  } catch (e) {
    if (e.name !== 'AbortError') console.error(e)
  } finally {
    loading.value = false
  }
}, { immediate: true, deep: true })
</script>

<template>
  <!-- 不渲染任何自己的元素，只把数据交给插槽 -->
  <slot :result="result" :loading="loading" />
</template>

用渲染函数，一行就够了：

import { h } from 'vue'

export default {
  props: ['level'],
  setup(props, { slots }) {
    // setup 返回一个函数 = 渲染函数，每次需要重新渲染时调用
    return () => h(
      `h${props.level}`,                                 // 标签名
      { class: { 'important-title': props.level <= 3 },  // 属性
        onClick: () => console.log('你点击了标题') },
      slots.default?.(),                                 // 子节点：默认插槽的内容
    )
  },
}

Comment.props = ['comment']   // 可选：声明 props
★ Vue 3 变化：函数式组件不再是性能利器

Vue 3 大幅优化了普通组件的创建开销，官方文档明确指出：普通组件和函数式组件的性能差异已经可以忽略不计。 functional: true 选项和 <template functional> 写法都被移除了。 所以评论组件写成普通的 SFC 完全没问题；函数式组件现在主要是一种“写起来更轻”的风格选择。

<script setup>
import { ref, computed } from 'vue'
import { storeToRefs } from 'pinia'
import { usePostsStore } from '../../stores/posts'
import { formatDate } from '../../utils/format'
import Comment from './Comment.jsx'

const postsStore = usePostsStore()
const { selectedPostDetails: details } = storeToRefs(postsStore)

const commentContent = ref('')
const commentFormValid = computed(() => commentContent.value.trim().length > 0)

function submitComment() {
  if (!commentFormValid.value) return
  postsStore.sendComment({
    post: details.value,
    comment: { content: commentContent.value },
  })
  commentContent.value = ''
}
</script>

<template>
  <div class="post-content">
    <template v-if="details">
      <div class="title">
        <img :src="details.author.profile.photos[0].value">
        <span>
          <span>{{ details.title }}</span>
          <span class="info">
            <span class="name">{{ details.author.profile.displayName }}</span>
            <span class="date">{{ formatDate(details.date) }}</span>
          </span>
        </span>
      </div>
      <div class="content">{{ details.content }}</div>

      <div class="comments">
        <Comment v-for="(comment, index) of details.comments" :key="index" :comment="comment" />
      </div>

      <div class="actions">
        <button type="button" class="icon-button secondary" @click="postsStore.unselectPost()">
          <i class="material-icons">close</i>
        </button>
        <input v-model="commentContent" placeholder="写一条评论" @keyup.enter="submitComment">
        <button type="button" class="icon-button" :disabled="!commentFormValid" @click="submitComment">
          <i class="material-icons">send</i>
        </button>
      </div>
    </template>
    <Loading v-else />
  </div>
</template>

@keyup.enter 是带按键修饰符的事件监听：只有按下回车时才调用。
