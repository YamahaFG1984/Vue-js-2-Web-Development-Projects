工单列表和 FAQ 页面几乎一样，用同一个组合式函数：

<script setup>

<template>

日期格式化：原书安装 moment 并注册过滤器 {{ ticket.date | date }}。我们用一个普通的工具函数：

const dateFormatter = new Intl.DateTimeFormat('zh-CN', { dateStyle: 'medium' })

export function formatDate(value) {
  return dateFormatter.format(new Date(value))
}
ⓘ tickets?.length 是什么

?. 是可选链：如果 tickets 是 null 或 undefined，整个表达式直接得到 undefined 而不会报错。 数据还没回来时 tickets 是 null，这样写就很安全。

会话过期

会话过一段时间会失效（这个服务器设置为 3 小时），服务器重启也会让会话丢失。这时请求私有接口会返回 403， 而页面还以为自己处于登录状态，加载动画永远转下去。最合适的处理位置是所有请求的必经之路 —— $fetch： 

import state from '../state'
import router from '../router'

export async function $fetch(url, options) {
  // ...
  const response = await fetch(`${baseUrl}${url}`, finalOptions)
  if (response.ok) {
    return await response.json()
  } else if (response.status === 403) {
    // 会话失效：登出
    state.user = null
    // 如果当前在私有页面，去登录页
    const current = router.currentRoute.value     // Vue Router 4：currentRoute 是一个 ref
    if (current.meta.private) {
      router.replace({ name: 'login', query: { redirect: current.fullPath } })
    }
    throw new Error('会话已过期，请重新登录')
  } else {
    const message = await response.text()
    const error = new Error(message)
    error.response = response
    throw error
  }
}

用 replace 而不是 push：否则用户点“后退”会再次进入私有页、再次被送回登录页，陷入循环。

嵌套路由

工单页面里还要能切换到“新建工单”表单和“工单详情”。用嵌套路由来组织：/tickets 路由有自己的子路由， 而 TicketsLayout 组件里放第二个 <RouterView> 来显示它们： 

import Tickets from './components/Tickets.vue'
import NewTicket from './components/NewTicket.vue'

const routes = [
  // ...
  {
    path: '/tickets',
    component: TicketsLayout,
    meta: { private: true },
    children: [
      { path: '', name: 'tickets', component: Tickets },          // 默认子路由
      { path: 'new', name: 'new-ticket', component: NewTicket },  // /tickets/new
    ],
  },
]

空字符串路径的子路由是默认子路由，所以 name: 'tickets' 要从父路由移到它身上。

<script setup>
import { useRouter } from 'vue-router'
const router = useRouter()
</script>

<template>
  <main class="tickets-layout">
    <h1>我的工单</h1>
    <div class="actions">
      <button v-if="$route.name !== 'tickets'" class="secondary"
              @click="router.push({ name: 'tickets' })">查看所有工单</button>
      <button v-if="$route.name !== 'new-ticket'"
              @click="router.push({ name: 'new-ticket' })">新建工单</button>
    </div>
    <RouterView />
  </main>
</template>
⚠ Vue Router 4 变化：RouterLink 的 tag 属性被移除

原书用 <router-link tag="button"> 把链接渲染成按钮。tag 在 Vue Router 4 中被移除了。 可以像上面那样用普通按钮 + router.push；或者用 custom + 作用域插槽完全自定义渲染： 

<RouterLink :to="{ name: 'tickets' }" custom v-slot="{ navigate }">
  <button class="secondary" @click="navigate">查看所有工单</button>
</RouterLink>

（从语义上讲，“跳到另一个页面”本来就应该是链接 <a>，用 CSS 把它做成按钮的样子通常是更好的选择。）

嵌套路由与守卫：原书的 bug 在 v4 里自动消失了

原书在这里发现了一个漏洞：登出后仍能进入工单页！因为 Vue Router 3 中 to 是目标子路由（''），它自己没有 private 标记， 标记在父路由上。原书的解决办法是检查所有匹配的路由记录：to.matched.some(r => r.meta.private)。

★ Vue Router 4：to.meta 会合并所有父级的 meta

在 Vue Router 4 中，to.meta 是从父到子所有匹配记录的 meta 合并后的结果。所以我们一开始写的 to.meta.private 对子路由同样生效，不需要改。to.matched 依然存在，需要逐层检查时仍可使用。

返回列表时保留状态：KeepAlive补充

试一下这个操作：在工单列表里往下滚动一段（或者在搜索框里输入了筛选关键字），点开一张工单，再点“查看所有工单”返回。 列表回到了顶部，筛选条件也没了，还重新显示了一次加载动画 —— 因为离开列表页时 Tickets 组件被销毁了，回来时是一个全新的实例。

Vue 内置的 <KeepAlive> 组件可以把切换出去的组件缓存起来，而不是销毁，下次切回来时直接复用：

配合 <RouterView> 的作用域插槽使用（和后面“路由过渡”一节的写法类似）：

<RouterView v-slot="{ Component }">
  <KeepAlive include="Tickets" :max="5">
    <component :is="Component" />
  </KeepAlive>
</RouterView>
  • include / exclude：按组件名决定缓存哪些。使用 <script setup> 的单文件组件会自动以文件名作为组件名（Tickets.vue → Tickets）；也可以用 defineOptions({ name: 'Tickets' }) 显式指定。
  • max：最多缓存几个实例，超出时淘汰最久没用的那个（LRU）。

被缓存的组件不会再执行 setup，但有两个专门的生命周期钩子。比如每次回到列表时，悄悄刷新一下数据：

import { onActivated, onDeactivated } from 'vue'

const { data: tickets, loading, refresh } = useRemoteData('tickets')

onActivated(() => {
  refresh()          // 回到列表：后台刷新（旧数据先显示着，不会闪加载动画）
})
onDeactivated(() => {
  // 离开列表：可以在这里暂停定时器、轮询等
})
⚠ 缓存不是免费的

被缓存的组件会一直占用内存，它里面的定时器、事件监听也不会因为“离开页面”而停止（要在 onDeactivated 里暂停）。 只缓存那些重新创建代价高、或者用户希望保留状态的页面（列表、长表单、多标签页），并用 max 限制数量。

让 FormInput 支持多行文本

描述需要 <textarea>。让 FormInput 在 type="textarea" 时渲染 textarea —— 又见动态组件 <component :is>，它的 is 也可以是 HTML 标签名：

const element = computed(() => props.type === 'textarea' ? 'textarea' : 'input')

<component :is="element" v-model="model" class="input" :class="inputClass"
           :name="name" :type="type" :placeholder="placeholder" />

透传属性 $attrs

textarea 有 rows，input 有 maxlength、required……给每个都声明一个 prop 太繁琐了。 没有被声明为 prop 的属性会进入 $attrs，我们可以用 v-bind="$attrs" 把它们一股脑儿转给内部的输入元素： 

<script setup>
import { computed } from 'vue'

// 不要把未声明的属性自动加到根元素 div 上
defineOptions({ inheritAttrs: false })

const model = defineModel({ required: true })
const props = defineProps({
  name: { type: String },
  type: { type: String, default: 'text' },
  placeholder: { type: String },
  invalid: { type: Boolean, default: false },
})

const inputClass = computed(() => ({ invalid: props.invalid }))
const element = computed(() => props.type === 'textarea' ? 'textarea' : 'input')
</script>

<template>
  <div class="row">
    <component
      :is="element"
      v-model="model"
      class="input"
      :class="inputClass"
      :name="name"
      :type="element === 'input' ? type : undefined"
      :placeholder="placeholder"
      v-bind="$attrs"
    />
  </div>
</template>
ⓘ 和原书的两处不同
  • 原书只写了 v-bind="$attrs"，但没有关掉 inheritAttrs，于是 rows 等属性会同时出现在外层 div 和 textarea 上。
  • Vue 3 的 $attrs 还包含 class、style 和事件监听器（Vue 2 里它们是分开的 $listeners），所以透传更彻底。

备份用户输入

为了更好的体验，自动把用户正在填写的内容备份到 localStorage：浏览器崩溃、误刷新、甚至会话过期被踢到登录页，回来后内容都还在。 原书写了一个 PersistantData mixin，我们写成组合式函数： 

import { ref, watch } from 'vue'

// 一个会自动存到 localStorage 的 ref
export function usePersistentRef(key, defaultValue) {
  const saved = localStorage.getItem(key)
  const value = ref(saved !== null ? JSON.parse(saved) : defaultValue)

  watch(value, (val) => {
    localStorage.setItem(key, JSON.stringify(val))
  }, { deep: true })

  return value
}

在 NewTicket.vue 里，只需要把两个 ref('') 换掉：

import { usePersistentRef } from '../composables/usePersistentRef'

const title = usePersistentRef('NewTicket.title', '')
const description = usePersistentRef('NewTicket.description', '')
原书 · mixin（约 30 行）
mixins: [
  PersistantData('NewTicket', [
    'title',
    'description',
  ]),
],
// mixin 内部：用 reduce 动态生成 watch 对象，
// 再加 created 恢复、beforeDestroy 保存……
Vue 3 · 组合式函数（约 10 行）
const title =
  usePersistentRef('NewTicket.title', '')
const description =
  usePersistentRef('NewTicket.description', '')
// 就是两个 ref，用法和普通 ref 完全一样

表单进阶：校验与复合组件补充

回头看看上篇写的登录表单和这一篇的新工单表单，还有几个不够好的地方：

  • 校验规则散落在一堆计算属性里（retypePasswordError、signupValid、valid……），规则一多就很难维护；
  • 只有“两次密码不一致”有提示，其他错误（用户名太短、邮箱格式不对）用户根本不知道错在哪；
  • 提交过程中，输入框还能继续编辑，按钮也不知道表单正在提交。

这一节用三个工具解决它们：VeeValidate + Zod 负责校验，provide/inject 让表单的子组件自动知道表单状态，defineExpose 让父组件可以调用表单的方法。

用 Zod 描述规则，用 VeeValidate 管理表单

npm install vee-validate @vee-validate/zod zod

Zod 用一个“模式（schema）”声明数据应该长什么样；VeeValidate 根据模式管理每个字段的值、错误、是否被碰过，以及整个表单的提交状态： 

<script setup>
import { useForm } from 'vee-validate'
import { toTypedSchema } from '@vee-validate/zod'
import { z } from 'zod'

const signupSchema = toTypedSchema(
  z.object({
    username: z.string().min(3, '用户名至少 3 个字符'),
    email: z.email('邮箱格式不正确'),
    password: z.string().min(8, '密码至少 8 位'),
    password2: z.string(),
  }).refine((data) => data.password === data.password2, {
    message: '两次输入的密码不一致',
    path: ['password2'],                // 错误显示在哪个字段上
  })
)

const { defineField, errors, handleSubmit, isSubmitting, meta } = useForm({
  validationSchema: signupSchema,
})

// 每个字段：一个 ref（绑定 v-model）+ 一组属性（失焦时触发校验等）
const [username, usernameAttrs] = defineField('username')
const [email, emailAttrs] = defineField('email')
const [password, passwordAttrs] = defineField('password')
const [password2, password2Attrs] = defineField('password2')

// handleSubmit：先完整校验，全部通过才调用；values 就是校验后的数据
const signup = handleSubmit(async (values) => {
  await $fetch('signup', { method: 'POST', body: JSON.stringify(values) })
})
</script>

给 FormInput 加一个 error prop 来显示错误信息，模板就很直观了：

<form @submit="signup">
  <FormInput name="username" v-model="username" v-bind="usernameAttrs"
             placeholder="用户名" :error="errors.username" />
  <FormInput name="email" type="email" v-model="email" v-bind="emailAttrs"
             placeholder="邮箱" :error="errors.email" />
  <FormInput name="password" type="password" v-model="password" v-bind="passwordAttrs"
             placeholder="密码" :error="errors.password" />
  <FormInput name="verify-password" type="password" v-model="password2" v-bind="password2Attrs"
             placeholder="再次输入密码" :error="errors.password2" />
  <button type="submit" :disabled="isSubmitting">创建账号</button>
</form>

<!-- props 里加上 error: String，invalid 改为由 error 推导 -->
<div class="row">
  <component :is="element" v-model="model" class="input" :class="{ invalid: error }" v-bind="$attrs" />
  <div v-if="error" class="field-error">{{ error }}</div>
</div>
ⓘ 什么时候显示错误

VeeValidate 默认在字段失焦和提交时校验，而不是用户每敲一个字就报错 —— 还没输完就满屏红字的体验很差。 v-bind="usernameAttrs" 正是把这些事件（onBlur 等）绑定到输入框上。另外，Zod 4 起邮箱写作 z.email()，老版本写作 z.string().email()。

✓ 另一个选择：FormKit

FormKit 走的是“组件化表单”路线：用 <FormKit type="email" validation="required|email" /> 一个组件搞定输入框、标签、校验和错误提示，适合表单特别多的后台系统。

复合组件：用 provide/inject 共享表单状态

第三个问题：提交过程中，所有输入框都应该被禁用。最直接的办法是给每个 FormInput 传一个 :disabled="busy" —— 重复又容易漏。 更好的做法是让 SmartForm 把自己的状态 provide 出去，里面的每个 FormInput 自己 inject： 

// 用 Symbol 作为 key，避免和别的 provide 撞名
export const FormKey = Symbol('form')

import { provide, readonly } from 'vue'
import { FormKey } from './formContext'

// busy、error 是前面已有的 ref；只读地提供出去，子组件不能改
provide(FormKey, {
  busy: readonly(busy),
  error: readonly(error),
})

import { inject, computed } from 'vue'
import { FormKey } from './formContext'

// 第二个参数是默认值：FormInput 不在 SmartForm 里使用时也不会报错
const form = inject(FormKey, null)
const disabled = computed(() => form?.busy.value ?? false)
// 模板里：<component :is="element" … :disabled="disabled" />
🔍 TypeScript：带类型的 InjectionKey（点击展开） 
import type { InjectionKey, Ref } from 'vue'

export interface FormContext {
  busy: Readonly<Ref<boolean>>
  error: Readonly<Ref<string | null>>
}
export const FormKey: InjectionKey<FormContext> = Symbol('form')

// inject(FormKey) 的返回值会被自动推断为 FormContext | undefined

作用域插槽 + defineExpose：让父组件更灵活

还有两个小改进。第一，“提交”按钮写在父组件的 #actions 插槽里，它也想知道表单是否正在提交（显示“提交中……”）。把状态通过作用域插槽传出去：

<!-- SmartForm.vue 里 -->
<slot name="actions" :busy="busy" :valid="valid" />

<!-- 使用时 -->
<template #actions="{ busy }">
  <button type="submit" :disabled="busy">{{ busy ? '提交中……' : '提交工单' }}</button>
</template>

第二，提交成功后父组件想清空表单的错误信息。<script setup> 组件默认是封闭的：父组件通过模板引用拿到它，也访问不到里面的任何东西。 需要对外开放的方法，用 defineExpose 明确列出： 

<script setup>
function reset() {
  error.value = null
}
defineExpose({ reset })          // 只暴露 reset，其他内部状态仍然是私有的
</script>

<script setup>
import { useTemplateRef } from 'vue'
const form = useTemplateRef('form')

async function operation() {
  await $fetch('tickets/new', { /* ... */ })
  form.value.reset()             // 调用子组件暴露的方法
}
</script>

<template>
  <SmartForm ref="form" title="新工单" :operation="operation" :valid="valid">…</SmartForm>
</template>
★ 组件之间的几种通信方式，怎么选
方式方向适合
props / emit父 ⇄ 子绝大多数情况，首选
v-model / defineModel父 ⇄ 子（双向）表单类组件

高级路由功能

动态路由参数

最后一个页面是工单详情，显示某一张工单。URL 里要带上工单的 id，这就要用到动态路由匹配：路径中以冒号开头的段是参数，会出现在 route.params 里。

路由模式示例路径route.params
/tickets/:id/tickets/abc{ id: 'abc' }
/tickets/:id/comments/:comId/tickets/abc/comments/42{ id: 'abc', comId: '42' }
/files/:path(.*)/files/a/b/c.txt{ path: 'a/b/c.txt' }（自定义正则）
/users/:id?/users{ id: '' }（可选参数）
 
children: [
  { path: '', name: 'tickets', component: Tickets },
  { path: 'new', name: 'new-ticket', component: NewTicket },
  { path: ':id', name: 'ticket', component: Ticket, props: true },
],
ⓘ 顺序不再重要

new 和 :id 都能匹配 /tickets/new。Vue Router 4 会按“具体程度”自动排序：静态路径优先于动态参数，所以 new 总是赢，和书写顺序无关。

列表里的标题改成指向详情页的链接：

<RouterLink :to="{ name: 'ticket', params: { id: ticket._id } }">
  {{ ticket.title }}
</RouterLink>

用 props 解耦组件和路由

Ticket 组件可以直接读 route.params.id，但那样它就和路由绑死了，没法在别处复用（比如在弹窗里显示一张工单）。 更好的做法是让组件接收一个普通的 id prop，由路由把参数“喂”给它 —— 这就是路由配置里 props: true 的作用：

props 的三种写法：

  • props: true：把所有 params 作为 props 传入；
  • props: route => ({ id: route.params.id, page: Number(route.query.page) })：函数，最灵活，可以组合静态值、转换类型、改名；
  • props: { id: 'abc' }：静态对象。

参数变化时重新加载

现在 useRemoteData 只接受固定字符串。但工单 id 会变（从一张工单点到另一张时，Vue Router 会复用同一个 Ticket 组件实例，只改 prop）， 我们需要在 id 变化时重新请求。让组合式函数也接受一个getter 函数或 ref： 

import { ref, watch, toValue } from 'vue'
import { $fetch } from '../plugins/fetch'

// url 可以是：字符串 / ref / getter 函数
export function useRemoteData(url) {
  const data = ref(null)
  const error = ref(null)
  const loading = ref(false)

  async function load(currentUrl) {
    loading.value = true
    error.value = null
    try {
      data.value = await $fetch(currentUrl)
    } catch (e) {
      console.error(e)
      error.value = e
    } finally {
      loading.value = false
    }
  }

  // toValue：统一取出“当前的值”；它依赖的响应式数据变化时，watch 会重新执行
  watch(() => toValue(url), load, { immediate: true })

  return { data, error, loading, refresh: () => load(toValue(url)) }
}

<script setup>
import { useRemoteData } from '../composables/useRemoteData'
import { formatDate } from '../utils/format'

const props = defineProps({
  id: { type: String, required: true },
})

// 传入 getter：props.id 变化时自动重新请求
const { data: ticket, loading } = useRemoteData(() => `ticket/${props.id}`)
</script>

这对应原书在 mixin 里用 this.$watch(fn, ..., { immediate: true }) 支持动态路径的做法。

🔍 进阶：竞态条件（点击展开）

用户快速从工单 A 点到工单 B：A 的请求还没回来，B 的请求已经发出。如果 A 的响应后到，页面上就会显示 A 的内容 —— 这叫竞态条件。 Vue 3.5 的 onWatcherCleanup 配合 AbortController 可以在 id 变化时取消旧请求： 

import { watch, onWatcherCleanup } from 'vue'

watch(() => toValue(url), async (currentUrl) => {
  const controller = new AbortController()
  onWatcherCleanup(() => controller.abort())   // 下次触发前先取消上一次
  data.value = await $fetch(currentUrl, { signal: controller.signal })
}, { immediate: true })

这正是 TanStack Query 这类库替你处理掉的细节之一。

⚠ Vue Router 4 变化：不再支持 path: '*'

原书的 { path: '*' } 在 Vue Router 4 中会报错，必须写成带自定义正则的参数 '/:pathMatch(.*)*'。因为路由会按具体程度自动排序，它放在哪里都行。

路由过渡动画

原书直接把 <router-view> 包在 <transition> 里。Vue Router 4 中 <RouterView> 不能再直接被 <Transition> 包裹， 而是通过作用域插槽把当前组件交给你，你自己用 <component :is> 渲染： 

<RouterView v-slot="{ Component }">
  <Transition name="fade" mode="out-in">
    <component :is="Component" />
  </Transition>
</RouterView>

mode="out-in" 表示先让旧页面离开、再让新页面进入，避免两个页面同时出现挤在一起。

✓ 这个插槽还能做更多事

同样的模式可以包一层 <KeepAlive> 来缓存页面状态，或者根据 route.meta.transition 给不同页面设置不同的过渡效果。

滚动行为

切换路由时，可以控制页面滚动位置：回到顶部、跳到锚点，或者在用户点“后退”时恢复之前的位置。

const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) {
      return savedPosition            // 前进/后退：恢复之前的位置
    }
    if (to.hash) {
      return { el: to.hash }          // 有锚点：滚到对应元素
    }
    return { top: 0 }                 // 其他：回到顶部
  },
})
ⓘ 返回值的格式变了

原书返回 { x: 0, y: 0 } 和 { selector: '#foo' }；Vue Router 4 对齐了浏览器原生的 scrollTo，改为 { left, top } 和 { el: '#foo' }，还可以加 behavior: 'smooth'。

路由懒加载

原书没有提到，但对真实项目非常重要：把 component 写成一个返回 import() 的函数，这个页面就会被打包成单独的文件， 第一次访问时才下载。用户打开首页时，不需要下载工单页的代码： 

const routes = [
  { path: '/', name: 'home', component: Home },                       // 首页：直接导入
  { path: '/faq', name: 'faq', component: () => import('./components/FAQ.vue') },
  {
    path: '/tickets',
    component: () => import('./components/TicketsLayout.vue'),
    meta: { private: true },
    children: [ /* 子路由也可以懒加载 */ ],
  },
]

最终的路由配置

import { createRouter, createWebHistory } from 'vue-router'
import state from './state'
import Home from './components/Home.vue'

const routes = [
  { path: '/', name: 'home', component: Home },
  { path: '/faq', name: 'faq', component: () => import('./components/FAQ.vue') },
  { path: '/login', name: 'login', component: () => import('./components/Login.vue'), meta: { guest: true } },
  {
    path: '/tickets',
    component: () => import('./components/TicketsLayout.vue'),
    meta: { private: true },
    children: [
      { path: '', name: 'tickets', component: () => import('./components/Tickets.vue') },
      { path: 'new', name: 'new-ticket', component: () => import('./components/NewTicket.vue') },
      { path: ':id', name: 'ticket', component: () => import('./components/Ticket.vue'), props: true },
    ],
  },
  { path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('./components/NotFound.vue') },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition
    if (to.hash) return { el: to.hash }
    return { top: 0 }
  },
})

router.beforeEach((to) => {
  if (to.meta.private && !state.user) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  if (to.meta.guest && state.user) {
    return { name: 'home' }
  }
})

export default router

错误处理补充

到目前为止，我们只在 SmartForm 和 useRemoteData 里处理了请求错误。但应用里还可能发生其他错误：组件渲染时访问了 undefined 的属性、 某个第三方库抛出异常、部署新版本后用户浏览器里的旧页面加载不到懒加载的代码块……不处理的话，轻则控制台报错，重则整个页面白屏。 一个稳健的应用应该分层处理错误：

组件级：错误边界

<script setup>
import { ref, onErrorCaptured } from 'vue'

const error = ref(null)

onErrorCaptured((err, instance, info) => {
  error.value = err
  console.error('组件出错：', info, err)
  return false              // 返回 false：错误到此为止，不再向上传播
})
</script>

<template>
  <div v-if="error" class="error-box">
    <p>这部分内容出了点问题。</p>
    <button @click="error = null">重试</button>
  </div>
  <slot v-else />
</template>

<!-- 工单详情出错，不会影响外面的布局和菜单 -->
<ErrorBoundary :key="$route.fullPath">     <!-- 换页面时用 key 重置错误状态 -->
  <RouterView />
</ErrorBoundary>

全局：errorHandler 与路由错误

app.config.errorHandler = (err, instance, info) => {
  console.error('[全局错误]', info, err)
  // 生产环境上报到监控服务，例如：Sentry.captureException(err)
}

// 部署新版本后，旧页面去请求已被删除的代码块会失败：直接刷新页面加载新版本
router.onError((error, to) => {
  if (/Failed to fetch dynamically imported module|Loading chunk/i.test(error.message)) {
    window.location.assign(to.fullPath)
  }
})
✓ 生产环境的错误监控

用户遇到的错误你在自己的电脑上看不到。Sentry 等服务提供了 Vue 专用的 SDK（@sentry/vue）， 会自动挂到 errorHandler 上，收集错误堆栈、发生在哪个组件、用户之前做了什么操作，配合 source map 还能直接定位到源码行。
