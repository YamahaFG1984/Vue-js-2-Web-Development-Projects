第 2 章 · 项目一

Markdown 笔记本

第一个完整应用：一个能实时预览 Markdown、支持多条笔记、刷新后自动恢复的笔记本。 做完它，你就掌握了 Vue 日常开发里八成的基本功。

本章目标

  • 用 computed 派生数据，理解它的缓存机制
  • 用 watch 在数据变化时执行副作用（保存到 localStorage）
  • 认识组件的生命周期钩子
  • 掌握 v-on、v-bind、v-for、v-if、v-html 和动态 class
  • 知道为什么 Vue 3 删除了过滤器，以及用什么替代

我们要做什么

先列出需求：

  • 用户可以用 Markdown 语法写笔记
  • Markdown 实时渲染预览
  • 可以创建任意多条笔记，可以重命名、删除、收藏
  • 下次打开页面时，笔记和上次选中的那条都还在

界面分成三栏：

我们分两步走：先做一个单条笔记的编辑器 + 预览，再把它扩展成多条笔记的笔记本。

预览面板

要把 Markdown 转成 HTML，我们借助一个库：marked。在 Vue 的 <script> 之后引入它： 

<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<!-- Markdown 解析器 -->
<script src="https://cdn.jsdelivr.net/npm/marked@15/lib/marked.umd.js"></script>
<!-- HTML 消毒器，后面会解释为什么需要它 -->
<script src="https://cdn.jsdelivr.net/npm/dompurify@3/dist/purify.min.js"></script>

在控制台里试一下：

marked.parse('**粗体** *斜体* [链接](https://vuejs.org/)')
// '<p><strong>粗体</strong> <em>斜体</em> <a href="https://vuejs.org/">链接</a></p>\n'
ⓘ 和原书的差别

原书直接调用 marked(text)。新版 marked 推荐写成 marked.parse(text)，并且地址要锁定大版本号。

计算属性 computed

预览内容是由 content 推导出来的：content 变了，预览就该跟着变。 这种“由别的数据算出来的数据”，正是计算属性的用武之地。它有四个特点：

  • 有缓存：依赖没变，就直接返回上次的结果，不会重复计算。
  • 自动更新：函数里用到的任何响应式数据变了，它会被标记为“需要重算”。
  • 用法和普通数据一样：可以在模板里用，也可以在别的计算属性里用。
  • 惰性：没人读它，它就不算。
const { createApp, ref, computed } = Vue

createApp({
  setup() {
    const content = ref('这是一条笔记。')

    // 计算属性：传一个“取值函数”，返回一个只读的 ref
    const notePreview = computed(() => marked.parse(content.value))

    return { content, notePreview }
  }
}).mount('#notebook')
原书 · 选项式 API
computed: {
  notePreview () {
    return marked(this.content)
  }
}
Vue 3 · 组合式 API
const notePreview = computed(
  () => marked.parse(content.value)
)
✓ 计算属性 vs. 函数

你也可以写一个普通函数 function preview() { return marked.parse(content.value) }，在模板里用 {{ preview() }}。 结果一样，但函数每次重新渲染都会执行，计算属性则有缓存。Markdown 解析不便宜，这里用计算属性更合适。

文本插值会转义 HTML

先试着用插值显示预览：

<aside class="preview">
  {{ notePreview }}
</aside>

在编辑器里输入 我是 **粗体**！，预览区显示的却是：

<p>我是 <strong>粗体</strong>！</p>

HTML 标签被原样显示成了文字。这是 Vue 故意的：文本插值总是会转义 HTML，以防止 XSS（跨站脚本）攻击。

用 v-html 显示 HTML

既然插值不能渲染 HTML，我们需要另一个指令：v-html。它会把绑定的字符串当作 HTML 插入元素内部： 

<!-- 预览面板 -->
<aside class="preview" v-html="notePreview"></aside>

现在预览正常了。v-html 会替换掉元素原有的所有子内容。

⚠ v-html + 用户内容 = 危险

原书提醒过“不要对用户创建的内容使用 v-html”，但笔记本恰恰就是在显示用户写的内容。 Markdown 允许内嵌原始 HTML，marked 也不会替你过滤危险标签。 如果将来笔记可以分享给别人看，这就是一个真实的 XSS 漏洞。

现代做法是：先用 DOMPurify 消毒，再交给 v-html。 

const notePreview = computed(() =>
  // 先把 Markdown 转成 HTML，再去掉 <script>、onerror= 之类的危险内容
  DOMPurify.sanitize(marked.parse(content.value))
)
ⓘ v-text

v-text="x" 和 {{ x }} 效果一样（会转义），区别是它会替换元素的全部内容。日常用插值即可。

保存笔记：侦听器 watch

现在一刷新页面，笔记就没了。我们用浏览器自带的 localStorage 把它存下来。 需求是“content 一变就保存” —— 这种数据变化时执行某个动作（副作用）的场景，用侦听器。 

const { createApp, ref, computed, watch } = Vue

// 在 setup() 里：
watch(content, (val, oldVal) => {
  console.log('新笔记：', val, '旧笔记：', oldVal)
})

在编辑器里打字，控制台会打印：

新笔记： 这是一条**笔记**！ 旧笔记： 这是一条**笔记**

侦听器的选项

watch 的第三个参数是选项对象，最常用的有：

选项作用默认
immediate创建侦听器时立刻执行一次回调，而不是等第一次变化false
deep深度侦听：对象/数组内部任何属性变化都触发false（侦听 reactive 对象时默认为 true）
once 3.4+只触发一次，之后自动停止false
flush回调的执行时机：'pre'（DOM 更新前）、'post'（更新后）、'sync''pre'

试试 immediate：

watch(content, (val, oldVal) => {
  console.log('新笔记：', val, '旧笔记：', oldVal)
}, { immediate: true })
// 刷新页面立即打印：新笔记： 这是一条笔记。 旧笔记： undefined

旧值是 undefined，因为回调是在侦听器刚创建时调用的。这里我们其实不需要它，去掉即可。现在真正保存：

watch(content, (val) => {
  localStorage.setItem('content', val)
})

打开开发者工具的 Application（Chrome）或 存储（Firefox）面板， 在 Local Storage 下能看到一个 content 条目。

原书 · 选项式 API
watch: {
  content: {
    handler (val, oldVal) {
      localStorage.setItem('content', val)
    },
    immediate: false,
  }
}
Vue 3 · 组合式 API
watch(content, (val, oldVal) => {
  localStorage.setItem('content', val)
}, {
  immediate: false,
})

把逻辑提取成函数

“不要重复自己（DRY）”是写代码的好原则。原书在这里引入了 methods 选项； 在组合式 API 里，方法就是 setup() 里的普通函数，返回出去模板就能调用： 

function saveNote() {
  console.log('正在保存：', content.value)
  localStorage.setItem('content', content.value)
  reportOperation('保存')
}

function reportOperation(opName) {
  console.log(opName, '操作完成！')
}

// 侦听器的回调可以直接传函数
watch(content, saveNote)
★ setup() 里没有 this

原书反复用 this.content、this.reportOperation() 访问实例。组合式 API 里不需要也不应该用 this： 所有数据和函数都是 setup() 里的局部变量，函数之间通过 JavaScript 的闭包直接互相访问。 这让代码更像“普通的 JS”，也更容易被拆分和复用。

加载已保存的笔记

保存做好了，接下来是打开页面时恢复。用 localStorage.getItem()：

console.log('恢复的笔记：', localStorage.getItem('content'))

生命周期钩子

每个 Vue 组件实例都会经历一个确定的过程：被创建、挂载到页面、随数据更新、最后被卸载。 在这些关键时刻，Vue 会调用你注册的生命周期钩子函数，让你插入自己的逻辑。

Vue 2（原书）Vue 3 选项式Vue 3 组合式典型用途
beforeCreate / created同名直接写在 setup() 里初始化数据、发起请求
beforeMount / mounted同名onBeforeMount / onMounted需要访问真实 DOM 时（如初始化图表、地图）
beforeUpdate / updated同名onBeforeUpdate / onUpdated很少用
beforeDestroy / destroyedbeforeUnmount / unmountedonBeforeUnmount / onUnmounted清理定时器、事件监听

原书用 created 钩子恢复笔记。在组合式 API 里，setup() 就是“创建时”，所以直接写：

setup() {
  const content = ref('这是一条笔记。')

  // 相当于原书的 created 钩子：setup 运行时实例正在被创建
  content.value = localStorage.getItem('content') || '你可以用 **Markdown** 写作'

  watch(content, saveNote)
  // ...
}
ⓘ 什么是 falsy

a || b 在 a 为 falsy 时取 b。JavaScript 里 falsy 的值有：false、0、空字符串、null、undefined、NaN。 localStorage.getItem() 在键不存在时返回 null，所以第一次打开时会用默认文字。

更简单：直接用存储的值初始化

与其“先给默认值再覆盖”，不如创建 ref 时就用恢复的值：

const content = ref(localStorage.getItem('content') || '你可以用 **Markdown** 写作')

这样侦听器不会在启动时被触发一次（因为值是“初始化”的，而不是“修改”的），更干净。

多条笔记

只有一条笔记的笔记本没什么用。现在我们加入左侧的笔记列表，以及重命名、收藏等功能。先在模板里加上侧边栏：

<div id="notebook">
  <!-- 侧边栏 -->
  <aside class="side-bar">
    <!-- 笔记列表放这里 -->
  </aside>

  <!-- 主区域 -->
  <section class="main">
  ...

笔记的数据结构

每条笔记是一个对象，所有笔记放在 notes 数组里：

  • id：唯一标识
  • title：列表里显示的名字
  • content：Markdown 正文
  • created：创建时间（毫秒时间戳）
  • favorite：是否收藏，收藏的排在列表最前
const notes = ref([])

// 新建一条带默认内容的笔记
function addNote() {
  const time = Date.now()
  const note = {
    id: String(time),
    title: '新笔记 ' + (notes.value.length + 1),
    content: '**你好！** 这个笔记本支持 [Markdown](https://commonmark.org/help/) 格式！',
    created: time,
    favorite: false,
  }
  notes.value.push(note)
}
✓ 更稳妥的唯一 id

Date.now() 在同一毫秒内连点两次会重复。现代浏览器提供了 crypto.randomUUID()， 生成形如 '3b241101-e2bb-4255-8caf-4136c566a962' 的随机 id，几乎不可能冲突。

v-on：监听点击事件

需要一个按钮来调用 addNote。监听 DOM 事件用 v-on 指令，冒号后面是事件名（指令的参数）： 

<aside class="side-bar">
  <div class="toolbar">
    <button v-on:click="addNote"><i class="material-icons">add</i> 新建笔记</button>
  </div>
</aside>

v-on: 太常用了，所以有简写 @：

<button @click="addNote"><i class="material-icons">add</i> 新建笔记</button>

v-bind：绑定属性

想让鼠标悬停在按钮上时，显示“已有 3 条笔记”。提示文字由 HTML 的 title 属性控制， 但静态写死的值不会变。要把属性和 JS 表达式绑定，用 v-bind： 

<button @click="addNote" v-bind:title="notes.length + ' 条笔记'">
<!-- 简写：冒号 -->
<button @click="addNote" :title="notes.length + ' 条笔记'">

表达式会在依赖变化时自动重新计算。如果表达式变长了，可以把它移到计算属性里：

const addButtonTitle = computed(() => `已有 ${notes.value.length} 条笔记`)
⚠ 原书的一个小 bug

原书这里写成了 return notes.length + ...，漏了 this.。在组合式 API 里对应的坑是漏了 .value —— 写成 notes.length 会得到 undefined。

✓ Vue 3.4+：同名简写

当属性名和变量名相同时，:title="title" 可以简写为 :title。

v-for：渲染列表

现在在工具栏下方显示笔记列表。v-for 用 item of items（或 item in items）的语法遍历数组， 它所在的元素会被重复渲染： 

<div class="notes">
  <div class="note" v-for="note of notes" :key="note.id">{{ note.title }}</div>
</div>
★ 一定要加 :key

原书这里没有写 key，但现在的 Vue 官方风格指南和 ESLint 插件都要求 v-for 搭配 :key。 key 是每一项的“身份证”，让 Vue 在列表变化时能准确知道哪一项被移动、新增或删除，而不是笨拙地就地复用 DOM。 用数据里稳定且唯一的值（比如 id），不要用数组下标。第 3 章做动画时你会亲眼看到它的作用。

选择笔记

被选中的笔记成为中间和右侧面板的内容。先加一个 selectedId 记录选中的 id，再写一个选择函数：

const selectedId = ref(null)

function selectNote(note) {
  selectedId.value = note.id
}

<div class="note" v-for="note of notes" :key="note.id"
     @click="selectNote(note)">{{ note.title }}</div>
ⓘ 为什么存 id，而不是直接存笔记对象

存对象也能工作，但保存到 localStorage 时会很麻烦（JSON 化后对象身份就丢了）。存 id 简单、可序列化，选中的对象交给计算属性去查。

当前笔记：计算属性

const selectedNote = computed(() =>
  notes.value.find(note => note.id === selectedId.value)
)

然后把之前所有用 content 的地方换成 selectedNote.content：

<textarea v-model="selectedNote.content"></textarea>

const notePreview = computed(() =>
  selectedNote.value
    ? DOMPurify.sanitize(marked.parse(selectedNote.value.content))
    : ''
)

旧的 content、它的侦听器和 saveNote 函数现在都用不上了，可以删掉。

动态 CSS class

选中的笔记应该有不同的背景色。:class 有特殊的“魔法”：除了字符串，它还接受数组和对象。

写法渲染结果
:class="['one', 'two']"class="one two"
:class="{ one: true, two: false, three: true }"class="one three"
class="note" :class="{ selected: isSel }"静态和动态会合并：class="note selected"

对象写法最常用：键是 class 名，值是“要不要加上它”。我们的列表变成：

<div class="note" v-for="note of notes" :key="note.id"
     :class="{ selected: note === selectedNote }"
     @click="selectNote(note)">{{ note.title }}</div>
✓ 静态 class 写在静态属性里

不会变的 class（比如 note）放在普通的 class 属性里，Vue 编译时会把它们当作常量优化。

v-if：条件渲染

如果没有选中任何笔记，selectedNote 是 undefined，访问 selectedNote.content 会直接报错。 所以没选中时，中间和右边的面板都不应该出现。v-if 可以根据条件把一段模板完全从 DOM 中移除： 

<div v-if="loading">加载中……</div>
<div v-else-if="processing">处理中……</div>
<div v-else>内容</div>

两个面板都要加同样的条件，重复了。可以用一个特殊的 <template> 标签把它们包起来，它就像 JS 里的花括号，本身不会出现在 DOM 里：

<template v-if="selectedNote">
  <!-- 主区域 -->
  <section class="main">
    <textarea v-model="selectedNote.content"></textarea>
  </section>

  <!-- 预览 -->
  <aside class="preview" v-html="notePreview"></aside>
</template>
⚠ Vue 3 变化：v-if 和 v-for 的优先级

在 Vue 2 里，同一个元素上同时写 v-for 和 v-if 时，v-for 先执行； Vue 3 反过来了，v-if 优先，此时 v-if 里还拿不到循环变量。 官方建议永远不要把它们写在同一个元素上：要过滤列表就用计算属性，要整体隐藏就在外面包一层 <template v-if>。

用深度侦听保存所有笔记

现在要把整个笔记列表持久化。localStorage 只能存字符串，所以要先 JSON.stringify：

const notes = ref(JSON.parse(localStorage.getItem('notes')) || [])

function saveNotes() {
  localStorage.setItem('notes', JSON.stringify(notes.value))
  console.log('笔记已保存！', new Date())
}

watch(notes, saveNotes)

试一下：新建笔记……控制台什么都没打印。修改笔记内容，也没打印。这是为什么？

直接侦听一个 ref，Vue 只关心 notes.value 有没有被整个替换。 往数组里 push、修改某条笔记的 content，都发生在更深的层级。解决办法是加上 deep 选项： 

watch(notes, saveNotes, { deep: true })

现在不论是新增、删除还是在编辑器里打字（v-model 修改的是选中笔记的 content），列表都会被保存。

ⓘ 和原书的差异

原书说“push、splice、sort 默认就能被侦听到，只有改嵌套属性才需要 deep”。那是 Vue 2 侦听 data 属性时的行为。 在 Vue 3 里侦听一个 ref，连 push 都需要 deep: true（或者直接侦听一个 reactive() 对象，那样默认就是深度的）。

🔍 另一种写法：watchEffect（点击展开）

watchEffect 会自动追踪回调里读到的所有响应式数据。JSON.stringify 会读遍每一个属性，所以下面这一行天然就是“深度”的：

watchEffect(() => {
  localStorage.setItem('notes', JSON.stringify(notes.value))
})

它还会在创建时立即执行一次（相当于 immediate: true）。社区工具库 VueUse 更是直接提供了 useLocalStorage('notes', [])，一行就能得到一个自动持久化的 ref。

保存选中状态

如果刷新后还能选中上次那条笔记就更好了。同样用侦听器：

const selectedId = ref(localStorage.getItem('selected-id'))

watch(selectedId, (val) => {
  if (val) localStorage.setItem('selected-id', val)
  else localStorage.removeItem('selected-id')
})
⚠ 小心 localStorage 把 null 变成 "null"

原书直接 setItem('selected-id', val)。当 val 是 null 时，存进去的是字符串 "null"， 下次读出来是一个“真值”，就会去找 id 为 "null" 的笔记。上面的写法在没有选中时把键删掉，避免这个坑。

删除

function removeNote() {
  if (selectedNote.value && confirm('确定删除这条笔记吗？')) {
    const index = notes.value.indexOf(selectedNote.value)
    if (index !== -1) {
      notes.value.splice(index, 1)
    }
  }
}

删除后会同时发生三件事：左侧列表少了一项；中间和右边的面板消失（因为 selectedNote 查不到了）；列表被保存。这就是“数据驱动”的威力 —— 我们只改了一个数组。

收藏

收藏按钮根据状态显示实心或空心的星星：

<button @click="favoriteNote" title="收藏">
  <i class="material-icons">{{ selectedNote.favorite ? 'star' : 'star_border' }}</i>
</button>

function favoriteNote() {
  selectedNote.value.favorite = !selectedNote.value.favorite
}
ⓘ 关于原书的 ^= true

原书最后把它“优化”成了 favorite ^= true（异或）。这会把布尔值变成数字 1/0， 读代码的人也要多想一下。用 ! 取反更清晰，类型也保持为布尔值。

接下来让列表排序：先按创建时间排，再把收藏的放前面。用计算属性 sortedNotes： 

const sortedNotes = computed(() =>
  notes.value
    .toSorted((a, b) => a.created - b.created)          // 按创建时间升序
    .sort((a, b) => (a.favorite === b.favorite) ? 0     // 都收藏或都没收藏：不动
                    : a.favorite ? -1                    // a 收藏了：a 排前面
                    : 1)                                 // 否则 b 排前面
)
⚠ 不要在计算属性里修改原数组

sort() 会原地修改数组。如果直接 notes.value.sort(...)，计算属性就会修改它依赖的数据， 还会触发深度侦听器白白保存一次。原书用 slice() 先复制一份；现代 JS（ES2023）提供了 toSorted()，返回排好序的新数组、不碰原数组。之后的 .sort() 作用在这个新数组上，就无所谓了。

然后把列表的 v-for 换成 sortedNotes，并给收藏的笔记加一个星标：

<div class="notes">
  <div class="note" v-for="note of sortedNotes" :key="note.id"
       :class="{ selected: note === selectedNote }"
       @click="selectNote(note)">
    <i class="icon material-icons" v-if="note.favorite">star</i>
    {{ note.title }}
  </div>
</div>

创建时间：过滤器没了，用函数

直接显示 {{ selectedNote.created }} 会得到一串毫秒数，比如 1730800000000，对用户毫无意义。原书的做法是：

  1. 引入 moment.js 日期库；
  2. 用 Vue.filter('date', ...) 注册一个全局过滤器；
  3. 在模板里用管道符 {{ selectedNote.created | date }}。

这三步在今天都过时了：

❌

过滤器被移除

Vue 3 删除了过滤器语法。管道符 | 在 JS 里本来是“按位或”，放在模板里容易混淆，而且它做的事普通函数完全能做。

💤

moment.js 已停止开发

moment 官方已进入维护模式并建议新项目不要使用。它体积大、对象可变。

✅

浏览器自带 Intl

Intl.DateTimeFormat 零依赖、自动适配语言地区，格式化日期足够了。

原书 · Vue 2 过滤器 + moment
Vue.filter('date', time =>
  moment(time).format('DD/MM/YY, HH:mm'))

// 模板：
// {{ selectedNote.created | date }}
Vue 3 · 普通函数 + Intl
const dateFormatter = new Intl.DateTimeFormat('zh-CN', {
  dateStyle: 'short', timeStyle: 'short',
})
const formatDate = (time) => dateFormatter.format(time)

// 模板：
// {{ formatDate(selectedNote.created) }}

<span class="date">
  <span class="label">创建于</span>
  <span class="value">{{ formatDate(selectedNote.created) }}</span>
</span>

显示效果类似 2026/11/5 14:30。

✓ 多处要用？注册成全局属性

如果很多组件都要格式化日期，可以挂到应用上：app.config.globalProperties.$date = formatDate， 之后任何模板里都能写 {{ $date(x) }}。这是官方推荐的“全局过滤器”替代方案。

文字统计

三个计算属性，分别统计行数、词数和字符数：

const linesCount = computed(() => {
  if (!selectedNote.value) return 0
  // 按换行符切分
  return selectedNote.value.content.split(/\r\n|\r|\n/).length
})

// Intl.Segmenter 能正确地给中文、日文这类没有空格的语言分词
const segmenter = new Intl.Segmenter('zh', { granularity: 'word' })

const wordsCount = computed(() => {
  if (!selectedNote.value) return 0
  let n = 0
  for (const s of segmenter.segment(selectedNote.value.content)) {
    if (s.isWordLike) n++
  }
  return n
})

const charactersCount = computed(() => {
  if (!selectedNote.value) return 0
  // 展开成数组能正确处理 emoji 等由两个 UTF-16 单元组成的字符
  return [...selectedNote.value.content].length
})
🔍 为什么不用原书的空格计数法

原书用正则把多个空白合并，再按空格 split 来数单词。这对英文有效，但中文句子里没有空格， “我爱学习 Vue”会被数成 2 个词。Intl.Segmenter 是浏览器内置的分词器，会把它切成“我 / 爱 / 学习 / Vue”共 4 个词。 另外 '😀'.length 是 2，[...'😀'].length 才是 1。 

<span class="lines"><span class="label">行</span><span class="value">{{ linesCount }}</span></span>
<span class="words"><span class="label">词</span><span class="value">{{ wordsCount }}</span></span>
<span class="characters"><span class="label">字符</span><span class="value">{{ charactersCount }}</span></span>

const { createApp, ref, computed, watch } = Vue

const dateFormatter = new Intl.DateTimeFormat('zh-CN', { dateStyle: 'short', timeStyle: 'short' })
const segmenter = new Intl.Segmenter('zh', { granularity: 'word' })

createApp({
  name: 'Notebook',
  setup() {
    // ---------- 状态 ----------
    const notes = ref(JSON.parse(localStorage.getItem('notes')) || [])
    const selectedId = ref(localStorage.getItem('selected-id'))

    // ---------- 计算属性 ----------
    const selectedNote = computed(() =>
      notes.value.find(note => note.id === selectedId.value))

    const notePreview = computed(() => selectedNote.value
      ? DOMPurify.sanitize(marked.parse(selectedNote.value.content))
      : '')

    const sortedNotes = computed(() => notes.value
      .toSorted((a, b) => a.created - b.created)
      .sort((a, b) => (a.favorite === b.favorite) ? 0 : a.favorite ? -1 : 1))

    const addButtonTitle = computed(() => `已有 ${notes.value.length} 条笔记`)

    const content = computed(() => selectedNote.value?.content ?? '')
    const linesCount = computed(() => content.value.split(/\r\n|\r|\n/).length)
    const wordsCount = computed(() =>
      [...segmenter.segment(content.value)].filter(s => s.isWordLike).length)
    const charactersCount = computed(() => [...content.value].length)

    // ---------- 侦听器：持久化 ----------
    watch(notes, () => {
      localStorage.setItem('notes', JSON.stringify(notes.value))
    }, { deep: true })

    watch(selectedId, (val) => {
      if (val) localStorage.setItem('selected-id', val)
      else localStorage.removeItem('selected-id')
    })

    // ---------- 方法 ----------
    function addNote() {
      const time = Date.now()
      const note = {
        id: crypto.randomUUID(),
        title: '新笔记 ' + (notes.value.length + 1),
        content: '**你好！** 这个笔记本支持 [Markdown](https://commonmark.org/help/) 格式！',
        created: time,
        favorite: false,
      }
      notes.value.push(note)
      selectNote(note)
    }

    function selectNote(note) {
      selectedId.value = note.id
    }

    function removeNote() {
      if (selectedNote.value && confirm('确定删除这条笔记吗？')) {
        const index = notes.value.indexOf(selectedNote.value)
        if (index !== -1) notes.value.splice(index, 1)
      }
    }

    function favoriteNote() {
      selectedNote.value.favorite = !selectedNote.value.favorite
    }

    const formatDate = (time) => dateFormatter.format(time)

    return {
      notes, selectedNote, notePreview, sortedNotes, addButtonTitle,
      linesCount, wordsCount, charactersCount,
      addNote, selectNote, removeNote, favoriteNote, formatDate,
    }
  },
}).mount('#notebook')
ⓘ 返回值好长？

setup() 最后那个长长的 return 确实有点烦。第 4 章引入构建工具后，我们会用 <script setup>， 顶层声明的变量和函数自动暴露给模板，再也不用手写 return。

小结

概念Vue 3 写法一句话
响应式数据ref()JS 里用 .value，模板里直接用
计算属性computed(() => ...)派生值，有缓存
侦听器watch(src, cb, { deep, immediate })数据变了去做事
方法普通函数没有 this，靠闭包
生命周期onMounted 等setup 本身就是 created
格式化函数 / globalProperties过滤器已移除
事件@clickv-on:click 的简写
属性绑定:title、:classv-bind 的简写，class 支持对象/数组
列表v-for + :keykey 用稳定唯一的 id
条件v-if / v-else / v-show移除 vs. 隐藏
原始 HTMLv-html用户内容务必先消毒
