第 10 章 · 进阶专题

组件库与设计系统

书里的项目大多手写样式，这对学习很好。真实项目里，团队通常会选一个组件库来加速开发，或者在它的基础上搭一套自己的设计系统。 本章讨论怎么选组件库、怎么定制主题、怎么写出可复用而且人人都能用（无障碍）的基础组件，以及怎么用 Storybook 给组件写文档。

本章目标

  • 理解设计系统的层次：设计令牌 → 基础组件 → 业务组件 → 页面
  • 了解 Element Plus、Naive UI、Vuetify、PrimeVue 和 shadcn-vue / Reka UI 的定位，学会选型
  • 用 unplugin-vue-components 按需引入组件
  • 用 CSS 变量做主题和暗色模式，并定制各家组件库的主题
  • 写一个带变体、透传属性和插槽类型的基础按钮组件
  • 掌握无障碍（a11y）的核心：语义化标签、键盘操作、焦点管理和 ARIA
  • 用 Storybook 开发和展示组件

设计系统的四层结构

“设计系统”听起来很大，其实就是一套大家共同遵守的规则 + 实现这些规则的组件。从下往上可以分成四层，下层越稳定，上层越容易保持一致：

组件库帮你解决的是第二层（再附带一套默认的第一层）。选组件库，本质上是在选“基础组件和设计令牌，我要自己掌控多少”。

组件库选型

Vue 3 生态里的组件库大致落在一条光谱上：一头是“开箱即用、样式全包”，另一头是“只给行为、样式全归你”。

库风格与特点适合
Element Plus国内最流行的后台风格组件库，表单、表格、日期组件齐全，中文文档完善管理后台、内部系统
Naive UITypeScript 编写，主题定制基于 JS 对象，性能和类型体验好想要现代外观、重视类型的项目
VuetifyMaterial Design 实现，组件最全，自带栅格和主题系统喜欢 Material 风格、需要大量现成组件
PrimeVue组件数量多，可切换“有样式 / 无样式”两种模式，主题预设丰富需要灵活度的企业应用
shadcn-vue不是依赖包，而是用 CLI 把组件源码复制进项目；基于 Reka UI + Tailwind品牌感强、要求完全掌控外观的产品
Reka UI（原 Radix Vue）无样式组件：只负责交互逻辑、键盘操作和 ARIA从零搭自己的设计系统
★ 选型时问自己三个问题

① 设计稿是贴近某个现成风格，还是有强烈的品牌设计？前者选样式全包的库，后者选 shadcn-vue 或 headless。
② 最复杂的组件是什么？大数据表格、树形选择、日期区间这类组件自己写成本很高，确认候选库里有，并且好用。
③ 团队会维护多久？看 GitHub 活跃度、Vue 新版本的跟进速度、TypeScript 类型和无障碍支持。

按需引入

组件库通常有几十上百个组件，全量引入会让包体积变大。推荐用 unplugin-vue-components：你在模板里直接写 <el-button>， 它在编译时自动加上对应的 import（连样式一起），没用到的组件不会打包进来。以 Element Plus 为例： 

npm i element-plus
npm i -D unplugin-vue-components unplugin-auto-import

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import Components from 'unplugin-vue-components/vite'
import AutoImport from 'unplugin-auto-import/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    vue(),
    // 模板里的 <el-xxx> 组件自动导入
    Components({ resolvers: [ElementPlusResolver()] }),
    // ElMessage、ElMessageBox 这类在 JS 里调用的 API 自动导入
    AutoImport({ resolvers: [ElementPlusResolver()] }),
  ],
})

Naive UI、Vuetify、PrimeVue、Ant Design Vue 都有对应的 resolver 或官方插件，用法相同。

ⓘ 和第 4 章的自动导入是同一件事

第 4 章讨论过自动导入的利弊。组件库的按需引入是它最没有争议的用法：组件名带统一前缀（el-、n-），一眼就能看出来源。

主题与设计令牌

设计令牌的三层

不要在组件里直接写 #3b82f6。把颜色、间距等值定义成令牌（token），再分层引用。 这样换品牌色、做暗色模式时，只需要改一处： 

:root {
  /* 原始令牌 */
  --blue-500: #3b82f6;
  --blue-400: #60a5fa;
  --gray-50: #f9fafb;
  --gray-900: #111827;

  /* 语义令牌 */
  --color-primary: var(--blue-500);
  --color-bg: var(--gray-50);
  --color-text: var(--gray-900);
  --radius: 8px;
}

/* 暗色模式：只改语义层 */
:root.dark {
  --color-primary: var(--blue-400);
  --color-bg: var(--gray-900);
  --color-text: var(--gray-50);
}

本教程网站的配色也是这么做的：所有颜色都是 CSS 变量，用 light-dark() 函数同时给出亮色和暗色的值，你可以在浏览器开发者工具里看到。 切换暗色模式的逻辑可以直接用 VueUse 的 useDark()，它会在 <html> 上切换 dark 类并记住用户的选择。

定制各家组件库

主流组件库都把自己的设计令牌暴露成了 CSS 变量或 JS 对象，覆盖它们就能换成你的品牌色：

/* main.js 里：import 'element-plus/theme-chalk/dark/css-vars.css' 后，给 html 加 dark 类即可切换暗色 */
:root {
  --el-color-primary: #7c3aed;
  --el-border-radius-base: 8px;
}

<script setup>
import { NConfigProvider, darkTheme } from 'naive-ui'
import { useDark } from '@vueuse/core'

const isDark = useDark()
const overrides = { common: { primaryColor: '#7c3aed', borderRadius: '8px' } }
</script>

<template>
  <n-config-provider :theme="isDark ? darkTheme : null" :theme-overrides="overrides">
    <RouterView />
  </n-config-provider>
</template>

@import "tailwindcss";

@theme {
  --color-brand: #7c3aed;     /* 自动生成 bg-brand、text-brand 等工具类 */
  --radius-card: 12px;
}

写一个基础组件

不管用不用组件库，你迟早要写自己的基础组件。下面这个按钮展示了一个好的基础组件应该具备的几个特征：

<script setup lang="ts">
type Variant = 'solid' | 'soft' | 'ghost'

const props = withDefaults(defineProps<{
  variant?: Variant
  size?: 'sm' | 'md'
  loading?: boolean
  disabled?: boolean
}>(), { variant: 'solid', size: 'md', loading: false, disabled: false })

// 声明插槽的类型：默认插槽 + 可选的图标插槽
defineSlots<{
  default(): any
  icon?(): any
}>()
</script>

<template>
  <!-- 没声明为 prop 的属性（type、@click、aria-*）会自动透传到根元素 button 上 -->
  <button
    class="btn"
    :class="[`btn-${props.variant}`, `btn-${props.size}`]"
    :disabled="props.disabled || props.loading"
    :aria-busy="loading || undefined"
  >
    <span v-if="loading" class="spinner" aria-hidden="true" />
    <slot v-else name="icon" />
    <slot />
  </button>
</template>

<style scoped>
.btn {
  border-radius: var(--btn-radius, var(--radius));
  border: 1px solid var(--btn-color, var(--color-primary));
  padding: 6px 14px;
}
.btn-solid { background: var(--btn-color, var(--color-primary)); color: #fff; }
.btn-soft  { background: color-mix(in oklch, var(--btn-color, var(--color-primary)) 12%, transparent); }
.btn-ghost { background: transparent; }
.btn:focus-visible { outline: 3px solid var(--color-primary); outline-offset: 2px; }
</style>
🎨

变体而不是样式参数

用 variant="soft" 这样有限的选项，而不是让调用方传颜色、边框，保证全站一致。

🔗

属性透传

原生 button 的属性和事件不用一一声明，调用方写的 type、@click 自动落到根元素上。

🎯

样式钩子

组件内部只引用令牌，并留出 --btn-color 这样的组件级变量，特殊场景可以局部覆盖。

⌨

键盘友好

用真正的 <button>，保留 :focus-visible 焦点样式。下一节详细说。

✓ 根元素不是你想透传的元素时

比如 BaseInput 的根元素是包住 label 和 input 的 div，你希望 placeholder 落到 input 上。 这时用 defineOptions({ inheritAttrs: false }) 关闭自动透传，再在 input 上写 v-bind="$attrs"。

无障碍：让每个人都能用

无障碍（accessibility，常缩写为 a11y）是指让使用屏幕阅读器、只用键盘、视力不佳的用户也能使用你的应用。 这不只是“照顾少数人”：手腕受伤的人、在阳光下看手机的人、喜欢键盘快捷操作的高级用户，都会受益。很多国家和地区对公共服务网站有无障碍的法律要求。

第一原则：优先用原生的语义化标签

✗ 看起来像按钮
<div class="btn" @click="save">保存</div>
<!-- 不能用 Tab 聚焦，不能按回车触发，
     屏幕阅读器不知道它是按钮 -->
✓ 本来就是按钮
<button type="button" class="btn" @click="save">
  保存
</button>
<!-- 焦点、键盘、读屏全部免费获得 -->

同理：跳转用 <a> / RouterLink，输入框配 <label>，标题按层级用 h1~h6，列表用 ul/li。只有原生标签做不到时，才需要 ARIA。

复杂组件：把第 5 章的下拉菜单做完整

第 5 章的用户菜单只处理了“点外面关闭”。按照 WAI-ARIA 菜单按钮模式，一个完整的下拉菜单需要这样的键盘行为和 ARIA 属性：

把这套逻辑写成一个组合式函数，任何下拉菜单都能复用：

import { ref, nextTick, useId } from 'vue'

export function useMenu() {
  const open = ref(false)
  const buttonEl = ref(null)
  const itemEls = ref([])           // 在模板里用 :ref 函数收集
  const menuId = useId()            // 3.5+：SSR 安全的唯一 id

  const focusItem = (i) => {
    const items = itemEls.value
    items[(i + items.length) % items.length]?.focus()   // 首尾循环
  }

  async function show(index = 0) {
    open.value = true
    await nextTick()                // 等菜单渲染出来再移焦点
    focusItem(index)
  }
  function hide(returnFocus = true) {
    open.value = false
    if (returnFocus) buttonEl.value?.focus()
  }

  function onButtonKeydown(e) {
    if (['Enter', ' ', 'ArrowDown'].includes(e.key)) { e.preventDefault(); show(0) }
    if (e.key === 'ArrowUp') { e.preventDefault(); show(-1) }
  }
  function onMenuKeydown(e) {
    const current = itemEls.value.indexOf(document.activeElement)
    const actions = {
      ArrowDown: () => focusItem(current + 1),
      ArrowUp: () => focusItem(current - 1),
      Home: () => focusItem(0),
      End: () => focusItem(-1),
      Escape: () => hide(),
      Tab: () => hide(false),       // 不阻止默认行为，让焦点自然移走
    }
    if (actions[e.key]) {
      if (e.key !== 'Tab') e.preventDefault()
      actions[e.key]()
    }
  }

  return { open, buttonEl, itemEls, menuId, show, hide, onButtonKeydown, onMenuKeydown }
}

<script setup>
import { useMenu } from '@/composables/useMenu'
import { vClickOutside } from '@/directives/clickOutside'

const items = [{ label: '个人资料', to: '/profile' }, { label: '设置', to: '/settings' }, { label: '退出登录', action: 'logout' }]
const { open, buttonEl, itemEls, menuId, show, hide, onButtonKeydown, onMenuKeydown } = useMenu()
</script>

<template>
  <div class="user-menu" v-click-outside="() => open && hide(false)">
    <button ref="buttonEl" type="button" aria-haspopup="menu"
      :aria-expanded="open" :aria-controls="menuId"
      @click="open ? hide() : show()" @keydown="onButtonKeydown">
      我的账户
    </button>
    <ul v-if="open" :id="menuId" role="menu" @keydown="onMenuKeydown">
      <li v-for="(item, i) in items" :key="item.label" role="menuitem" tabindex="-1"
        :ref="(el) => (itemEls[i] = el)" @click="select(item)" @keydown.enter="select(item)">
        {{ item.label }}
      </li>
    </ul>
  </div>
</template>

弹窗的焦点管理

第 3 章用 Teleport 做过浮层。一个合格的模态对话框还需要：

  1. 打开时把焦点移到对话框里（第一个可聚焦元素或标题），关闭时把焦点还给打开它的按钮；
  2. 焦点陷阱：按 Tab 时焦点只在对话框内循环，不会跑到背后的页面上；
  3. 按 Esc 关闭；背后的内容对读屏软件隐藏。

最省事的办法是直接用浏览器原生的 <dialog> 元素：showModal() 打开的对话框天然具备焦点陷阱、Esc 关闭和背景隔离：

<script setup>
import { useTemplateRef, watch } from 'vue'

const open = defineModel({ type: Boolean, default: false })
const dialog = useTemplateRef('dialog')

watch(open, (v) => (v ? dialog.value.showModal() : dialog.value.close()))
</script>

<template>
  <!-- close 事件在按 Esc 或调用 close() 时都会触发，保持 v-model 同步 -->
  <dialog ref="dialog" aria-labelledby="dlg-title" @close="open = false">
    <h2 id="dlg-title"><slot name="title" /></h2>
    <slot />
    <button type="button" @click="open = false">关闭</button>
  </dialog>
</template>

需要更复杂的交互（组合框、日期选择器、树形控件）时，不要从零实现键盘和 ARIA 逻辑，直接用 Reka UI 这类 headless 库，它们已经按 WAI-ARIA 规范做好了。

无障碍检查清单与工具

检查项怎么做
只用键盘能完成所有操作拔掉鼠标走一遍主要流程；焦点样式要清晰可见（不要随手 outline: none）
图片有替代文字有意义的图片写 alt，装饰性图片 alt=""
表单控件有标签<label for> 或 aria-label；错误信息用 aria-describedby 关联到输入框
颜色对比度足够正文至少 4.5:1；不要只靠颜色传达信息（错误除了变红还要有文字）
动态内容会被读出Toast、表单提交结果放进 aria-live="polite" 的区域
路由切换后焦点合理单页应用换页后，把焦点移到新页面的 h1，并更新 document.title

用 Storybook 开发组件

基础组件多了以后，需要一个地方集中展示“每个组件有哪些状态”：给设计师验收、给同事查用法、给自己单独调试。 Storybook 就是这样一个独立运行的组件工作台，它支持 Vue 3 + Vite： 

npm create storybook@latest    # 自动识别 Vue 3 + Vite 项目并完成配置
npm run storybook              # 在 6006 端口打开

每个组件写一个 .stories.js 文件，导出若干个“故事”，每个故事就是组件的一种状态：

import BaseButton from './BaseButton.vue'

export default {
  title: 'Base/Button',
  component: BaseButton,
  tags: ['autodocs'],                  // 根据 props 自动生成文档页
  argTypes: {
    variant: { control: 'select', options: ['solid', 'soft', 'ghost'] },
  },
  render: (args) => ({
    components: { BaseButton },
    setup: () => ({ args }),
    template: '<BaseButton v-bind="args">保存</BaseButton>',
  }),
}

export const Solid = { args: { variant: 'solid' } }
export const Soft = { args: { variant: 'soft' } }
export const Loading = { args: { loading: true } }
✓ 更轻量的选择

Storybook 功能强大但依赖较多。如果只想要一个简单的组件展示页，可以看看为 Vue 设计的 Histoire，或者干脆在项目里建一个仅开发环境可访问的 /playground 路由。

小结

主题要点
设计系统令牌 → 基础组件 → 业务组件 → 页面，下层越稳定越好
选型贴近现成风格选 Element Plus / Naive UI / Vuetify / PrimeVue；品牌感强选 shadcn-vue 或 Reka UI
按需引入unplugin-vue-components + 对应的 resolver
主题原始 / 语义 / 组件三层令牌；暗色模式只改语义层；覆盖组件库暴露的变量
基础组件有限的变体、属性透传、defineSlots 类型、只引用令牌
无障碍优先原生标签；复杂组件按 WAI-ARIA 模式实现键盘和焦点；用原生 <dialog>；工具 + 真实读屏测试
文档Storybook：每个状态一个故事，自动生成文档和无障碍检查

动手练习

  1. 用 Element Plus 或 Naive UI 重写第 5 章客服中心的登录表单和工单列表，比较代码量和外观。
  2. 给你的项目建立 tokens.css，把所有硬编码的颜色替换成语义令牌，再用 useDark() 实现暗色模式切换。
  3. 写一个 BaseInput：带 label、错误提示，用 inheritAttrs: false 把属性透传到 input 上，并用 aria-describedby 关联错误信息。
  4. 把本章的 useMenu 用到第 5 章的 UserMenu 上，只用键盘完成“打开菜单 → 选择退出登录”。
  5. 在第 7 章的 Playwright 测试里接入 @axe-core/playwright，修复它报告的问题。
