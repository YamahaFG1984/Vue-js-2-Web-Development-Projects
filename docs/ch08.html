Meteor 实时仪表盘

最后一个项目换一套完全不同的技术栈：全栈 JavaScript 框架 Meteor。我们做一个监控产品生产情况的实时仪表盘 —— 在一个窗口里录入数据，另一个窗口里的图表会立刻跟着变化，而我们几乎不用写任何网络通信代码。

本章目标

  • 了解 Meteor 的架构：Minimongo、DDP、MongoDB 和“全栈响应式”
  • 用 Meteor 3 创建 Vue 3 项目，理解 Meteor 的目录约定
  • 用集合（Collection）存数据，用方法（Method）修改数据并获得乐观更新
  • 用发布/订阅（Pub/Sub）把数据实时同步到 Vue 组件
  • 自己用 SVG 画一个半圆进度仪表组件
  • 数据涨到上万条时：用 v-memo、虚拟滚动和数据裁剪保持流畅补充
  • 不用 Meteor，用 Express + SSE 写一个完整可运行的实时版本补充

Meteor 是什么

Meteor 是一个用于构建 Web 应用的全栈 JavaScript 框架。它的组成部分：

  • Web 客户端：可以用任何前端库（React、Vue、Svelte……），内置一个客户端数据库 Minimongo；
  • 服务器：基于 Node.js，支持现代 JS 语法；
  • 实时数据库：服务器端使用 MongoDB；
  • 通信被抽象掉了：客户端和服务器之间通过 WebSocket 上的 DDP 协议自动同步数据；
  • 可选的混合移动应用（Android / iOS）构建、开箱即用的命令行工具和构建系统、既能用 Meteor 包也能用 npm 包。

JavaScript 无处不在，Meteor 还鼓励客户端和服务器共享代码。因为 Meteor 管理了整个技术栈，整个栈都是响应式和实时的： 一个客户端修改了数据，所有其他客户端都会收到新数据，界面自动更新。

ⓘ Meteor 的今天

Meteor 3（2024 年发布）完成了一次大升级：移除了基于 Fibers 的同步写法，全面改用 async/await，并支持最新的 Node.js LTS。 所以本章的代码会和原书有明显不同：insert 变成 insertAsync、Meteor.call 变成 Meteor.callAsync 等。 Meteor 也支持用现代打包工具（Vite / Rspack）构建前端，具体集成方式随版本演进，以 meteor create 生成的项目为准。

ⓘ 原书的 lib/ 目录约定

原书把集合放在 lib/ 目录，利用 Meteor 的“急切加载”规则：lib/ 下的文件会被自动、优先加载，client/ 只在客户端、server/ 只在服务器。 这个规则至今仍然存在，但官方推荐在 package.json 里设置 meteor.mainModule，把代码放进 imports/ 并显式 import —— 新模板默认就是这样。

集合与方法

集合（Collection）

Meteor 集合是一个响应式的对象列表，类似 MongoDB 的集合（底层就是 MongoDB）。在服务器上，它直接读写 MongoDB；在客户端，它读写 Minimongo 里的缓存副本。 

import { Meteor } from 'meteor/meteor'
import { Mongo } from 'meteor/mongo'

export const Measures = new Mongo.Collection('measures')

方法（Method）与乐观更新

Meteor 方法是一个特殊的函数：客户端调用它时，它会同时在客户端（操作 Minimongo）和服务器（操作 MongoDB）上执行。 客户端那一份是“模拟”，让界面瞬间更新；服务器那一份才是权威结果，完成后会纠正客户端的数据（如果不一致的话）。 这就是乐观更新，在网络不好时效果特别明显。 

import { Meteor } from 'meteor/meteor'
import { Mongo } from 'meteor/mongo'
import { check } from 'meteor/check'

export const Measures = new Mongo.Collection('measures')

Meteor.methods({
  async 'measure.add'(measure) {
    // 校验参数：方法可以被任何客户端调用，永远不要信任输入
    check(measure, { value: Number, error: Boolean })

    await Measures.insertAsync({
      ...measure,
      date: new Date(),
    })
  },
})
原书 · Meteor 1.x（同步，基于 Fibers）
Meteor.methods({
  'measure.add' (measure) {
    Measures.insert({

Meteor 3（async/await）

发布与订阅

数据在服务器的 MongoDB 里，客户端要怎么拿到它？Meteor 的答案是发布/订阅：服务器发布一个查询，客户端订阅它。 订阅之后，查询结果会被同步到客户端的 Minimongo 中，并且持续保持同步 —— 服务器上的数据有任何变化，都会被自动推送过来。

发布

import { Meteor } from 'meteor/meteor'
import { Measures } from './measures'

Meteor.publish('measures', function () {
  return Measures.find({})
})

import '../imports/api/measures'
import '../imports/api/publications'   // 只有服务器需要发布

在 Vue 组件中订阅和查询

原书使用 vue-meteor-tracker 提供的 meteor 组件选项（选项式 API）。新版的 vue-meteor-tracker 提供了组合式 API：

  • subscribe(名称, ...参数)：订阅一个发布，组件卸载时自动取消；
  • autorun(函数)：在 Meteor 的响应式计算（Tracker）中运行函数，函数读到的 Meteor 数据变化时自动重新运行，.result 是一个包含最新结果的 ref。
<script setup>
import { computed } from 'vue'
import { subscribe, autorun } from 'vue-meteor-tracker'
import { Measures } from '../api/measures'
import ProductionIndicator from './ProductionIndicator.vue'

// 订阅
subscribe('measures')

// 查询：按时间倒序。Minimongo 数据一变，measures 自动更新
const measures = autorun(() =>
  Measures.find({}, { sort: { date: -1 } }).fetch()
).result

// 之后就是普通的 Vue 计算属性了
const count = computed(() => measures.value.length)

const average = computed(() => {
  if (!count.value) return 0
  const total = measures.value.reduce((sum, m) => sum + m.value, 0)
  return total / count.value
})

const errorRate = computed(() => {
  if (!count.value) return 0
  const errors = measures.value.filter(m => m.error).length
  return errors / count.value
})
</script>

🔍 两套响应式系统的“握手”

Meteor 有自己的响应式系统 Tracker，Vue 有自己的响应式系统。autorun 做的就是桥接：在 Tracker 计算中执行你的查询， 每次 Tracker 通知“数据变了”，就把新结果写进一个 Vue ref，于是 Vue 这边的 computed 和模板也跟着更新。 这和第 6 章“把 Leaflet 事件桥接到 Pinia”是同一个思路。

仪表组件：用 SVG 画半圆进度条

原书用 vue-progress-path 库画半圆进度条，但它只支持 Vue 2。其实用 SVG 自己画一个只需要十几行，还能顺便学一个很实用的技巧。

原理：stroke-dasharray

<script setup>
defineProps({
  value: { type: Number, required: true },   // 0 ~ 1
  title: String,
  info: [String, Number],
})
</script>

<template>
  <div class="production-indicator">
    <svg viewBox="0 0 180 100">
      <!-- 轨道 -->
      <path class="track" d="M10 90 A80 80 0 0 1 170 90" />
      <!-- 进度：Math.min/max 防止数值越界 -->
      <path class="bar" d="M10 90 A80 80 0 0 1 170 90"
            pathLength="1" stroke-dasharray="1"
            :stroke-dashoffset="1 - Math.min(Math.max(value, 0), 1)" />
    </svg>
    <div class="info">{{ info }}</div>
    <div class="title">{{ title }}</div>
  </div>
</template>

<style scoped>
.track, .bar { fill: none; stroke-width: 12; stroke-linecap: round; }
.track { stroke: #e5e5e5; }
.bar { stroke: #42b883; transition: stroke-dashoffset .6s ease; }
.production-indicator.danger .bar { stroke: #e53935; }
</style>
ⓘ SVG 弧线命令 A

A80 80 0 0 1 170 90 的意思是：画一段 x、y 半径都是 80 的椭圆弧，旋转 0 度，取小弧（0），顺时针方向（1），终点在 (170, 90)。 起点 (10, 90) 和终点 (170, 90) 相距 160 = 2 × 80，所以正好是一个半圆。

数据很多时：大列表的性能补充

打开“每秒自动生成”跑上几个小时，测量记录会涨到上万条。这时你会发现仪表盘越来越卡：每来一条新数据，Vue 都要重新比较一万个列表项；浏览器要维护一万组 DOM 节点。 解决思路有三层，从简单到复杂：

① 少要数据

仪表盘上的列表，用户其实只会看最近的几十条。在发布函数里就限制数量，客户端的数据量直接降两个数量级：

Meteor.publish('measures.recent', function (limit = 200) {
  check(limit, Number)
  return Measures.find({}, { sort: { date: -1 }, limit: Math.min(limit, 1000) })
})

至于“平均值”“错误率”这类统计，应该由服务器基于全部数据计算后发布一个汇总结果（或者定时写进一个 stats 集合），而不是把一万条原始数据都发给浏览器去算。

② v-memo：跳过没变的列表项

v-memo 接收一个依赖数组：重新渲染时，如果数组里的值都没变，Vue 会直接复用这个元素上次的结果，连虚拟 DOM 都不生成、不比较。 测量记录一旦写入就不会再修改，正好适合： 

<div v-for="item of measures" :key="item._id" v-memo="[item._id]">
  <div class="date">{{ item.date.toLocaleString() }}</div>
  <div class="error">{{ item.error ? '错误' : '' }}</div>
  <div class="value">{{ item.value }}</div>
</div>
⚠ 依赖写漏了，界面就不更新

v-memo 是一把“手动挡”的刀：如果某一项的 value 后来真的改了，但它不在依赖数组里，界面就不会更新。 只在确认存在性能问题、而且依赖清晰的大列表上使用。相关的还有 v-once：只渲染一次，之后永远不更新。

③ 虚拟滚动：只渲染看得见的部分

如果确实需要展示上万行（比如可以无限往下翻的日志），就用虚拟滚动：容器高度按全部数据计算（滚动条正常），但只真正渲染可视区域内的几十行：

<script setup>
import { useVirtualList } from '@vueuse/core'

const { list, containerProps, wrapperProps } = useVirtualList(measures, {
  itemHeight: 32,          // 每行固定高度（像素）
  overscan: 10,            // 可视区域外多渲染几行，滚动更顺滑
})
</script>

<template>
  <div v-bind="containerProps" class="list" style="height: 400px">
    <div v-bind="wrapperProps">
      <div v-for="{ data: item } in list" :key="item._id" class="row" style="height: 32px">
        {{ item.date.toLocaleString() }} · {{ item.value }}
      </div>
    </div>
  </div>
</template>

完整示例：Express + SSE 实时仪表盘补充

下面用最少的代码实现和 Meteor 版本相同的效果。SSE（Server-Sent Events）是浏览器原生支持的“服务器推送”： 客户端发起一个普通的 HTTP 请求，服务器不结束响应，而是一条一条地往里写 data: ...，浏览器每收到一条就触发一次事件，断线还会自动重连。 

import express from 'express'

const app = express()
app.use(express.json())

const measures = []            // 演示用：存在内存里
const clients = new Set()      // 所有打开的 SSE 连接

// 客户端订阅：保持连接不断开
app.get('/api/stream', (req, res) => {
  res.set({
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  })
  res.flushHeaders()
  // 先把最近 50 条发过去，作为初始数据
  res.write(`event: init\ndata: ${JSON.stringify(measures.slice(-50))}\n\n`)
  clients.add(res)
  req.on('close', () => clients.delete(res))     // 断开时移除
})

// 写入新数据，并推送给所有订阅者
app.post('/api/measures', (req, res) => {
  const { value, error } = req.body
  if (typeof value !== 'number' || typeof error !== 'boolean') return res.sendStatus(400)
  const measure = { id: crypto.randomUUID(), value, error, date: new Date() }
  measures.push(measure)
  for (const client of clients) client.write(`data: ${JSON.stringify(measure)}\n\n`)
  res.status(201).json(measure)
})

app.listen(3000)

import { ref, onMounted, onBeforeUnmount } from 'vue'

export function useMeasuresStream(url = '/api/stream') {
  const measures = ref([])
  const connected = ref(false)
  let source

  onMounted(() => {
    source = new EventSource(url)
    source.onopen = () => { connected.value = true }
    source.onerror = () => { connected.value = false }     // 浏览器会自动重连
    source.addEventListener('init', (e) => {               // 自定义事件：初始数据
      measures.value = JSON.parse(e.data).reverse()
    })
    source.onmessage = (e) => {                             // 默认事件：每条新数据
      measures.value = [JSON.parse(e.data), ...measures.value].slice(0, 500)   // 只保留最近 500 条
    }
  })

  onBeforeUnmount(() => source?.close())                   // 离开页面时断开

  return { measures, connected }
}

</script>
ⓘ 和 Meteor 版本比一比

SSE 版本需要自己处理：数据存储、连接管理、初始数据、断线重连后的数据补齐（这里简单地用 init 事件重发最近 50 条）、多台服务器之间的消息同步（需要 Redis 等）。 Meteor 把这些全部包办了，但代价是绑定它的整套技术栈。两种方式没有绝对的好坏，取决于项目规模和团队熟悉的技术。 VueUse 也提供了 useEventSource 和 useWebSocket，可以进一步简化客户端代码。

动手练习

  1. 发布只返回最近 50 条测量，并在仪表盘上显示“共 N 条记录”。
  2. 加一个 measure.clear 方法清空所有数据，并在生成页加一个按钮（想一想：这个方法应该允许任何人调用吗？）。
  3. 给仪表组件加一个 max prop，让它能显示 0~max 而不只是 0~1 的值；再加上刻度。
  4. 让发布接收一个参数 onlyErrors，仪表盘上加一个复选框，勾选时只订阅错误记录（提示：subscribe('measures', () => [onlyErrors.value]) 这类写法能让参数变化时重新订阅，具体以 vue-meteor-tracker 文档为准）。
  5. 把本章的 Express + SSE 示例跑起来，打开两个浏览器窗口验证实时效果；再加一个“连接状态”指示灯（用 connected）。
  6. 用 useVirtualList 渲染 10000 条模拟数据，在 Performance 面板里对比使用前后的渲染时间。
