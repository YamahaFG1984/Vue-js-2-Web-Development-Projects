深入响应式原理

前面八章一直在用 ref、computed、watch。改了数据界面就会变，像魔法一样。 本章我们拆开这个魔法：先用不到 100 行代码亲手写一个迷你响应式系统，再对照 Vue 的真实实现， 最后学习几个只有懂了原理才用得好的 API：effectScope、customRef 和各种“逃生舱”。

本章目标

  • 理解响应式的三个角色：响应式数据、副作用（effect）、依赖关系
  • 用 Proxy 亲手实现 reactive、effect、track、trigger
  • 在此基础上实现 ref 和惰性缓存的 computed
  • 理解调度器：为什么更新是批量的、异步的
  • 用 effectScope 管理一组副作用，写出可共享的组合式函数
  • 用 customRef 自定义依赖追踪，写一个防抖 ref
  • 知道 shallowRef、markRaw、toRaw 等性能工具什么时候用
  • 了解 Vapor Mode：不用虚拟 DOM 的 Vue
ⓘ 本章适合谁

学完前八章、能熟练写组件之后再来读。本章的代码不需要在项目里使用，它的目的是帮你建立正确的心智模型： 以后遇到“为什么这里不更新”“为什么 watch 触发了两次”之类的问题，你能自己推理出答案。

三个角色

先看一段最普通的代码：

const state = reactive({ price: 10, quantity: 2 })

watchEffect(() => {
  console.log('总价', state.price * state.quantity)
})

state.quantity = 3   // 控制台自动打印：总价 30

这里面有三样东西。响应式数据 state；一个副作用函数（effect），也就是传给 watchEffect 的箭头函数； 以及它们之间的依赖关系：“这个函数读过 state.price 和 state.quantity”。 组件的渲染函数也是一个 effect，所以模板用到的数据变了，组件就会重新渲染。

所以响应式系统要解决的就是两件事：

  1. track（追踪）：effect 运行期间，每读一个响应式属性，就记下“当前 effect 依赖这个属性”。
  2. trigger（触发）：某个属性被修改时，找出所有依赖它的 effect，重新运行它们。

动手写一个迷你响应式系统

第一步：依赖表的数据结构

“哪个对象的哪个属性被哪些 effect 依赖”是一个三层结构。Vue 用 WeakMap → Map → Set 来存： 第一层用对象做键（用 WeakMap，对象不再被使用时能被垃圾回收），第二层用属性名做键，第三层是不重复的 effect 集合。 

const targetMap = new WeakMap()
let activeEffect = null          // 当前正在运行的 effect

function track(target, key) {
  if (!activeEffect) return      // 不在 effect 里读取，不用记录
  let depsMap = targetMap.get(target)
  if (!depsMap) targetMap.set(target, (depsMap = new Map()))
  let dep = depsMap.get(key)
  if (!dep) depsMap.set(key, (dep = new Set()))
  dep.add(activeEffect)
}

function trigger(target, key) {
  const dep = targetMap.get(target)?.get(key)
  if (!dep) return
  // 复制一份再遍历，避免 effect 运行时又往 dep 里加自己导致死循环
  ;[...dep].forEach((effect) => effect())
}

第二步：用 Proxy 拦截读写

Proxy 可以拦截对一个对象的几乎所有操作。我们在 get 里调用 track，在 set 里调用 trigger。 Reflect 则负责完成“原本的”读写操作： 

function reactive(target) {
  return new Proxy(target, {
    get(obj, key, receiver) {
      track(obj, key)
      const value = Reflect.get(obj, key, receiver)
      // 读到的值如果也是对象，就把它也变成响应式（懒代理：用到才代理）
      return value !== null && typeof value === 'object' ? reactive(value) : value
    },
    set(obj, key, value, receiver) {
      const old = obj[key]
      const ok = Reflect.set(obj, key, value, receiver)
      if (old !== value) trigger(obj, key)   // 值没变就不触发
      return ok
    },
  })
}
🔎 这就是 Vue 2 和 Vue 3 的根本差别

Vue 2 用 Object.defineProperty 给每个已有属性装 getter/setter，所以“新增属性”和“用下标改数组”无法被检测， 必须用 Vue.set。Proxy 拦截的是整个对象上的操作，新增、删除属性和数组下标都能捕获，这些限制也就没有了。 真实的 Vue 还拦截了 has（in 运算符）、deleteProperty、ownKeys（遍历），并对数组方法和 Map/Set 做了专门处理。

第三步：effect

effect 只做一件事：运行函数之前把自己设为 activeEffect，这样函数里读到的每个属性都会登记到它名下。

function effect(fn) {
  const run = () => {
    const prev = activeEffect
    activeEffect = run
    try {
      return fn()
    } finally {
      activeEffect = prev      // 恢复外层 effect，支持嵌套
    }
  }
  run()                        // 立即运行一次，收集初始依赖
  return run
}

完成了。试一试：

const state = reactive({ price: 10, quantity: 2 })
effect(() => console.log('总价', state.price * state.quantity))   // 总价 20
state.quantity = 3                                                 // 总价 30
state.price = 20                                                   // 总价 60

下面的演示运行的正是上面这几十行代码，页面上没有加载 Vue。点按钮修改数据，右边的日志会显示每次 track 和 effect 的运行：

第四步：清理过期依赖

上面的实现有个隐藏 bug。看这个 effect：

effect(() => {
  el.textContent = state.showDetail ? state.detail : '已隐藏'
})

第一次运行时 showDetail 为 true，effect 读了 showDetail 和 detail。 后来 showDetail 变成 false，effect 不再读 detail，但依赖表里仍然记着它，于是修改 detail 时 effect 还会白白运行一次。 解决方法是：每次运行前，先把 effect 从所有 dep 中移除，运行时再重新收集： 

function effect(fn) {
  const run = () => {
    run.deps.forEach((dep) => dep.delete(run))   // 清除旧依赖
    run.deps.length = 0
    const prev = activeEffect
    activeEffect = run
    try { return fn() } finally { activeEffect = prev }
  }
  run.deps = []          // 记录“我在哪些 dep 里”
  run()
  return run
}

// track 里多加一行：
dep.add(activeEffect)
activeEffect.deps.push(dep)
✓ Vue 3.5 的实现更聪明

每次全部删掉再重新收集，开销不小。Vue 3.5 重写了响应式系统：依赖改用双向链表存储，每个依赖带一个版本号， 重新运行后只移除这一轮没有再被访问的那些。官方数据是内存占用下降了 56%。思路和我们的一样，只是更高效。

实现 ref 和 computed

ref：只有一个 value 属性的对象

Proxy 只能代理对象，数字、字符串这类原始值没法代理。所以 ref 把值装进一个对象，通过 value 的 getter/setter 来追踪。 这就是 .value 存在的原因： 

function ref(initial) {
  let _value = initial
  const r = {
    get value() {
      track(r, 'value')
      return _value
    },
    set value(v) {
      if (v === _value) return
      _value = v
      trigger(r, 'value')
    },
  }
  return r
}

computed：带“脏标记”的惰性 effect

computed 有两个特点：惰性（没人读就不计算）和缓存（依赖没变就直接返回上次的结果）。 实现关键是给 effect 加一个调度器（scheduler）：依赖变化时不直接重新计算，只把自己标记为“脏”，并通知读过这个 computed 的 effect。 

function computed(getter) {
  let cached
  let dirty = true
  const c = {}

  // 不用 effect() 立即运行，而是自己控制何时运行
  const runner = () => {
    runner.deps.forEach((dep) => dep.delete(runner)); runner.deps.length = 0
    const prev = activeEffect
    activeEffect = runner
    try { return getter() } finally { activeEffect = prev }
  }
  runner.deps = []
  // trigger 调用 runner 时，走调度器：只标脏 + 通知下游
  runner.scheduler = () => {
    if (!dirty) { dirty = true; trigger(c, 'value') }
  }

  Object.defineProperty(c, 'value', {
    get() {
      track(c, 'value')               // 读 computed 的 effect 依赖它
      if (dirty) { cached = runner(); dirty = false }
      return cached
    },
  })
  return c
}

// trigger 也要改一下：有 scheduler 就调用 scheduler
;[...dep].forEach((e) => (e.scheduler ? e.scheduler() : e()))

调度器：为什么更新是批量的

我们的迷你版本每改一次数据，effect 就同步运行一次。如果连续改 100 次，组件就渲染 100 次，显然太浪费。 Vue 给组件渲染 effect 也设置了调度器：不立即渲染，而是把任务放进队列，在微任务中统一执行，同一个任务只入队一次。 第 2 章讲的 nextTick，等的就是这个队列被清空。 

const queue = new Set()
let flushing = false
const resolved = Promise.resolve()

function queueJob(job) {
  queue.add(job)                 // Set 自动去重
  if (!flushing) {
    flushing = true
    resolved.then(() => {
      queue.forEach((j) => j())
      queue.clear()
      flushing = false
    })
  }
}

function nextTick(fn) {
  return fn ? resolved.then(fn) : resolved
}

// 渲染 effect 用调度器把自己放进队列
const update = () => render()
update.scheduler = () => queueJob(update)

这也解释了 watch 的 flush 选项：

flush回调何时运行适合
'pre'（默认）组件更新之前，放进队列大多数情况
'post'组件更新之后，能拿到新 DOM回调里要读 DOM（等价于 watchPostEffect）
'sync'数据一变立即同步运行，不进队列极少数需要同步响应的场景，注意性能

回到 Vue：原理对应的 API

有了心智模型，回头看 Vue 的 API 就清楚多了。下面几个是 Vue 3.5 带来的、和 effect 生命周期相关的新能力：

import { watch, onWatcherCleanup } from 'vue'

watch(id, async (newId) => {
  const controller = new AbortController()
  // 3.5+：effect 下一次重新运行（或被停止）之前调用，用来取消上一次的请求
  onWatcherCleanup(() => controller.abort())
  data.value = await fetch(`/api/items/${newId}`, { signal: controller.signal }).then((r) => r.json())
})

// 3.5+：deep 可以是数字，只追踪到指定层数
watch(tree, render, { deep: 2 })

// 3.4+：只触发一次
watch(ready, init, { once: true })

// 3.5+：暂停 / 恢复 / 停止
const { pause, resume, stop } = watch(source, cb)
⚠ onWatcherCleanup 必须在 await 之前调用

和 onMounted 一样，它依赖“当前正在运行的 effect”这个全局变量（就是我们的 activeEffect）。 一旦经过 await，同步执行上下文就结束了，Vue 不知道你在哪个 watcher 里。需要在 await 之后注册时，改用回调的第三个参数 onCleanup。

effectScope：成组管理副作用

组件里创建的 computed、watch 会在组件卸载时自动停止。原理是：组件 setup 运行时，有一个“当前作用域”收集了这期间创建的所有 effect，卸载时一起停掉。 这个能力通过 effectScope 暴露给了我们： 

import { effectScope, ref, computed, watch, onScopeDispose } from 'vue'

const scope = effectScope()
scope.run(() => {
  const count = ref(0)
  const doubled = computed(() => count.value * 2)
  watch(count, (v) => console.log(v))
  onScopeDispose(() => console.log('作用域被停止了'))   // 类似 onUnmounted，但不依赖组件
})

scope.stop()   // 上面的 computed 和 watch 都停了

实战：多个组件共享一个组合式函数

假设 useMouse() 在 window 上监听 mousemove。页面上 10 个组件都调用它，就会注册 10 个监听器。 用 effectScope 可以让它们共享同一份状态，最后一个使用者卸载时才清理： 

import { effectScope, onScopeDispose } from 'vue'

export function createSharedComposable(composable) {
  let subscribers = 0
  let state, scope

  const dispose = () => {
    subscribers--
    if (scope && subscribers <= 0) {
      scope.stop()
      state = scope = undefined
    }
  }

  return (...args) => {
    subscribers++
    if (!state) {
      // detached: true —— 不挂在当前组件的作用域下，否则第一个组件卸载就会把它停掉
      scope = effectScope(true)
      state = scope.run(() => composable(...args))
    }
    onScopeDispose(dispose)   // 调用者（组件）卸载时减少计数
    return state
  }
}

// 使用
export const useSharedMouse = createSharedComposable(useMouse)

VueUse 里同名的 createSharedComposable 就是这么实现的。Pinia 也一样：每个 store 都运行在自己的 effectScope 里，所以 store 里的 computed 和 watch 不随组件卸载而停止。

customRef：自己决定何时追踪、何时触发

customRef 把 track 和 trigger 两个函数直接交给你，你自己决定什么时候调用它们。 经典例子是防抖 ref：输入框每次输入都更新值，但界面（以及依赖它的请求）等用户停下 300 毫秒后才更新： 

import { customRef } from 'vue'

export function useDebouncedRef(value, delay = 300) {
  let timer
  return customRef((track, trigger) => ({
    get() {
      track()              // 读取时登记依赖
      return value
    },
    set(newValue) {
      clearTimeout(timer)
      timer = setTimeout(() => {
        value = newValue
        trigger()          // 停顿 delay 毫秒后才通知
      }, delay)
    },
  }))
}

<script setup>
import { watch } from 'vue'
import { useDebouncedRef } from '@/composables/useDebouncedRef'

const keyword = useDebouncedRef('')
watch(keyword, (k) => search(k))   // 停止输入 300ms 后才搜索
</script>

<template>
  <input v-model="keyword" placeholder="搜索…">
</template>
ⓘ 注意 v-model 的小问题

因为 set 之后值不会立即变，输入框在防抖期间显示的仍是用户输入的内容（DOM 自己的值），这没问题。 但如果你在防抖期间读 keyword.value，拿到的是旧值。需要“输入框立即响应，搜索延迟执行”时，更常见的做法是普通 ref 加 VueUse 的 watchDebounced。

性能逃生舱

深层响应式很方便，但代价是：每读一个嵌套对象都要创建代理、登记依赖。数据量大或者对象来自第三方库时，可以有选择地“关掉”响应式：

API作用本教程里的例子
shallowRef只有替换 .value 才触发第 6 章的帖子列表
triggerRef(r)手动通知一个 shallowRef “我改了里面的东西”原地修改大数组后调用一次
markRaw(obj)给对象打标记，永远不会被转成代理第 6 章的 Leaflet 地图实例（放进响应式数据里也不会被代理）
toRaw(proxy)拿到代理背后的原始对象把数据传给 structuredClone、IndexedDB 或第三方库时
readonly只读代理，写入时警告第 3 章的全局游戏状态
⚠ 代理不等于原对象

reactive(obj) !== obj。如果你把原对象和代理混着用，比如 list.includes(rawItem)，可能得到意外的 false。 同理，structuredClone(proxy) 会报错，需要先 toRaw。

Vapor Mode：不用虚拟 DOM 的 Vue

到目前为止，Vue 组件的更新流程是：数据变化 → 组件渲染 effect 重新运行 → 生成新的虚拟 DOM 树 → 和旧树比较（diff）→ 把差异应用到真实 DOM。 虚拟 DOM 让编写渲染逻辑很灵活，但“生成整棵树再比较”本身有开销。

既然响应式系统已经知道哪个数据被哪段代码使用，为什么不让每一处绑定直接对应一个小 effect，数据变了只更新那一个 DOM 节点？ 这就是 Vapor Mode：编译器把模板编译成直接创建、更新 DOM 的代码，跳过虚拟 DOM。

对写代码的人来说，变化非常小：组件的写法完全一样，只需要在 <script setup> 上加一个 vapor 标记：

<script setup vapor>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">点了 {{ count }} 次</button>
</template>
⚠ Vapor Mode 还在演进中

Vapor Mode 随 Vue 3.6 推出，同时 3.6 也把响应式核心换成了基于 alien-signals 思路的新实现。截至本文写作时，Vapor 只支持 <script setup> 的组合式写法， 部分功能（例如与一些虚拟 DOM 组件库混用的细节、SSR 水合）仍在完善。是否在生产中使用、怎么启用，请以 Vue 官方文档和发布说明为准。 好消息是：本章讲的响应式原理在两种模式下完全相同，Vapor 只是让“effect → DOM”这一步更直接。

小结

概念一句话
track / triggereffect 运行时读属性就登记依赖；改属性就重新运行依赖它的 effect
依赖表WeakMap<对象, Map<属性, Set<effect>>>（3.5 起改为链表 + 版本号）
Proxy拦截整个对象的操作，所以新增属性、数组下标都能追踪
ref原始值不能被代理，所以用一个带 value getter/setter 的对象包起来
computed惰性 effect + 脏标记 + 缓存
调度器渲染任务进队列、去重、在微任务里统一执行；nextTick 等这个队列
effectScope收集一组 effect，一次停止；组件和 Pinia store 都靠它
customRef自己掌控 track 和 trigger 的时机，例如防抖
逃生舱shallowRef、markRaw、toRaw：大数据和第三方对象
Vapor Mode细粒度 effect 直接更新 DOM，跳过虚拟 DOM

动手练习

  1. 给迷你响应式系统加上 deleteProperty 拦截：delete state.x 时触发依赖 x 的 effect。
  2. 现在 for (const k in state) 这样的遍历不会被追踪。用 ownKeys 拦截和一个特殊的键（比如 Symbol('iterate')）实现它：新增或删除属性时触发遍历过的 effect。
  3. 实现 watch(getter, cb)：用一个带 scheduler 的 effect，scheduler 里重新运行 getter，并把新旧值传给 cb。
  4. 把迷你调度器接入演示：连续点击“＋”三次时让总价 effect 只运行一次，观察日志的变化。
  5. 用 customRef 写一个 useLocalStorageRef(key, initial)：读取时从 localStorage 取，写入时保存并触发更新。
