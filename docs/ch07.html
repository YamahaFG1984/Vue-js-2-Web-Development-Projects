CSS 兼容：PostCSS 与 browserslist

写 CSS 时，我们希望它在大多数浏览器里都能正常工作，比如自动为 user-select 补上 -webkit-user-select 这样的厂商前缀。 PostCSS 是一个 CSS 后处理工具，靠插件工作；autoprefixer 是其中最有名的插件。

Vite 内置了 PostCSS：只要项目根目录有 postcss.config.js，它就会自动应用到所有 CSS（包括 .vue 里的 <style> 和 Stylus 编译后的结果）。 

npm install -D autoprefixer

用 browserslist 指定目标浏览器

要支持哪些浏览器，由 browserslist 配置决定（数据来自 caniuse.com）。在 package.json 里加一个字段： 

"browserslist": [
  "defaults",          // ≈ 使用率 > 0.5%、最近 2 个版本、仍在维护的浏览器
  "not dead"
]
ⓘ 原书的配置该换了

原书用的是 "> 1%", "last 2 versions", "not ie <= 8"。现在推荐直接用 defaults；IE 已全面退役，不需要再写排除规则。 在 browsersl.ist 网站输入查询语句，能看到它具体覆盖了哪些浏览器。

✓ 现在需要前缀的属性已经很少了

主流浏览器早已停止新增厂商前缀，autoprefixer 在现代目标下实际补充的东西越来越少。Vite 还支持用更快的 Lightning CSS 取代 PostCSS （css: { transformer: 'lightningcss' }），它同时负责加前缀和降级新语法。

用 ESLint 检查代码质量

多人协作时，必须保证没有低级错误（比如用了未声明的变量），并让代码风格保持一致。自动检查代码的过程叫 lint。 ESLint 是 Vue 团队推荐的工具，eslint-plugin-vue 提供了遵循 Vue 官方风格指南的规则。

ESLint 9 的扁平配置

原书使用 .eslintrc.js，还要安装 babel-eslint、eslint-config-standard 及其四个配套插件。 ESLint 9 改用了全新的扁平配置（flat config），文件名是 eslint.config.js，旧格式已被弃用。如果你在 create-vue 里勾选了 ESLint，它已经帮你生成好了，大致如下： 

import js from '@eslint/js'
import pluginVue from 'eslint-plugin-vue'
import globals from 'globals'

export default [
  // 1. 要检查哪些文件
  { files: ['**/*.{js,mjs,jsx,vue}'] },

  // 2. 忽略构建产物
  { ignores: ['**/dist/**', '**/coverage/**'] },

  // 3. 规则集：从通用到具体，后面的覆盖前面的
  js.configs.recommended,                  // JavaScript 推荐规则
  ...pluginVue.configs['flat/recommended'], // Vue 推荐规则（含 .vue 解析器）

  // 4. 运行环境与自定义规则
  {
    languageOptions: {
      globals: { ...globals.browser },     // window、document 等浏览器全局变量
    },
    rules: {
      'comma-dangle': ['error', 'always-multiline'],
      'vue/multi-word-component-names': 'warn',
    },
  },
]

规则的级别有三种：'off'（0）、'warn'（1）、'error'（2）。

ⓘ 想要 Standard 风格？

原书使用 StandardJS 风格（无分号、两空格缩进）。它的扁平配置继任者是社区维护的 neostandard：npm i -D neostandard，然后在数组里加上 ...neostandard()。

运行 ESLint

"lint": "eslint . --fix"

--fix 会自动修复能修复的问题（比如缺少的逗号）。剩下的需要手动处理。错误信息末尾会显示规则名，如 no-unused-vars 或 vue/require-v-for-key， 到 eslint.org 或 eslint.vuejs.org 搜索它就能看到详细说明。

✓ 原书的 no-new 报错消失了

原书在 new Vue({...}) 这一行收到 no-new 错误（创建了对象却没有保存），只好加注释禁用。 Vue 3 写的是 createApp(App).mount('#app')，是函数调用而不是 new，这个问题自然不存在了。 真的需要临时禁用某条规则时，用 // eslint-disable-next-line 规则名。

ⓘ Prettier 和 ESLint 的分工

ESLint 负责代码质量（可能的 bug、不推荐的写法），Prettier 负责代码格式（缩进、换行、引号）。create-vue 勾选 Prettier 时会自动关闭 ESLint 中与格式相关的规则，避免两者打架。 另外，用 Rust 编写的 Oxlint 速度快几十倍，create-vue 也提供了把它和 ESLint 搭配使用的选项。

用 Vitest 做单元测试

重要的代码和组件应该有单元测试：确认它按预期工作，并防止以后修改代码时把它改坏（回归）。原书使用 Jest，需要配置 vue-jest、babel-jest、 专门的 Babel 测试环境、jest-serializer-vue……

今天 Vue 官方推荐 Vitest：它由 Vite 团队开发，直接复用你的 vite.config.js， 所以 .vue 文件、别名、插件全都不用再配一遍；API 与 Jest 几乎相同，迁移成本很低。

快照测试

快照测试把某个值（通常是组件渲染出的 HTML）保存下来，以后每次运行时进行比较。HTML 意外变了，测试就会失败，提醒你检查是不是引入了回归。 原书为此借用了服务端渲染的 vue-server-renderer；现在直接用 wrapper.html()： 

test('快照', () => {
  const wrapper = mount(BaseButton, {
    props: {
      icon: 'add',
      disabled: true,
      badge: '3',
    },
    slots: {
      default: '<span>添加商品</span>',
    },
  })
  expect(wrapper.html()).toMatchSnapshot()
})

先正常跑一遍测试，确认只有你改动的那个组件的快照失败，再更新。否则可能把别处真正的回归也一起“合法化”了。

按需加载：动态 import 与代码分割

语言包可能很大，用户一次只用一种语言，没必要把五种都打包进首屏代码。我们用动态 import()：它返回一个 Promise， 构建工具会把被动态导入的模块拆成单独的文件（chunk），需要时才从服务器下载。这就是代码分割。 

async function loadModule() {
  const module = await import('./path/to/module.js')
  console.log('默认导出', module.default)
  console.log('具名导出', module.myExportedFunction)
}

路径里可以有变量，但必须让构建工具能“猜到”可能的文件范围：

import(myModulePath)                       // ✗ 完全未知，无法打包
import(`./locales/${locale}.js`)           // ✓ Vite 会把 locales 目录下所有 .js 都拆成 chunk
ⓘ Vite 对动态路径的要求

路径必须以 ./ 或 ../ 开头、要带文件扩展名、变量只能代表一层目录或文件名。需要更灵活的批量导入时，可以用 Vite 特有的 import.meta.glob('./locales/*.js')，它返回一个“路径 → 加载函数”的对象。 原书这里还需要把 Babel 预设从 stage-3 改成 stage-2 才能解析 import()；现在它已是标准语法，什么都不用改。

创建 i18n 实例

import { createI18n } from 'vue-i18n'
import langs from '../i18n'

// 把语言包按需加载进来并切换过去
// composer：i18n.global，或组件里 useI18n({ useScope: 'global' }) 的返回值
export async function loadLocale(composer, locale) {
  if (!composer.availableLocales.includes(locale)) {
    const { default: messages } = await import(`../i18n/locales/${locale}.js`)
    composer.setLocaleMessage(locale, messages)
  }
  composer.locale.value = locale
  if (typeof document !== 'undefined') {
    document.documentElement.lang = locale     // 顺便更新 <html lang>（服务器上没有 document）
  }
}

export async function setupI18n(locale) {
  const i18n = createI18n({
    legacy: false,          // 使用组合式 API 模式（v11 推荐）
    locale,
    fallbackLocale: 'en',   // 某个词缺翻译时退回英文
    messages: {},
  })
  await loadLocale(i18n.global, locale)
  return i18n
}

// 根据浏览器语言选择一个我们支持的语言
export function getAutoLang() {
  for (const tag of navigator.languages ?? [navigator.language]) {
    const lang = tag.slice(0, 2).toLowerCase()   // 'zh-CN' → 'zh'
    if (langs.includes(lang)) return lang
  }
  return 'en'
}

import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './components/App.vue'
import router from './router'
import { setupI18n, getAutoLang } from './utils/i18n'

async function main() {
  const i18n = await setupI18n(getAutoLang())   // 别忘了 await，否则拿到的是 Promise

  createApp(App)
    .use(createPinia())
    .use(router)
    .use(i18n)
    .mount('#app')
}

语言选择页面，用组合式 API 的 useI18n()：

<script setup>
import { ref } from 'vue'
import { useRouter } from 'vue-router'
import { useI18n } from 'vue-i18n'
import langs from '../i18n'
import { loadLocale } from '../utils/i18n'

const i18n = useI18n({ useScope: 'global' })   // 拿到全局的 i18n 组合器
const { t, locale } = i18n
const router = useRouter()
const loading = ref(false)

async function setLocale(lang) {
  loading.value = true
  await loadLocale(i18n, lang)   // 首次切换到某语言时，才去下载它的语言包
  loading.value = false
}
</script>

<template>
  <BasePage class="page-locale">
    <Transition name="fade" mode="out-in">
      <BaseLoading v-if="loading" key="loading" class="overlay" />
      <div v-else>
        <h1>{{ t('change-lang') }}</h1>
        <div class="locales">
          <div v-for="lang of langs" :key="lang" class="locale">
            <BaseButton :class="{ selected: lang === locale }" @click="setLocale(lang)">
              {{ t(`lang.${lang}`) }}
            </BaseButton>
          </div>
        </div>
        <div class="toolbar">
          <BaseButton class="secondary" @click="router.back()">{{ t('back') }}</BaseButton>
        </div>
      </div>
    </Transition>
  </BasePage>
</template>
ⓘ 只切换已加载的语言

如果语言包都已经加载过了，组件里直接 locale.value = 'fr' 就能切换；loadLocale 只是多做了一步“没加载过就先下载”。

✓ 价格和日期也要本地化

不同地区的数字和货币写法不同（1,234.5 vs 1.234,5，$ vs €）。vue-i18n 内置了基于 Intl 的 n() 和 d()：配置 numberFormats: { zh: { currency: { style: 'currency', currency: 'CNY' } } } 后，模板里写 {{ $n(item.price, 'currency') }}。

服务端渲染（SSR）

什么是 SSR，为什么需要它

到目前为止，我们的应用都是客户端渲染（CSR）：服务器返回一个几乎为空的 HTML，浏览器下载并执行 JS 之后，页面内容才出现。 服务端渲染（SSR）则是在服务器上先把应用运行一遍，把渲染好的 HTML 直接发给浏览器：

水合（hydration）是 SSR 的关键概念：浏览器拿到的 HTML 是“死”的（没有事件监听），客户端 Vue 启动后不会重新创建 DOM， 而是“认领”服务器渲染的现有 DOM，给它们挂上事件和响应式 —— 就像给干燥的骨架注入水分。

ⓘ 不是所有应用都需要 SSR

后台管理系统、需要登录才能用的工具类应用，首屏速度和 SEO 都不关键，用 CSR 就好。电商、博客、新闻、营销页这类需要被搜索引擎收录、追求首屏速度的场景才值得上 SSR。 如果内容基本不变，还可以考虑静态站点生成（SSG）：构建时就把每个页面渲染成 HTML 文件。

了解原理：手写 Vite SSR

如果你想理解 SSR 在底层是怎么工作的（或者有特殊需求不想用框架），可以参照 Vite 的 SSR 指南手写。 它的结构和原书一一对应，只是简单得多。

1. 通用的应用工厂

import { createSSRApp } from 'vue'
import { createPinia } from 'pinia'
import { createRouter } from './router'     // router.js 改为导出工厂函数
import { setupI18n } from './utils/i18n'
import App from './components/App.vue'

// 每次调用都返回全新的实例
export async function createApp({ locale }) {
  const app = createSSRApp(App)             // 注意是 createSSRApp：支持水合
  const pinia = createPinia()
  const router = createRouter()             // 内部：服务器用 createMemoryHistory，浏览器用 createWebHistory
  const i18n = await setupI18n(locale)

  app.use(pinia).use(router).use(i18n)
  return { app, router, pinia }
}

2. 组件里的数据预取

原书给组件加了一个自定义的 asyncData 选项。Vue 3 内置了 onServerPrefetch 钩子：服务器渲染时会等待它返回的 Promise 完成后再输出 HTML。

<script setup>
import { onServerPrefetch, onMounted } from 'vue'
import { useItemsStore } from '../stores/items'

const itemsStore = useItemsStore()

// 服务器上：渲染前把数据取好
onServerPrefetch(() => itemsStore.fetchItems())

// 浏览器上：如果 store 里已经有服务器给的数据，就不再请求
onMounted(() => {
  if (!itemsStore.items.length) itemsStore.fetchItems()
})
</script>

3. 服务端入口

import { renderToString } from 'vue/server-renderer'
import { createApp } from './app'

export async function render(url, locale) {
  const { app, router, pinia } = await createApp({ locale })

  await router.push(url)
  await router.isReady()               // 等异步路由组件加载完（取代原书的 router.onReady）

  const html = await renderToString(app)   // 会等待所有 onServerPrefetch
  const state = JSON.stringify(pinia.state.value)

  return { html, state }
}

4. 客户端入口

import { createApp } from './app'
import { getAutoLang } from './utils/i18n'

const { app, router, pinia } = await createApp({ locale: getAutoLang() })

// 恢复服务器序列化的状态（取代原书的 store.replaceState）
if (window.__INITIAL_STATE__) {
  pinia.state.value = window.__INITIAL_STATE__
}

await router.isReady()
app.mount('#app')                       // 因为是 createSSRApp，这里会进行水合

<!doctype html>

    <div id="app"><!--app-html--></div>

import fs from 'node:fs/promises'
import express from 'express'
import { createServer as createViteServer } from 'vite'

const app = express()

// 以中间件模式运行 Vite：负责编译和热更新（取代原书的 server.dev.js + memory-fs + 各种中间件）
const vite = await createViteServer({
  server: { middlewareMode: true },
  appType: 'custom',
})
app.use(vite.middlewares)

app.use('*all', async (req, res) => {
  try {
    const url = req.originalUrl
    let template = await fs.readFile('index.html', 'utf-8')
    template = await vite.transformIndexHtml(url, template)

    // 直接加载源码里的服务端入口，Vite 会即时编译
    const { render } = await vite.ssrLoadModule('/src/entry-server.js')
    const locale = req.acceptsLanguages('zh', 'en', 'fr', 'es', 'de') || 'en'
    const { html, state } = await render(url, locale)

    res.status(200).set({ 'Content-Type': 'text/html' }).end(
      template
        .replace('<!--app-html-->', html)
        .replace('<!--app-state-->', state)
    )
  } catch (e) {
    vite.ssrFixStacktrace(e)
    console.error(e)
    res.status(500).end('500 | Internal Server Error')
  }
})

⚠ 序列化状态时注意 XSS

直接把 JSON.stringify 的结果放进 <script> 有风险：如果数据里有 </script> 这样的字符串（比如商品评论），就能截断脚本标签注入代码。 生产环境请用 devalue 或 serialize-javascript 这类会转义危险字符的序列化库（Nuxt 内部用的就是 devalue）。

ⓘ 写“通用代码”的注意事项
  • window、document、localStorage 在服务器上不存在。只在 onMounted 里，或用 import.meta.env.SSR 判断后再访问。
  • 服务器上只会执行 setup 和 onServerPrefetch，onMounted 等钩子不会执行，所以在这里启动的定时器不会泄漏。
  • 服务器和客户端渲染的结果必须一致，否则会出现“水合不匹配（hydration mismatch）”警告，比如直接在模板里显示 Date.now() 或随机数。

生产构建

原书最后一节为生产构建做了大量配置：用 extract-text-webpack-plugin 把 CSS 抽成文件、加 ModuleConcatenationPlugin 优化、 用 rimraf 清理 dist、写 cross-env 设置环境变量……

★ 在 Vite 里，这些全是默认行为

vite build 默认就会：把 CSS 抽成独立文件并压缩、对 JS 做 tree-shaking 和压缩、作用域提升、按动态 import 拆分代码、给文件名加内容哈希、构建前清空输出目录。 import.meta.env.PROD / import.meta.env.MODE 取代了手动设置的 NODE_ENV。

普通（CSR）应用：

npm run build      # 输出到 dist/
npm run preview    # 本地预览

手写 Vite SSR 时，需要分别构建客户端和服务端两个包：

"scripts": {
  "dev": "node server",
  "build": "npm run build:client && npm run build:server",
  "build:client": "vite build --outDir dist/client --ssrManifest",
  "build:server": "vite build --outDir dist/server --ssr src/entry-server.js",
  "start": "NODE_ENV=production node server"
}

把 dist/、server.js、package.json 和 lock 文件上传到服务器，执行 npm ci --omit=dev 安装依赖，再 npm start 即可。
