第 3 章 · 项目二

城堡决斗：浏览器卡牌游戏

这次做一个完全不同的东西：双人回合制卡牌游戏。两位玩家各守一座城堡，用行动卡把对手的粮食或生命值打到零。 借这个项目，我们学习 Vue 最核心的概念 —— 组件，以及组件之间如何对话、如何做动画。

本章目标

  • 用 app.component() 定义和注册组件，理解“组件树”
  • 父传子用 props，子传父用 自定义事件 emit
  • 用 插槽 slot 让组件接收任意内容，用 <component :is> 动态切换组件
  • 用 <Transition> 和 <TransitionGroup> 做进出场和列表动画，理解 key
  • 在模板里直接生成动态 SVG，用模板引用访问 DOM 元素

游戏规则

  • 两位玩家轮流行动。
  • 每人开局有 10 点生命、10 点粮食和 5 张手牌；生命和粮食都不能超过 10。
  • 粮食或生命降到 0 即失败；两人可能同时失败（平局）。
  • 每个回合，当前玩家必须且只能打出一张牌，打出的牌进入弃牌堆。
  • 每个回合开始时从抽牌堆抽一张牌（每人的第一回合除外），所以回合开始时手里总是 5 张。
  • 抽牌堆空了，就把弃牌堆洗回去。
  • 卡牌可以改变自己或对手的生命和粮食，有的还能让某个玩家跳过回合。

游戏的精髓在于：大部分牌都会让自己付出代价（最常见的是消耗粮食），所以出牌前要想清楚。

除了顶栏和手牌，还有三种浮层（overlay）会轮流出现，盖住手牌：

集中管理的游戏状态

state.js 用来把游戏的主要数据集中在一个对象里。这样，写游戏逻辑的函数可以直接修改它， 而不必把一堆方法塞进组件。在 Vue 3 里，我们用 reactive() 把这个对象变成响应式的： 

// 集中管理的游戏状态
const state = Vue.reactive({
  // 世界缩放比例：窗口越宽，场景越大
  worldRatio: getWorldRatio(),
})

worldRatio 表示场景要缩放多少才能适应窗口（0.6 表示缩到 60%），由 utils.js 里的 getWorldRatio() 计算。 窗口大小变化时要重新计算： 

const app = createApp({
  name: 'Game',
  setup() {
    // 把整个 state 交给模板使用
    return { state }
  },
  template: `<div class="game">
    {{ state.worldRatio }}
  </div>`,
})

// 窗口尺寸变化时更新比例
window.addEventListener('resize', () => {
  state.worldRatio = getWorldRatio()
})

横向拖动浏览器窗口，页面上的数字会跟着变。注意我们修改的是全局的 state 对象，而不是组件 —— 但因为 state 是 reactive() 创建的，任何读取它的组件都会自动更新。

原书 · Vue 2
var state = { worldRatio: getWorldRatio() }

new Vue({
  el: '#app',
  data: state,   // Vue 2 会“改造”这个对象本身
})
// this.$data === state  → true
Vue 3
const state = Vue.reactive({
  worldRatio: getWorldRatio(),
})

createApp({
  setup: () => ({ state }),
})
// 原始对象不变，reactive 返回的是它的代理
🔍 ref 还是 reactive？

ref() 可以装任何值（包括对象），读写要 .value；reactive() 只能装对象，直接用属性。 官方推荐默认使用 ref，但像这里“一个全局状态对象”的场景用 reactive 更顺手。 记住一个限制：不要把 reactive 对象解构（const { turn } = state），解构出来的是普通值，会丢失响应性。 这正是第 6 章引入 Pinia 要解决的问题之一。

定义和使用组件

新建 components/ui.js，在 main.js 之前引入。组件的本质就是一个选项对象，和传给 createApp 的对象用的是同一套选项：

然后在 main.js 里，在 mount 之前用 app.component() 注册它，就能在模板里像 HTML 标签一样使用了：

const app = createApp({

  template: `...`,

// 所有 new Vue() 都能用
Vue 3：注册到某一个应用上

app.mount('#app')
// 只有这个 app 能用
ⓘ 组件名的大小写

用 PascalCase（TopBar）注册的组件，在模板里写 <TopBar> 或 <top-bar> 都可以。 但如果模板是直接写在 HTML 文件里的（像第 2 章那样，称为 DOM 内模板），浏览器会把标签名转成小写，这时只能用 <top-bar></top-bar>，而且不能自闭合。 我们这里的模板写在 JS 字符串里，没有这个限制。

✓ 组件名用多个单词

Vue 官方风格指南建议组件名至少由两个单词组成（TodoItem 而不是 Item），以免将来和 HTML 原生标签撞名。 所以本教程把原书的 card、hand、overlay、castle、bubble、cloud 分别命名为 GameCard、CardHand、GameOverlay、PlayerCastle、StatBubble、SkyCloud。CSS 类名保持不变。

打开 DevTools，现在组件树里有两个节点：Game 和它下面的 TopBar。每个组件都是一个独立的实例。

父传子：props

组件之间需要通信。先看“向下”的方向：父组件把数据传给子组件，用 props。 顶栏需要知道三件事：有哪些玩家、当前是谁、第几回合。所以声明三个 prop： 

const TopBar = {
  props: ['players', 'currentPlayerIndex', 'turn'],
  template: `...`,
}

父组件像写 HTML 属性一样给 prop 传值。用 :（v-bind）传的是 JS 表达式：

<top-bar :turn="state.turn"
         :current-player-index="state.currentPlayerIndex"
         :players="state.players" />
ⓘ 命名约定

JS 里用 camelCase（currentPlayerIndex），模板属性里推荐用 kebab-case（current-player-index），Vue 会自动转换。

⚠ 不要在子组件里修改 prop

prop 是父组件“借”给你看的数据。直接 props.turn = 4 会收到 Vue 的警告，因为下次父组件重新渲染时你的修改会被覆盖， 而且数据到底在哪里被改的会变得无法追踪。想改？发一个事件，让父组件去改。

在模板里使用 props

prop 在模板里的用法和普通数据一样：

const TopBar = {
  props: ['players', 'currentPlayerIndex', 'turn'],
  template: `<div class="top-bar" :class="'player-' + currentPlayerIndex">
    <div class="player p0">{{ players[0].name }}</div>
    <div class="turn-counter">
      <img class="arrow" src="svg/turn.svg" />
      <div class="turn">第 {{ turn }} 回合</div>
    </div>
    <div class="player p1">{{ players[1].name }}</div>
  </div>`,
}

动态 class player-0 / player-1 会让 CSS 旋转箭头。在控制台试试：

state.currentPlayerIndex = 1
state.currentPlayerIndex = 0

箭头会转向对应的玩家，名字也会高亮。

🔍 在 setup 里使用 props（点击展开）

如果组件需要在 JS 里用到 prop，setup 的第一个参数就是 props 对象（它是响应式的）：

const TopBar = {
  props: ['players', 'currentPlayerIndex', 'turn'],
  setup(props) {
    console.log(props.players)           // ✓ 直接读
    // const { turn } = props           // ✗ 解构会丢失响应性（Vue 3.5 的 <script setup> 除外）
    const label = Vue.computed(() => `第 ${props.turn} 回合`)
    return { label }
  },
}

在组件上监听原生事件

给卡牌加一个点击处理：

<game-card :def="testCard" @click="handlePlay" />

在 Vue 2 里，这样写不会生效：组件上的 @click 被当作“自定义事件”，必须加 .native 修饰符才能监听原生点击。 Vue 3 简化了这一点：

★ Vue 3 变化：.native 被移除了

在 Vue 3 里，组件上的监听器如果没有在 emits 选项中声明，就会被自动“透传”到组件的根元素上，当作原生 DOM 事件监听。 所以上面的 @click 直接就能工作。这个机制叫透传 attribute（fallthrough attributes），class、style、id 等普通属性也一样会落到根元素上。

子传父：自定义事件

虽然原生 click 能用，但更好的做法是让卡牌组件自己决定什么时候算“出牌”，然后通知父组件。 将来如果要支持“键盘选中 + 回车出牌”，只需改卡牌组件内部，父组件不用动。这就是自定义事件： 

const GameCard = {
  props: ['def'],
  emits: ['play'],            // 声明本组件会发出哪些事件
  setup(props, { emit }) {    // setup 的第二个参数里有 emit 函数
    function play() {
      emit('play')            // 发出 play 事件
    }
    return { play }
  },
  template: `<div class="card" :class="'type-' + def.type" @click="play">
    ...
  </div>`,
}

父组件用 v-on（@）监听它，和监听原生事件的写法完全一样：

<game-card :def="testCard" @play="handlePlay" />

事件还可以带参数，监听函数会按顺序收到它们：

emit('play', 'orange', 42)

// 父组件中
function handlePlay(color, number) {
  console.log('color =', color, 'number =', number)   // color = orange number = 42
}
✓ 模板里的简写

简单的场景可以不写 setup，直接在模板里调用 $emit：@click="$emit('play')"。

⚠ Vue 3 删除了 $on / $off / $once

原书提到可以用 this.$on('play', ...) 在组件内部监听自己发出的事件。Vue 3 移除了这些实例方法， “事件总线（event bus）”的写法也随之失效。组件之间的通信请用 props/emit、provide/inject 或状态管理（第 6 章的 Pinia）。

用 <Transition> 给手牌做进出场动画

游戏中，浮层出现时手牌要隐藏。为了好看，我们在它进入和离开 DOM 时加上动画。Vue 提供了一个内置组件 <Transition>， 它能和 v-if / v-show 配合，自动在合适的时机给元素加上 CSS 类名。

先在状态里加一个 activeOverlay（当前显示的浮层名称，null 表示没有浮层）：

const state = Vue.reactive({
  // 界面
  activeOverlay: null,
  // ...
})

<transition>
  <card-hand v-if="!state.activeOverlay" :cards="testHand" />
</transition>

<transition> 本身不会出现在 DOM 中。元素进入时，Vue 会依次给它加上这些类；离开时同理：

⚠ Vue 3 变化：v-enter 改名为 v-enter-from

原书里的 v-enter 和 v-leave 在 Vue 3 中分别改名为 v-enter-from 和 v-leave-from， 和 -to 对称，更好理解。其余四个类名不变。迁移老代码时最容易漏掉这一处，动画会“没有起点”，直接跳到终态。

新建 transitions.css 并在页面里引入。先写一个最简单的淡入淡出：

.hand.v-enter-active,
.hand.v-leave-active {
  transition: opacity 1s;
}

.hand.v-enter-from,
.hand.v-leave-to {
  opacity: 0;
}

在控制台里把 state.activeOverlay 设成 'player-turn' 再改回 null，手牌会淡出淡入。 为了复用，给过渡起个名字，类名前缀就会从 v- 变成这个名字： 

<transition name="fade">
  <card-hand v-if="!state.activeOverlay" :cards="testHand" />
</transition>

.fade-enter-active,
.fade-leave-active {
  transition: opacity .5s;
}

.fade-enter-from,
.fade-leave-to {
  opacity: 0;
}

更漂亮的 3D 动画

现在做一个更像样的效果：整手牌像被玩家从桌上拿起来一样绕 X 轴翻转，同时牌从叠在一起逐渐展开。 过渡类名会加在 .hand 上，我们可以用后代选择器去动画它里面的 .wrapper 和 .card： 

/* 整体淡入淡出 */
.hand-enter-active,
.hand-leave-active {
  transition: opacity .5s;
}
.hand-enter-from,
.hand-leave-to {
  opacity: 0;
}

/* 绕水平轴 3D 翻转 */
.hand-enter-active .wrapper,
.hand-leave-active .wrapper {
  transition: transform .8s cubic-bezier(.08, .74, .34, 1);
  transform-origin: bottom center;
}
.hand-enter-from .wrapper,
.hand-leave-to .wrapper {
  transform: rotateX(90deg);
}

/* 牌从叠在一起展开：负的左右外边距让它们重叠 */
.hand-enter-active .card,
.hand-leave-active .card {
  transition: margin .8s cubic-bezier(.08, .74, .34, 1);
}
.hand-enter-from .card,
.hand-leave-to .card {
  margin: 0 -100px;
}

<transition name="hand">
  <card-hand v-if="!state.activeOverlay" :cards="testHand" />
</transition>
ⓘ Transition 只能包一个元素/组件

<Transition> 的内容必须是单个元素或单个组件，而且组件本身也要只有一个根元素（这里是 .hand）， 过渡类名才知道该加在谁身上。要动画一组元素，用下面马上介绍的 <TransitionGroup>。

出牌

卡牌被点击时会发出 play 事件。手牌组件监听它，再向自己的父组件发出一个 card-play 事件，并带上被点击的那张牌： 

const CardHand = {
  props: ['cards'],
  emits: ['card-play'],
  template: `<div class="hand">
    <div class="wrapper">
      <game-card v-for="card of cards" :key="card.uid" :def="card.def"
                 @play="$emit('card-play', card)" />
    </div>
  </div>`,
}

注意 @play 里直接用了 v-for 的循环变量 card：手牌组件本来就知道是哪张牌，卡牌组件不需要把自己传上来。 根组件里先写一个临时的出牌函数，把牌从手里移除： 

function testPlayCard(card) {
  const index = testHand.value.indexOf(card)
  testHand.value.splice(index, 1)
}

<card-hand v-if="!state.activeOverlay" :cards="testHand" @card-play="testPlayCard" />

用 <TransitionGroup> 给列表做动画

还差三种动画：牌被加入手牌（从右边滑入）、被打出（向上放大飞走）、以及其余的牌移动填补空位。 列表动画要用另一个内置组件 <TransitionGroup>： 

<transition-group name="card" tag="div" class="cards">
  <game-card v-for="card of cards" :key="card.uid" :def="card.def"
             @play="$emit('card-play', card)" />
</transition-group>
ⓘ Vue 3 变化：TransitionGroup 默认不渲染包裹元素

原书说 <transition-group> 默认会渲染成一个 <span>。Vue 3 中它默认不渲染任何包裹元素， 需要的话用 tag 属性指定，比如这里的 tag="div"。

key 的真正作用

<TransitionGroup> 的每个子元素必须有唯一的 key。为什么？因为 Vue 更新列表时，默认会尽量就地复用 DOM 元素：

所以用每张牌的 uid 作为 key。这也解释了为什么要给手牌里的每张牌一个 uid： 同一种牌（比如两张“投石机”）的 id 相同，不能拿来当 key。

列表动画的 CSS

<TransitionGroup> 除了那六个类名，还多了一个 v-move（这里是 card-move），加在位置发生变化的元素上。 Vue 会用 FLIP 技术，通过 transform 让元素平滑地移动到新位置，我们只需要提供一个过渡时长： 

.card {

三种浮层根据 activeOverlay 的值显示其中一个。为此先给 state 加几个 getter，方便取当前玩家和对手：

  <overlay-content-player-turn v-if="state.activeOverlay === 'player-turn'" :player="state.currentPlayer" />
  <overlay-content-last-play v-else-if="state.activeOverlay === 'last-play'" :opponent="state.currentOpponent" />
  <overlay-content-game-over v-else-if="state.activeOverlay === 'game-over'" :players="state.players" />

有点啰嗦。Vue 有一个特殊的内置元素 <component>，它可以“变身”成任何组件：is 属性给它组件名（或组件对象），它就渲染成那个组件。 我们的三个内容组件恰好都以 overlay-content- 开头…… 

<game-overlay v-if="state.activeOverlay">
  <component :is="'overlay-content-' + state.activeOverlay"
             :player="state.currentPlayer"
             :opponent="state.currentOpponent"
             :players="state.players" />
</game-overlay>

多余的 prop 不会影响各个浮层的工作（没声明的 prop 会作为普通属性透传到根元素上）。在控制台试试：

ⓘ :is 用字符串的前提

:is="'overlay-content-xxx'" 这种字符串写法，要求组件已经用 app.component() 全局注册。 第 4 章使用单文件组件后，我们更常直接传组件对象：:is="overlays[name]"。

浮层动画与 key

用一个名为 zoom 的过渡包住浮层：

  transition: opacity .3s, transform .3s;
}
.zoom-enter-from,

  opacity: 0;
  transform: scale(.7);
}

试一下会发现：从“无浮层”到“有浮层”有动画，反过来也有；但从一个浮层切换到另一个时没有动画。 原因还是就地复用：<game-overlay> 一直存在，Vue 只是换掉了它里面的内容。 给它加一个随浮层变化的 key，Vue 就会把不同的浮层当作不同的元素 —— 旧的离开、新的进入： 

<transition name="zoom">
  <game-overlay v-if="state.activeOverlay" :key="state.activeOverlay">
    <component :is="'overlay-content-' + state.activeOverlay" ... />
  </game-overlay>
</transition>
✓ 用 key 强制“换一个新的”

这是一个通用技巧：给元素或组件一个会变化的 key，每次 key 变化，Vue 都会销毁旧的、创建新的。常用于触发过渡，或者重置组件内部状态。

浮层背景

半透明背景不能放在浮层组件里面，否则会跟着一起缩放，很别扭。把它单独放在外面，用淡入淡出：

让数值“动”起来

现在旗帜长度会瞬间跳变。如果能平滑地伸缩就更好了。CSS 过渡帮不上忙（我们改的是 SVG 路径字符串）， 所以要对数值本身做动画：让 height 在 500 毫秒内从旧值逐渐变到新值。

原书用了 TWEEN.js 库。为了少一个依赖，也为了看清原理，我们自己写一个只有十几行的补间函数，放进 utils.js： 

// 缓动函数：输入 0~1 的进度，输出 0~1 的“加工后的进度”
const easeInOutCubic = (t) => t < .5 ? 4 * t * t * t : 1 - (-2 * t + 2) ** 3 / 2

// 补间动画：在 duration 毫秒内把数值从 from 变到 to
function tween({ from, to, duration, delay = 0, easing = easeInOutCubic, onUpdate, onComplete }) {
  let frameId
  const start = performance.now() + delay
  function frame(now) {
    const t = Math.min(Math.max((now - start) / duration, 0), 1)
    onUpdate(from + (to - from) * easing(t))
    if (t < 1) frameId = requestAnimationFrame(frame)
    else onComplete?.()
  }
  frameId = requestAnimationFrame(frame)
  return () => cancelAnimationFrame(frameId)   // 返回一个“取消”函数
}

然后在旗帜组件里，把计算属性改名为 targetHeight（目标高度），另用一个 ref height 存“正在显示的高度”，侦听目标变化时启动动画：

const BannerBar = {
  template: '#banner',
  props: ['color', 'ratio'],
  setup(props) {
    const targetHeight = Vue.computed(() => 220 * props.ratio + 40)
    const height = Vue.ref(targetHeight.value)   // 初始值 = 目标值

    let cancel
    Vue.watch(targetHeight, (newValue, oldValue) => {
      cancel?.()                                 // 上一个动画还没完？先停掉
      cancel = tween({
        from: oldValue,
        to: newValue,
        duration: 500,
        onUpdate: (v) => { height.value = Math.round(v) },
      })
    })
    Vue.onBeforeUnmount(() => cancel?.())        // 组件被销毁时清理

    return { height }
  },
}
★ 告别 const vm = this

原书在 TWEEN 的回调里不得不写 const vm = this，因为回调里的 this 指向 Tween 对象而不是组件。 组合式 API 里根本没有 this，height 就是一个闭包里的变量，这类问题自然消失了。

✓ 现成的方案

TWEEN.js 仍然可用（包名已改为 @tweenjs/tween.js）。在使用构建工具的项目中，VueUse 的 useTransition 可以一行把一个 ref “变成会平滑过渡的 ref”。另外，requestAnimationFrame 在标签页不可见时会暂停，既省电又省资源。

飘动的云

最后给天空加一些从左往右飘的云。每朵云的高度、速度都随机；越快的云离我们越“近”，用 z-index 显示在前面。 这里要用到一个新东西：模板引用，用来拿到组件根元素的真实 DOM，读它的宽度。 

const cloudAnimationDurations = {
  min: 10000, // 10 秒
  max: 50000, // 50 秒
}

const SkyCloud = {
  props: ['type'],   // 1~5，对应五种云的图片
  setup(props) {
    const root = Vue.ref(null)                 // ① 声明一个同名的 ref
    const style = Vue.reactive({ transform: 'none', zIndex: 0 })
    let cancel

    function setPosition(left, top) {
      // 用 transform 移动，性能比改 left/top 好
      style.transform = `translate(${left}px, ${top}px)`
    }

    function initPosition() {
      // 图片加载完才知道宽度：先把云藏到屏幕左边外面
      setPosition(-root.value.clientWidth, 0)
    }

    function startAnimation(delay = 0) {
      const width = root.value.clientWidth
      const { min, max } = cloudAnimationDurations
      const duration = Math.random() * (max - min) + min
      style.zIndex = Math.round(max - duration)          // 越快越靠前
      const top = Math.random() * (window.innerHeight * 0.3)

      cancel = tween({
        from: -width,
        to: window.innerWidth,
        duration,
        delay,
        easing: (t) => t,                                // 匀速
        onUpdate: (x) => setPosition(x, top),
        onComplete: () => startAnimation(Math.random() * 10000),
      })
    }

    Vue.onMounted(() => {
      // 负的延迟 = 动画“已经进行了一段时间”，开局时云就分布在天空各处
      startAnimation(-Math.random() * cloudAnimationDurations.min)
    })
    Vue.onBeforeUnmount(() => cancel?.())

    return { root, style, initPosition }
  },
  template: `<div ref="root" class="cloud" :class="'cloud-' + type" :style="style">
    <img :src="'svg/cloud' + type + '.svg'" @load="initPosition" />
  </div>`,
}

      <card-hand v-if="!state.activeOverlay" :cards="state.currentHand"
                 @card-play="handlePlayCard" @card-leave-end="handleCardLeaveEnd" />
    </transition>

    <transition name="fade">
      <div class="overlay-background" v-if="state.activeOverlay" />
    </transition>

    <transition name="zoom">
      <game-overlay v-if="state.activeOverlay" :key="state.activeOverlay" @close="handleOverlayClose">
        <component :is="'overlay-content-' + state.activeOverlay"
                   :player="state.currentPlayer" :opponent="state.currentOpponent" :players="state.players" />
      </game-overlay>
    </transition>
  </div>`,
})

// 注册所有组件
const components = {
  TopBar, GameCard, CardHand, GameOverlay,
  OverlayContentPlayerTurn, OverlayContentLastPlay, OverlayContentGameOver, PlayerResult,
  PlayerCastle, CastleBanners, StatBubble, BannerBar, SkyCloud,
}
for (const [name, def] of Object.entries(components)) {
  app.component(name, def)
}

app.mount('#app')

// 窗口尺寸变化
window.addEventListener('resize', () => {
  state.worldRatio = getWorldRatio()
})

// 开局显示“轮到你了”
state.activeOverlay = 'player-turn'

小结

主题Vue 3 写法和原书的不同
全局状态reactive({...})Vue 2 直接把对象传给 data
注册组件app.component(name, def)不再是 Vue.component
父传子props: [...]，setup(props)—
子传父emits: [...]，setup(props, { emit })建议声明 emits；$on 已移除
组件上的原生事件直接 @click（透传到根元素）.native 已移除
插槽<slot />—
动态组件<component :is>—
过渡类名v-enter-from / v-leave-from原来叫 v-enter / v-leave
列表过渡<TransitionGroup tag="div">默认不再渲染 <span>
访问 DOM模板引用 ref="root"代替 this.$el
数值动画自写 tween() / VueUse原书用 TWEEN.js + const vm = this
