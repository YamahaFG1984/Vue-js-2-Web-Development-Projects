这个系列写给“会写 Vue 语法，但面对一个新需求不知道从哪里下手”的人，尤其是后端或 Django 全栈出身的开发者。 每个项目都先摊开写设计：用户要做什么、界面要记住什么、哪些能算出来、什么操作会改变它们。 设计清楚以后，再一步步翻译成 Vue 3 代码。 后面几个项目都是业务系统里天天见的功能：购物车、搜索自动补全、注册向导、后台数据表格、客服聊天室。学完就能用上。

为什么会“无处下手”

用 Django 写页面时，思路是一条直线：这个页面需要什么数据 → 从数据库取 → 交给模板渲染。 一次请求结束，内存清空，下一次点击再从头来一遍。“状态”只有一个归宿：数据库。而数据库表结构，你早就在 Model 里设计好了。

前端应用不是这样。它是一个一直活在浏览器里的进程：用户每点一下，它就改一点自己记住的东西，界面跟着变。 像 Markdown 笔记本这种根本没有后端的应用，“从哪里取数据”这个问题直接落空，于是就不知道从哪里开始了。

好消息是：你在 Django 里练出来的能力，大部分可以直接搬过来。前端的“状态”就相当于一个住在浏览器里的小数据库； 设计状态，和设计 Model 是同一种功夫。缺的只是一个固定的“设计步骤”，把这种功夫用到前端上。下面这张对照表是整个系列的出发点：

Model 上的 @property、聚合查询派生数据：computed由状态算出来，不单独存

一句话记住

界面 = f(状态)。你只负责设计状态、写清楚每个事件怎么改它；“把状态画到屏幕上”这件事交给 Vue。 需要手动去改某个 DOM 元素的时候，通常说明设计卡里漏了一项状态。

七个项目，每个只突破一个新思维

项目按“新思维”排序，而不是按“新 API”排序。前三个故意不碰后端，堵住“先取数据再渲染”这条老路，逼自己按状态思考； 第三阶段再把你熟悉的 Django 接回来。到那时你会看到，服务器上的数据只是前端整个状态里的一层。

怎样使用这个系列

  • 前置知识：读过主教程的第 1 章和第 2 章，知道 ref、computed、v-for 是什么就够了。不熟的 API 用到时会再讲。
  • 先自己填设计卡：每篇在给出设计卡之前都会停下来。请真的拿出纸笔，花 10 分钟自己填一遍，再往下看对照。对答案的过程，才是思维真正发生变化的地方。
  • 每篇开头的 Django 对照框：把这一篇的新概念挂到你熟悉的东西上。
  • 页内演示：每篇都有可以直接操作的成品演示，旁边实时显示当前的状态和派生数据，就像 Vue DevTools。点一下按钮，看状态怎么变、界面怎么跟着变。
  • 完整代码：每个项目在仓库的 examples/design/ 下都有一个可运行的 Vite 工程。
