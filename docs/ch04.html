工程化：Vite 与单文件组件

前三章都是“一个 HTML + 几个 script 标签”的老派写法。要做更大的应用，我们需要一套正经的开发环境： 脚手架、开发服务器、构建工具，以及 Vue 最重要的文件格式 —— 单文件组件 .vue。

本章目标

  • 掌握单文件组件的三个块，尤其是 <script setup> 和 <style scoped>

所有现代前端工具都运行在 Node.js 上。去官网下载 LTS（长期支持）版本 安装即可，npm 会一起装好。 Vite 对 Node 版本有最低要求（目前是 20.19+ 或 22.12+），装最新的 LTS 就不用操心。

本教程用 npm 演示。社区里 pnpm 也很流行（更快、更省磁盘），命令几乎一一对应： npm install → pnpm install，npm run dev → pnpm dev。

代码编辑器

推荐 Visual Studio Code，并安装 Vue 官方扩展 Vue - Official（以前叫 Volar）。 它提供 .vue 文件的语法高亮、智能提示、类型检查和跳转。

Vite 为什么这么快

Vite（法语“快”，读作 /vit/）的快，来自一个关键的思路转变：开发时不打包。

ⓘ dependencies 与 devDependencies

应用运行时真正要用的包（vue、vue-router、marked……）放 dependencies，用 npm install 包名 安装； 只在开发和构建时用的工具（vite、eslint、sass……）放 devDependencies，用 npm install -D 包名 安装。 （JSON 本身不允许注释，上面的注释只是为了讲解。） 

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],   // 让 Vite 认识 .vue 文件
})

创建应用

把 src 里的东西清空，从零写一个最小的入口：

import { createApp, h } from 'vue'

createApp({
  render: () => h('div', 'hello world'),
}).mount('#app')

从这里开始，我们全面使用 ES 模块：用 import 引入别的文件或包，用 export 导出。 注意 import ... from 'vue' —— 不再是全局变量 Vue，而是从 npm 包里按需导入。

原书 · Vue 2
import Vue from 'vue'

new Vue({
  el: '#app',
  render: h => h('div', 'hello world'),
})
Vue 3
import { createApp, h } from 'vue'

createApp({
  render: () => h('div', 'hello world'),
}).mount('#app')

注意 h 的来源变了：Vue 2 里它作为参数传给 render，Vue 3 里要从 'vue' 导入。

渲染函数与虚拟 DOM

上面的 render 是什么？要回答这个问题，得先知道 Vue 是怎么更新页面的。 直接操作真实 DOM 很慢，所以 Vue 在内存里维护一棵用普通 JS 对象描述的“虚拟 DOM”树。 数据变化时，生成一棵新树，和旧树比较（diff），只把真正不同的地方应用到真实 DOM 上。

h 是 hyperscript 的缩写（“用 JS 描述 HTML”），它创建一个虚拟节点（VNode）。它接收三个参数：

  1. 类型：HTML 标签名（如 'div'）或组件对象；
  2. 属性（可选）：class、style、props、事件监听器等；
  3. 子节点（可选）：文本，或由 h() 创建的子节点数组。
render: () => h('ul', { class: 'movies' }, [
  h('li', { class: 'movie' }, 'Star Wars'),
  h('li', { class: 'movie', onClick: () => alert('好片！') }, 'Blade Runner'),
])

<ul class="movies">
  <li class="movie">Star Wars</li>
  <li class="movie">Blade Runner</li>
</ul>
ⓘ Vue 3 的 h() 属性是“扁平”的

Vue 2 里要写成 { attrs: {...}, on: { click }, props: {...} } 这种嵌套结构； Vue 3 统一扁平化：{ id: 'x', class: 'a', onClick: fn }，以 on 开头的就是事件。

绝大多数时候你都会写模板，只有在需要 JS 的全部灵活性时才手写渲染函数。第 6 章会再见到它。

✓ 不用再操心 vue-template-compiler

★ 文件名里的哈希有什么用

文件内容变了，哈希就变，文件名也就变了。于是可以让浏览器对 assets/ 里的文件永久缓存， 发布新版本时 index.html 引用的是新文件名，用户自然拿到新代码，不会被旧缓存卡住。

ⓘ 部署到子路径

如果网站不是部署在域名根目录（比如 GitHub Pages 的 https://用户名.github.io/仓库名/），要在 vite.config.js 里设置 base: '/仓库名/'，否则资源路径会 404。

环境变量与构建模式补充

真实项目几乎都有“不同环境不同配置”的需求：开发时 API 在 localhost:3000，生产环境在 https://api.example.com； 测试环境要打开调试日志，生产环境要关掉。把这些值写死在代码里，每次部署都得改代码。Vite 的做法是 .env 文件 + 构建模式。

.env 文件

VITE_APP_TITLE=我的衬衫铺

VITE_API_BASE=/api/
VITE_DEBUG=true

VITE_API_BASE=https://api.example.com/
VITE_DEBUG=false

在代码里通过 import.meta.env 读取：

const baseUrl = import.meta.env.VITE_API_BASE        // 开发时是 '/api/'，构建后是正式地址

if (import.meta.env.DEV) {                            // 内置变量：是否开发环境
  console.log('当前模式：', import.meta.env.MODE)     // 'development' / 'production' / 自定义
}
⚠ 前端没有秘密

只有以 VITE_ 开头的变量才会暴露给前端代码，这是 Vite 的保护措施。但请记住：暴露给前端的任何值，用户都能在浏览器里看到。 API 密钥、数据库密码、OAuth 客户端密钥绝不能放进 VITE_ 变量，它们只能留在服务器上。

✓ 给环境变量加上类型提示

TypeScript 项目可以在 env.d.ts 里声明 interface ImportMetaEnv { readonly VITE_API_BASE: string }，编辑器就能补全，拼错名字时会报错。

单文件组件（SFC）

现在进入本章的重点。Vue 有自己的文件格式：单文件组件（Single-File Component，扩展名 .vue）。 它把一个组件的模板、逻辑和样式放在同一个文件里，组件因此真正“自给自足”，好维护也好分享。

新建 src/Test.vue：

<script setup>
import { ref } from 'vue'

const message = ref('Hello world')
</script>

<template>
  <div>
    <p>{{ message }}</p>
    <input v-model="message">
  </div>
</template>

<style>
p {
  color: grey;
}
</style>

然后在 main.js 里导入它作为根组件：

import { createApp } from 'vue'
import Test from './Test.vue'

createApp(Test).mount('#app')
ⓘ 关于原书的 ...Test 展开写法

原书用 new Vue({ el: '#app', ...Test }) 把组件选项展开到根实例上，以免 DevTools 里多一层无用的根组件。 Vue 3 的 createApp(Test) 本身就把 Test 当作根组件，天然没有这个问题。

<template>

就是我们熟悉的模板语法，指令、插值、简写都一样：

<template>
  <ul class="movies">
    <li v-for="movie of movies" :key="movie.id" class="movie">
      {{ movie.title }}
    </li>
  </ul>
</template>
✓ Vue 3：模板可以有多个根节点

Vue 2 要求组件模板只能有一个根元素，所以经常要套一层无意义的 <div>。Vue 3 支持多根节点（称为 Fragment）。 不过要注意：多根组件不会自动透传 class 等属性，需要时用 v-bind="$attrs" 指定给某个元素。

使用 Pug

如果你喜欢更简洁的 Pug 语法，只需安装 pug（不再需要 pug-loader），然后给 template 加上 lang="pug"： 

npm install -D pug

<template lang="pug">
ul.movies
  li.movie Star Wars
  li.movie Blade Runner
</template>

<script setup>：组合式 API 的最佳拍档

这是 Vue 3 单文件组件里最重要的语法糖。在 <script setup> 里：

  • 代码就是 setup() 函数的函数体，每创建一个组件实例执行一次；
  • 顶层声明的变量、函数、导入的组件都自动暴露给模板，不用再写 return { ... }；
  • 用编译宏 defineProps、defineEmits、defineModel 声明 props、事件和 v-model（不需要 import）。
第 2、3 章的写法
export default {
  props: ['movie'],
  emits: ['select'],
  setup(props, { emit }) {
    const count = ref(0)
    function select() {
      emit('select', props.movie)
    }
    return { count, select }
  },
}
<script setup>
<script setup>
import { ref } from 'vue'

const props = defineProps(['movie'])
const emit = defineEmits(['select'])

const count = ref(0)
function select() {
  emit('select', props.movie)
}
</script>

原书的选项式 <script> 写法在 Vue 3 中同样有效：

<script>
export default {
  data() {
    return {
      movies: [
        { id: 0, title: 'Star Wars' },
        { id: 1, title: 'Blade Runner' },
      ],
    }
  },
}
</script>
★ 本教程之后的约定

从第 5 章起，所有组件都写成 <script setup> 单文件组件，块的顺序是 script → template → style （官方 create-vue 模板的顺序；先看逻辑再看结构，两种顺序 Vue 都接受）。

ⓘ TypeScript

本章末尾专门有一节讲如何在 Vue 中使用 TypeScript，包括带类型的 props、emits 和模板引用。

JSX

JSX 是一种在 JS 里写类 HTML 标记的语法，本质上是渲染函数的语法糖。 在 create-vue 里勾选“JSX 支持”（或手动安装 @vitejs/plugin-vue-jsx）后，可以这样写： 

<script lang="jsx">
import { ref } from 'vue'

export default {
  setup() {
    const movies = ref([
      { id: 0, title: 'Star Wars' },
      { id: 1, title: 'Blade Runner' },
    ])
    const itemClass = 'movie'

    // setup 返回一个函数时，它就是渲染函数
    return () => (
      <ul class="movies">
        {movies.value.map(movie =>
          <li key={movie.id} class={itemClass}>{movie.title}</li>
        )}
      </ul>
    )
  },
}
</script>

花括号 { } 里可以写任意 JS 表达式。编译后，它会变成和手写 h() 几乎一样的代码：

return () => h('ul', { class: 'movies' },
  movies.value.map(movie =>
    h('li', { key: movie.id, class: itemClass }, movie.title)
  )
)
ⓘ 模板还是 JSX？

Vue 社区绝大多数代码用模板：它更接近 HTML，而且编译器能对模板做静态优化（JSX 太灵活，很难分析）。 JSX 适合逻辑特别复杂、需要大量动态生成结构的场景。知道它存在、看得懂就够了。

<style>

一个 SFC 可以有多个 <style> 块：

<style>
.movies {
  list-style: none;
  padding: 12px;
  background: rgba(0, 0, 0, .1);
  border-radius: 3px;
}
</style>

作用域样式 scoped

加上 scoped 属性，样式就只作用于当前组件模板里的元素。你可以放心地用 .title、.movie 这种通用类名，不怕和别的组件冲突： 

<style scoped>
.movie:not(:last-child) {
  padding-bottom: 6px;
  margin-bottom: 6px;
  border-bottom: solid 1px rgba(0, 0, 0, .1);
}
</style>

原理是：编译器给组件模板里的每个元素加上一个唯一属性，同时给每条 CSS 选择器加上同样的属性选择器：

✓ scoped 的三个常用技巧
  • 修改子组件内部样式：scoped 默认管不到子组件里的元素，用 :deep(.child-class) { ... } 穿透（取代原来的 /deep/ 和 >>>）。
  • 在 CSS 里使用响应式数据（Vue 3 新增）：color: v-bind(themeColor);，数据变了样式自动更新。
  • 性能：尽量用类选择器。li { } 被加上属性选择器后，匹配效率会比 .movie { } 差很多。
<script setup>
import { ref } from 'vue'
const themeColor = ref('#42b883')
</script>

<template>
  <h1 class="title" @click="themeColor = 'tomato'">点我变色</h1>
</template>

<style scoped>
.title {
  color: v-bind(themeColor);
}
</style>

⚠ node-sass 已废弃

原书用的 node-sass 已停止维护，并且经常在新版 Node 上编译失败。请使用官方的 Dart Sass：sass 或更快的 sass-embedded。

ⓘ 原生 CSS 也越来越强了

现代浏览器已经原生支持 CSS 嵌套（.article { .title { } }）、CSS 变量、color-mix() 等。 很多新项目已经不再需要预处理器 —— 本教程这套页面的样式就是纯原生 CSS 写的。后面的项目会沿用原书的 Stylus，你也可以换成原生 CSS。

在组件里使用组件

会写单文件组件后，下一步是把它们组合起来。先写一个表示单部电影的 Movie.vue：

<script setup>
defineProps(['movie'])
</script>

<template>
  <li class="movie">
    {{ movie.title }}
  </li>
</template>

<style scoped>
.movie:not(:last-child) {
  padding-bottom: 6px;
  margin-bottom: 6px;
  border-bottom: solid 1px rgba(0, 0, 0, .1);
}
</style>

然后在 Movies.vue 里导入并使用它。在 <script setup> 里，导入的组件可以直接在模板中使用，不需要原书的 components: { Movie } 注册：

<script setup>
import { ref } from 'vue'
import Movie from './Movie.vue'

const movies = ref([
  { id: 0, title: 'Star Wars' },

在 Vue 中使用 TypeScript补充

TypeScript 给 JavaScript 加上了类型：变量是什么类型、函数接收什么参数、对象有哪些属性。编辑器据此给出补全，在你写错时立刻标红。 现在大多数 Vue 项目都使用 TypeScript，Vue 3 本身也是用 TypeScript 写的，类型支持非常完整。

ⓘ 本教程的约定

为了不给初学者增加负担，后面几章的正文仍然使用 JavaScript，并在关键处附上 TypeScript 写法的对照。 学完这一节，你就能把任何一个示例改写成 TypeScript。

带类型的 props 和 emits

用 TypeScript 时，defineProps 和 defineEmits 可以直接接收一个类型参数，不再需要运行时的选项对象：

<script setup lang="ts">
export interface Movie {
  id: number
  title: string
  year?: number          // ? 表示可选
}

// Vue 3.5+：解构 props 时可以直接写默认值，而且解构出的变量依然是响应式的
const { movie, highlighted = false } = defineProps<{
  movie: Movie
  highlighted?: boolean
}>()

const emit = defineEmits<{
  select: [id: number]               // 事件名: [参数列表]
  favorite: [id: number, on: boolean]
}>()

function onClick() {
  emit('select', movie.id)           // ✓
  // emit('select', movie.title)     // ✗ 编辑器报错：string 不能赋给 number
}
</script>

<template>
  <li class="movie" :class="{ highlighted }" @click="onClick">
    {{ movie.title }} <small v-if="movie.year">({{ movie.year }})</small>
  </li>
</template>

父组件里用错的时候，模板也会被检查：

<Movie :movie="{ id: 1, title: 'Star Wars' }" />      <!-- ✓ -->
<Movie :movie="{ id: '1' }" />                        <!-- ✗ id 应该是 number，缺少 title -->
<Movie :movie="m" @select="(id) => id.toFixed()" />   <!-- ✓ id 被推断为 number -->

🔍 泛型组件（点击展开）

一个通用的下拉选择组件，它的选项可以是任意类型 —— 而且使用时类型能被正确推断：

<script setup lang="ts" generic="T">
defineProps<{
  options: T[]
  label: (item: T) => string
}>()
const model = defineModel<T>()
</script>

<template>
  <ul>
    <li v-for="(item, i) in options" :key="i"
        :class="{ active: item === model }" @click="model = item">
      {{ label(item) }}
    </li>
  </ul>
</template>

<BaseSelect :options="movies" :label="(m) => m.title" v-model="selected" /> 中，m 自动被推断为 Movie。

✓ 渐进地引入

TypeScript 不是“全有或全无”。一个项目可以同时有 .js 和 .ts 文件、lang="ts" 和普通的 <script setup>。 可以先从最容易出错的地方（API 返回的数据结构、store、通用组件的 props）开始加类型。

项目怎么组织补充

小项目按“文件类型”分目录就够了；项目变大后，更推荐按功能（feature）组织，把一个功能相关的组件、组合式函数、store、API 放在一起：

路径别名 @

组件嵌套深了以后，import X from '../../../components/X.vue' 这种相对路径很难维护。create-vue 默认配置了别名 @ 指向 src： 

import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})

import BaseButton from '@/shared/components/BaseButton.vue'   // 不管在哪个文件里，写法都一样

自动导入：方便，但要权衡

社区插件 unplugin-auto-import 和 unplugin-vue-components 可以省去 import：在任何文件里直接用 ref、computed， 模板里直接用 components/ 下的组件，插件会在编译时自动补上导入语句（Nuxt 默认就是这样工作的）。

👍

好处

代码更短，大量重复的 import 消失了；未使用的组件依然能被摇树优化。

⚠️

代价

看代码时不知道变量从哪来；依赖编辑器和生成的类型声明文件才有提示；新人上手可能困惑。

本教程坚持显式 import，让每个名字的来源一目了然；团队可以根据习惯自行选择。
