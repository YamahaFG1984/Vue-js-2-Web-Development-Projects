客服支持中心

第一个真正意义上的单页应用（SPA）：一个虚构的 T 恤网店“我的衬衫铺”的客服中心，有常见问题页、用户注册登录、 工单列表、提交工单和工单详情。我们会学习 Vue Router 4、插件、组合式函数，以及如何把登录状态和路由结合起来。

本章目标

  • 用 Vue Router 4 搭建多页面应用：路由表、<RouterView>、<RouterLink>、两种历史模式
  • 理解 Vue 插件，自己写一个 $fetch 插件
  • 用组合式函数取代原书的 mixins，实现可复用的远程数据加载
  • 封装通用表单组件，掌握 Vue 3 的组件 v-model（defineModel）和 $attrs
  • 用导航守卫保护私有页面，处理登录跳转和会话过期
  • 嵌套路由、动态参数、404 页面、路由过渡、滚动行为、懒加载

⚠ 2017 年的服务端代码在新版 Node 上可能装不上

这个服务器依赖 Babel 6 和老版本的 bcrypt（原生模块），在新版 Node 上 npm install 很可能失败。几个办法： ① 把 bcrypt 换成纯 JS 的 bcryptjs（API 相同），把启动脚本里的 babel-node 换成原生 ES 模块； ② 用 nvm 或 Docker 跑一个老版本的 Node；③ 按上表的接口约定，用你熟悉的任何后端自己实现 —— 前端代码完全不受影响。

用 Vite 代理解决跨域

前端跑在 localhost:5173，后端在 localhost:3000，端口不同就是“跨域”，浏览器默认不允许携带 Cookie 的跨域请求。 原书让后端开 CORS；更省心的做法是让 Vite 开发服务器代理 API 请求，浏览器看到的永远是同一个源： 

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      // 所有 /api 开头的请求，转发到 3000 端口，并去掉 /api 前缀
      '/api': {
        target: 'http://localhost:3000',
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
    },
  },
})
ⓘ 上线后呢？

生产环境通常也让前端和 API 同源：用 Nginx 之类的反向代理把 /api 转给后端，或者把前端构建产物交给后端一起托管。

路由与页面

路由是代表应用某个状态（通常就是一个“页面”）的路径。每条路由关联一个 URL 模式，地址匹配时就显示对应的组件。 单页应用里，切换页面时浏览器并不会真的去加载一个新的 HTML，而是由 JS 根据 URL 换掉页面上的组件。

Vue 插件

路由功能由官方插件 Vue Router 提供。插件就是给 Vue 应用“加功能”的一段代码：注册全局组件、添加全局属性、提供依赖…… 安装插件统一用 app.use()：

原书 · Vue 2：安装到全局
import Vue from 'vue'
import VueRouter from 'vue-router'

Vue.use(VueRouter)
const router = new VueRouter({ routes })

new Vue({ router, render: h => h(App) })
Vue 3 + Vue Router 4：安装到应用
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({ history: createWebHistory(), routes })

createApp(App).use(router).mount('#app')

社区插件可以在 npm 上搜索，awesome-vue 仓库按类别整理了很多。

然后写路由表。每条路由是一个对象，至少有 path（URL 模式）和 component（要渲染的组件）：

import { createRouter, createWebHistory } from 'vue-router'
import Home from './components/Home.vue'
import FAQ from './components/FAQ.vue'

const routes = [
  { path: '/', name: 'home', component: Home },
  { path: '/faq', name: 'faq', component: FAQ },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
})

export default router
✓ 一定要给路由起名字

name 是可选的，但强烈建议使用。之后跳转时用名字而不是路径，将来改路径也不会有链接失效。

import { createApp } from 'vue'
import AppLayout from './components/AppLayout.vue'
import router from './router'

createApp(AppLayout)
  .use(router)
  .mount('#app')

现在访问 http://localhost:5173/ 和 http://localhost:5173/faq，会看到不同的页面。

激活状态的 class

当前路由对应的链接会自动获得 CSS 类，可以借此高亮：

<style lang="stylus" scoped>
@import '../style/imports';

.router-link-active
  border-bottom-color $primary-color
</style>
★ Vue Router 4 变化：不再需要 exact

原书在这里遇到一个问题：在 FAQ 页面时，“首页”链接也被高亮了，因为 Vue Router 3 按路径前缀匹配，而所有路径都以 / 开头， 于是要给首页链接加 exact 属性。Vue Router 4 改为按路由记录判断：/ 和 /faq 是两条平级的记录， 首页链接自然不会被激活。exact 属性因此被移除了；需要精确匹配的样式就用 .router-link-exact-active。

<script setup>
import { ref } from 'vue'

const questions = ref([])
const error = ref(null)

async function loadQuestions() {
  try {

    if (response.ok) {
      questions.value = await response.json()

        <p v-html="question.content"></p>

自己写一个插件：$fetch

很多组件都要请求服务器，而且都要拼接相同的基础地址、解析 JSON、检查错误。把这些封装成一个插件，给所有组件提供一个 $fetch 方法。

最简单的插件

export default {
  install(app, options) {
    console.log('已安装！', options)
  },
}

import VueFetch from './plugins/fetch'

app.use(VueFetch, {
  baseUrl: '/api/',
})

控制台会打印出选项对象。install 的第一个参数在 Vue 2 里是全局的 Vue 构造器，在 Vue 3 里是应用实例 app。

实现 $fetch

let baseUrl = ''

// 单独导出，普通 JS 文件里也能直接用
export async function $fetch(url) {
  const response = await fetch(`${baseUrl}${url}`)
  if (response.ok) {
    return await response.json()
  } else {
    throw new Error('error')
  }
}

export default {
  install(app, options) {
    baseUrl = options.baseUrl
    // ① 模板和选项式 API 里可以用 this.$fetch / $fetch
    app.config.globalProperties.$fetch = $fetch
    // ② 组合式 API 里用 inject('fetch') 取到
    app.provide('fetch', $fetch)
  },
}
原书 · Vue 2：改原型
install (Vue, options) {
  Vue.prototype.$fetch = $fetch
}
// 组件里：this.$fetch('questions')
Vue 3：globalProperties / provide
install(app, options) {
  app.config.globalProperties.$fetch = $fetch
  app.provide('fetch', $fetch)
}
// setup 里：const $fetch = inject('fetch')
✓ 其实直接 import 也行

在组合式 API 里，最简单的方式是直接 import { $fetch } from '../plugins/fetch'。插件 + provide 的好处是“可替换”： 测试时可以 provide 一个假的 fetch，或者同一个页面上两个应用用不同的 baseUrl。本章两种都会用到。

代码复用：从 mixins 到组合式函数

插件解决了“发请求”的复用，但每个页面还要重复写 loading、error、data 这一套状态。 原书在这里引入了 mixins（混入）：一个可以“混”进组件选项里的对象。Vue 3 仍然支持 mixins，但官方已经不推荐使用它， 而是推荐组合式函数（composables）。先看看为什么：

组合式函数就是一个利用组合式 API 封装有状态逻辑的普通函数，约定以 use 开头。它在内部创建 ref、computed、watch， 然后把需要的东西返回出去。

第一版 useRemoteData

import { ref } from 'vue'
import { $fetch } from '../plugins/fetch'

export function useRemoteData(url) {
  const data = ref(null)
  const error = ref(null)
  const loading = ref(false)

  async function load() {
    loading.value = true
    error.value = null
    try {
      data.value = await $fetch(url)
    } catch (e) {
      console.error(e)
      error.value = e
    } finally {
      loading.value = false
    }
  }

  load()

  return { data, error, loading, refresh: load }
}

FAQ 页面一下子变得非常简洁：

<script setup>
import { useRemoteData } from '../composables/useRemoteData'

const { data: questions, loading, error } = useRemoteData('questions')
</script>

<template>
  <main class="faq">
    <h1>常见问题</h1>
    <Loading v-if="loading" />
    <div class="error" v-else-if="error">无法加载问题列表</div>
    <section class="list" v-else>
      <article v-for="question of questions" :key="question._id">
        <h2 v-html="question.title"></h2>
        <p v-html="question.content"></p>
      </article>
    </section>
  </main>
</template>
原书 · mixin

export default {
  mixins: [
    RemoteData({ questionList: 'questions' }),
  ],
}
// 模板里：questionList、remoteDataBusy、
//        hasRemoteErrors 凭空出现
Vue 3 · 组合式函数
import { useRemoteData } from '../composables/useRemoteData'

const {
  data: questions,
  loading,
  error,
} = useRemoteData('questions')
// 每个变量的来源都写在眼前
ⓘ 原书的计数器 + 错误对象去哪了

原书的 mixin 一次加载多个资源，所以要用 remoteDataLoading 计数器、remoteErrors 对象来汇总状态。 组合式函数每调用一次只负责一个资源，需要多个资源就调用多次；要汇总时写一个 computed：const busy = computed(() => l1.value || l2.value)。 每个函数的职责更单一了。

✓ 生产项目的选择

远程数据加载是个“深坑”：缓存、去重、重试、后台刷新、分页……真实项目可以直接用 TanStack Query（Vue Query）、 Pinia Colada 或 VueUse 的 useFetch。但自己写一遍 useRemoteData 能让你真正理解它们在做什么。

通用表单组件 SmartForm

登录、注册、提交工单都是表单，它们有相同的模式：提交时调用一个异步操作，期间显示加载动画，出错时显示错误信息。 把这个模式封装成 SmartForm： 

<script setup>
import { ref } from 'vue'

const props = defineProps({
  title: {
    type: String,
    required: true,
  },
  operation: {
    type: Function,
    required: true,
  },
  valid: {
    type: Boolean,
    required: true,
  },
})

const error = ref(null)
const busy = ref(false)

async function submit() {
  if (props.valid && !busy.value) {
    error.value = null
    busy.value = true
    try {
      await props.operation()
    } catch (e) {
      error.value = e.message
    } finally {
      busy.value = false
    }
  }
}
</script>

<template>
  <form @submit.prevent="submit">
    <section class="content">
      <h2>{{ title }}</h2>
      <!-- 主要内容 -->
      <slot />
      <div class="actions">
        <!-- 操作按钮 -->
        <slot name="actions" />
      </div>
      <div class="error" v-if="error">{{ error }}</div>
    </section>

    <Transition name="fade">
      <Loading v-if="busy" class="overlay" />
    </Transition>
  </form>
</template>
  • @submit.prevent：.prevent 修饰符相当于调用 event.preventDefault()，阻止浏览器提交表单后刷新页面。
  • props 这次用对象写法，可以声明类型、是否必填、默认值。传错类型或漏传时，Vue 会在控制台警告。推荐总是用这种写法。

把它和后面的 FormInput 一起注册为全局组件：

import FormInput from './components/FormInput.vue'

export default {

    app.component('FormInput', FormInput)

}

输入框组件与组件上的 v-model

表单里会有很多结构相同的输入框，再封装一个 FormInput。关键问题是：怎么让自己写的组件支持 v-model？ 先理解 v-model 用在组件上时到底展开成了什么：

⚠ Vue 3 变化：value/input 改成了 modelValue/update:modelValue

原书里组件 v-model 默认对应 value prop 和 input 事件，自定义名称要用 model 选项。 Vue 3 改成了 modelValue prop 和 update:modelValue 事件，model 选项被移除， 改用 v-model:text="..." 这种带参数的写法来指定名字，而且一个组件可以有多个 v-model。

先按“手动挡”写一遍，理解原理：

<script setup>
import { computed } from 'vue'

const props = defineProps({
  modelValue: { required: true },
  name: { type: String },
  type: { type: String, default: 'text' },
  placeholder: { type: String },
  invalid: { type: Boolean, default: false },
})
const emit = defineEmits(['update:modelValue'])

const inputClass = computed(() => ({ invalid: props.invalid }))

function update(event) {
  emit('update:modelValue', event.currentTarget.value)
}
</script>

<template>
  <div class="row">
    <input
      class="input"
      :class="inputClass"
      :name="name"
      :type="type"
      :value="modelValue"
      :placeholder="placeholder"
      @input="update"
    >
  </div>
</template>

然后是“自动挡”—— Vue 3.4+ 的 defineModel() 宏，它返回一个 ref：读它就是读 prop，写它就会自动发出更新事件：

<script setup>
import { computed } from 'vue'

const model = defineModel({ required: true })   // 自动声明 modelValue + update:modelValue

const props = defineProps({
  name: { type: String },
  type: { type: String, default: 'text' },
  placeholder: { type: String },
  invalid: { type: Boolean, default: false },
})

const inputClass = computed(() => ({ invalid: props.invalid }))
</script>

<template>
  <div class="row">
    <!-- 直接把 model 绑定到原生 input 上 -->
    <input v-model="model" class="input" :class="inputClass"
           :name="name" :type="type" :placeholder="placeholder">
  </div>
</template>

使用方式完全一样：

<FormInput name="username" v-model="username" placeholder="用户名" />
🔍 对照：原书的“自定义 v-model”在 Vue 3 中怎么写（点击展开）

原书用 model: { prop: 'text', event: 'update' } 把 v-model 改成使用 text prop。Vue 3 用参数：

<!-- FormInput 内部 -->

</script>

这让一个组件可以同时有多个双向绑定，比如 <UserName v-model:first="a" v-model:last="b" />。

表单占满了整个宽度，想限制一下 SmartForm 内部 .content 的最大宽度。但 scoped 样式管不到子组件内部的元素：

  :deep(.content)

增强 $fetch：支持 POST 和错误信息

目前 $fetch 只能发 GET。给它加一个 options 参数，透传给浏览器的 fetch：

export async function $fetch(url, options) {
  const finalOptions = {
    headers: {
      'Content-Type': 'application/json',   // 请求体是 JSON
    },
    credentials: 'include',                 // 带上 Cookie（会话凭证）
    ...options,                             // 调用者传入的选项覆盖默认值
  }

  const response = await fetch(`${baseUrl}${url}`, finalOptions)
  if (response.ok) {
    return await response.json()
  } else {
    // 服务器总是用纯文本返回错误信息
    const message = await response.text()
    const error = new Error(message)
    error.response = response
    throw error
  }
}

原书用 Object.assign({}, defaults, options)，这里换成了等价、更易读的对象展开语法 { ...defaults, ...options }。

导航守卫：保护私有页面

有了登录系统，路由就可以分成三类：

🌐

公开路由

谁都能访问：首页、常见问题。

🔒

私有路由

只有登录用户能访问：工单相关页面。

👤

游客路由

只有未登录用户能访问：登录页（已登录还去登录页没有意义）。

路由元信息 meta

先做一个工单页面的占位组件，然后在路由的 meta 对象里标记它是私有的。meta 里可以放任何你想附加到路由上的信息：

const routes = [
  { path: '/', name: 'home', component: Home },
  { path: '/faq', name: 'faq', component: FAQ },
  { path: '/login', name: 'login', component: Login, meta: { guest: true } },
  { path: '/tickets', name: 'tickets', component: TicketsLayout, meta: { private: true } },
]

全局前置守卫 beforeEach

导航守卫是路由跳转过程中被调用的钩子函数，可以改变路由器的行为。beforeEach 在每次导航确认之前运行，可以放行、取消或重定向： 

import state from './state'

router.beforeEach((to, from) => {
  if (to.meta.private && !state.user) {
    // 重定向到登录页，并带上原本想去的地址
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  if (to.meta.guest && state.user) {
    return { name: 'home' }
  }
  // 什么都不返回 = 放行
})
原书 · Vue Router 3：必须调用 next
router.beforeEach((to, from, next) => {
  if (to.meta.private && !state.user) {
    next({ name: 'login',
      params: { wantedRoute: to.fullPath } })
    return  // 忘了 return 会调用两次 next！
  }
  next()    // 忘了调用，应用就卡住了
})
Vue Router 4：返回值即结果
router.beforeEach((to, from) => {
  if (to.meta.private && !state.user) {
    return { name: 'login',
      query: { redirect: to.fullPath } }
  }
  // 不返回 = 放行；还可以是 async 函数
})
⚠ Vue Router 4 变化：params 不能再“夹带”数据

原书把原本想去的地址放在 params.wantedRoute 里传给登录页。但 wantedRoute 并不是 /login 路径里的参数， Vue Router 4.1.4 起这种“不在路径中的 params”会被直接丢弃（并给出警告）。正确做法是放进 query： URL 会变成 /login?redirect=/tickets，刷新页面也不会丢失。

登录后跳回原页面

async function login() {
  state.user = await $fetch('login', { /* ... */ })
  // replace：替换当前历史记录，而不是新增一条
  router.replace(route.query.redirect || { name: 'home' })
}
ⓘ push 和 replace

router.push() 会在浏览器历史里新增一条记录；router.replace() 替换当前记录。登录成功后用 replace， 用户点“后退”时不会又回到登录页。

⚠ 安全提示：校验 redirect

redirect 来自 URL，任何人都能伪造。这里交给 router.replace 只会在站内跳转，相对安全； 但如果你用它做 location.href = redirect，就可能被利用成“开放重定向”漏洞。至少检查一下它是以 / 开头的站内路径。

启动时恢复登录状态

刷新页面后，state.user 又变回 null 了 —— 但服务器端的会话其实还在。服务器提供了 /user 接口返回当前用户。 我们在挂载应用之前先查询一次： 

import { createApp } from 'vue'
import AppLayout from './components/AppLayout.vue'
import router from './router'
import state from './state'
import VueFetch, { $fetch } from './plugins/fetch'
import VueState from './plugins/state'
import GlobalComponents from './global-components'

async function main() {
  // 先拿到用户信息
  try {
    state.user = await $fetch('user')
  } catch (e) {
    console.warn(e)
  }

  // 再启动应用
  createApp(AppLayout)
    .use(VueFetch, { baseUrl: '/api/' })
    .use(VueState, state)
    .use(router)
    .use(GlobalComponents)
    .mount('#app')
}

main()
✓ 为什么要先查用户再挂载

如果先挂载，路由守卫在用户信息回来之前就运行了：用户直接打开 /tickets，会被误判为未登录而跳到登录页。 注意 $fetch 的 baseUrl 是在 install 里设置的，所以这里先调用 $fetch('user') 时，可以把 let baseUrl = '/api/' 设为默认值。

ⓘ tickets?.length 是什么

会话过期

会话过一段时间会失效（这个服务器设置为 3 小时），服务器重启也会让会话丢失。这时请求私有接口会返回 403， 而页面还以为自己处于登录状态，加载动画永远转下去。最合适的处理位置是所有请求的必经之路 —— $fetch： 

import state from '../state'
import router from '../router'

export async function $fetch(url, options) {
  // ...
  const response = await fetch(`${baseUrl}${url}`, finalOptions)
  if (response.ok) {
    return await response.json()
  } else if (response.status === 403) {
    // 会话失效：登出
    state.user = null
    // 如果当前在私有页面，去登录页
    const current = router.currentRoute.value     // Vue Router 4：currentRoute 是一个 ref
    if (current.meta.private) {
      router.replace({ name: 'login', query: { redirect: current.fullPath } })
    }
    throw new Error('会话已过期，请重新登录')
  } else {
    const message = await response.text()
    const error = new Error(message)
    error.response = response
    throw error
  }
}

用 replace 而不是 push：否则用户点“后退”会再次进入私有页、再次被送回登录页，陷入循环。

⚠ Vue Router 4 变化：RouterLink 的 tag 属性被移除

原书用 <router-link tag="button"> 把链接渲染成按钮。tag 在 Vue Router 4 中被移除了。 可以像上面那样用普通按钮 + router.push；或者用 custom + 作用域插槽完全自定义渲染：

（从语义上讲，“跳到另一个页面”本来就应该是链接 <a>，用 CSS 把它做成按钮的样子通常是更好的选择。）

嵌套路由与守卫：原书的 bug 在 v4 里自动消失了

原书在这里发现了一个漏洞：登出后仍能进入工单页！因为 Vue Router 3 中 to 是目标子路由（''），它自己没有 private 标记， 标记在父路由上。原书的解决办法是检查所有匹配的路由记录：to.matched.some(r => r.meta.private)。

★ Vue Router 4：to.meta 会合并所有父级的 meta

在 Vue Router 4 中，to.meta 是从父到子所有匹配记录的 meta 合并后的结果。所以我们一开始写的 to.meta.private 对子路由同样生效，不需要改。to.matched 依然存在，需要逐层检查时仍可使用。

让 FormInput 支持多行文本

描述需要 <textarea>。让 FormInput 在 type="textarea" 时渲染 textarea —— 又见动态组件 <component :is>，它的 is 也可以是 HTML 标签名：

const element = computed(() => props.type === 'textarea' ? 'textarea' : 'input')

<component :is="element" v-model="model" class="input" :class="inputClass"
           :name="name" :type="type" :placeholder="placeholder" />

透传属性 $attrs

textarea 有 rows，input 有 maxlength、required……给每个都声明一个 prop 太繁琐了。 没有被声明为 prop 的属性会进入 $attrs，我们可以用 v-bind="$attrs" 把它们一股脑儿转给内部的输入元素： 

<script setup>
import { computed } from 'vue'

// 不要把未声明的属性自动加到根元素 div 上
defineOptions({ inheritAttrs: false })

const model = defineModel({ required: true })
const props = defineProps({
  name: { type: String },
  type: { type: String, default: 'text' },
  placeholder: { type: String },
  invalid: { type: Boolean, default: false },
})

const inputClass = computed(() => ({ invalid: props.invalid }))
const element = computed(() => props.type === 'textarea' ? 'textarea' : 'input')
</script>

<template>
  <div class="row">
    <component
      :is="element"
      v-model="model"
      class="input"
      :class="inputClass"
      :name="name"
      :type="element === 'input' ? type : undefined"
      :placeholder="placeholder"
      v-bind="$attrs"
    />
  </div>
</template>
ⓘ 和原书的两处不同
  • 原书只写了 v-bind="$attrs"，但没有关掉 inheritAttrs，于是 rows 等属性会同时出现在外层 div 和 textarea 上。
  • Vue 3 的 $attrs 还包含 class、style 和事件监听器（Vue 2 里它们是分开的 $listeners），所以透传更彻底。

备份用户输入

为了更好的体验，自动把用户正在填写的内容备份到 localStorage：浏览器崩溃、误刷新、甚至会话过期被踢到登录页，回来后内容都还在。 原书写了一个 PersistantData mixin，我们写成组合式函数： 

import { ref, watch } from 'vue'

// 一个会自动存到 localStorage 的 ref
export function usePersistentRef(key, defaultValue) {
  const saved = localStorage.getItem(key)
  const value = ref(saved !== null ? JSON.parse(saved) : defaultValue)

  watch(value, (val) => {
    localStorage.setItem(key, JSON.stringify(val))
  }, { deep: true })

  return value
}

在 NewTicket.vue 里，只需要把两个 ref('') 换掉：

import { usePersistentRef } from '../composables/usePersistentRef'

const title = usePersistentRef('NewTicket.title', '')
const description = usePersistentRef('NewTicket.description', '')
原书 · mixin（约 30 行）

// mixin 内部：用 reduce 动态生成 watch 对象，
// 再加 created 恢复、beforeDestroy 保存……
Vue 3 · 组合式函数（约 10 行）

  usePersistentRef('NewTicket.title', '')

  usePersistentRef('NewTicket.description', '')
// 就是两个 ref，用法和普通 ref 完全一样

最后一个页面是工单详情，显示某一张工单。URL 里要带上工单的 id，这就要用到动态路由匹配：路径中以冒号开头的段是参数，会出现在 route.params 里。

</RouterLink>

用 props 解耦组件和路由

Ticket 组件可以直接读 route.params.id，但那样它就和路由绑死了，没法在别处复用（比如在弹窗里显示一张工单）。 更好的做法是让组件接收一个普通的 id prop，由路由把参数“喂”给它 —— 这就是路由配置里 props: true 的作用：

props 的三种写法：

  • props: true：把所有 params 作为 props 传入；
  • props: route => ({ id: route.params.id, page: Number(route.query.page) })：函数，最灵活，可以组合静态值、转换类型、改名；
  • props: { id: 'abc' }：静态对象。

参数变化时重新加载

现在 useRemoteData 只接受固定字符串。但工单 id 会变（从一张工单点到另一张时，Vue Router 会复用同一个 Ticket 组件实例，只改 prop）， 我们需要在 id 变化时重新请求。让组合式函数也接受一个getter 函数或 ref： 

import { ref, watch, toValue } from 'vue'
import { $fetch } from '../plugins/fetch'

// url 可以是：字符串 / ref / getter 函数
export function useRemoteData(url) {
  const data = ref(null)
  const error = ref(null)
  const loading = ref(false)

  async function load(currentUrl) {
    loading.value = true
    error.value = null
    try {
      data.value = await $fetch(currentUrl)
    } catch (e) {
      console.error(e)
      error.value = e
    } finally {
      loading.value = false
    }
  }

  // toValue：统一取出“当前的值”；它依赖的响应式数据变化时，watch 会重新执行
  watch(() => toValue(url), load, { immediate: true })

  return { data, error, loading, refresh: () => load(toValue(url)) }
}

<script setup>
import { useRemoteData } from '../composables/useRemoteData'
import { formatDate } from '../utils/format'

const props = defineProps({
  id: { type: String, required: true },
})

// 传入 getter：props.id 变化时自动重新请求
const { data: ticket, loading } = useRemoteData(() => `ticket/${props.id}`)
</script>

<template>
  <div class="ticket">
    <h2>工单</h2>
    <Loading v-if="loading" />
    <div class="empty" v-else-if="!ticket">找不到这张工单。</div>
    <template v-else>
      <section class="infos">
        <div class="info">创建于 <strong>{{ formatDate(ticket.date) }}</strong></div>
        <div class="info">作者 <strong>{{ ticket.user.username }}</strong></div>
        <div class="info">状态 <span class="badge">{{ ticket.status }}</span></div>
      </section>
      <section class="content">
        <h3>{{ ticket.title }}</h3>
        <p>{{ ticket.description }}</p>
      </section>
    </template>
  </div>
</template>

这对应原书在 mixin 里用 this.$watch(fn, ..., { immediate: true }) 支持动态路径的做法。

🔍 进阶：竞态条件（点击展开）

用户快速从工单 A 点到工单 B：A 的请求还没回来，B 的请求已经发出。如果 A 的响应后到，页面上就会显示 A 的内容 —— 这叫竞态条件。 Vue 3.5 的 onWatcherCleanup 配合 AbortController 可以在 id 变化时取消旧请求： 

import { watch, onWatcherCleanup } from 'vue'

watch(() => toValue(url), async (currentUrl) => {
  const controller = new AbortController()
  onWatcherCleanup(() => controller.abort())   // 下次触发前先取消上一次
  data.value = await $fetch(currentUrl, { signal: controller.signal })
}, { immediate: true })

这正是 TanStack Query 这类库替你处理掉的细节之一。

⚠ Vue Router 4 变化：不再支持 path: '*'

原书的 { path: '*' } 在 Vue Router 4 中会报错，必须写成带自定义正则的参数 '/:pathMatch(.*)*'。因为路由会按具体程度自动排序，它放在哪里都行。

路由过渡动画

原书直接把 <router-view> 包在 <transition> 里。Vue Router 4 中 <RouterView> 不能再直接被 <Transition> 包裹， 而是通过作用域插槽把当前组件交给你，你自己用 <component :is> 渲染： 

<RouterView v-slot="{ Component }">
  <Transition name="fade" mode="out-in">
    <component :is="Component" />
  </Transition>
</RouterView>

mode="out-in" 表示先让旧页面离开、再让新页面进入，避免两个页面同时出现挤在一起。

✓ 这个插槽还能做更多事

同样的模式可以包一层 <KeepAlive> 来缓存页面状态，或者根据 route.meta.transition 给不同页面设置不同的过渡效果。

滚动行为

切换路由时，可以控制页面滚动位置：回到顶部、跳到锚点，或者在用户点“后退”时恢复之前的位置。

const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) {
      return savedPosition            // 前进/后退：恢复之前的位置
    }
    if (to.hash) {
      return { el: to.hash }          // 有锚点：滚到对应元素
    }
    return { top: 0 }                 // 其他：回到顶部
  },
})
ⓘ 返回值的格式变了

原书返回 { x: 0, y: 0 } 和 { selector: '#foo' }；Vue Router 4 对齐了浏览器原生的 scrollTo，改为 { left, top } 和 { el: '#foo' }，还可以加 behavior: 'smooth'。

路由懒加载

原书没有提到，但对真实项目非常重要：把 component 写成一个返回 import() 的函数，这个页面就会被打包成单独的文件， 第一次访问时才下载。用户打开首页时，不需要下载工单页的代码： 

const routes = [
  { path: '/', name: 'home', component: Home },                       // 首页：直接导入
  { path: '/faq', name: 'faq', component: () => import('./components/FAQ.vue') },
  {
    path: '/tickets',
    component: () => import('./components/TicketsLayout.vue'),
    meta: { private: true },
    children: [ /* 子路由也可以懒加载 */ ],
  },
]

最终的路由配置

import { createRouter, createWebHistory } from 'vue-router'
import state from './state'
import Home from './components/Home.vue'

const routes = [
  { path: '/', name: 'home', component: Home },
  { path: '/faq', name: 'faq', component: () => import('./components/FAQ.vue') },
  { path: '/login', name: 'login', component: () => import('./components/Login.vue'), meta: { guest: true } },
  {
    path: '/tickets',
    component: () => import('./components/TicketsLayout.vue'),
    meta: { private: true },
    children: [
      { path: '', name: 'tickets', component: () => import('./components/Tickets.vue') },
      { path: 'new', name: 'new-ticket', component: () => import('./components/NewTicket.vue') },
      { path: ':id', name: 'ticket', component: () => import('./components/Ticket.vue'), props: true },
    ],
  },
  { path: '/:pathMatch(.*)*', name: 'not-found', component: () => import('./components/NotFound.vue') },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition
    if (to.hash) return { el: to.hash }
    return { top: 0 }
  },
})

router.beforeEach((to) => {
  if (to.meta.private && !state.user) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  if (to.meta.guest && state.user) {
    return { name: 'home' }
  }
})

export default router
