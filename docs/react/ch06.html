地理定位博客

一个以地图为中心的博客：用户用 Google 账号登录，在地图上点一下就能在那个位置发帖，点击标记查看帖子和评论。 这一章的主角是全局状态管理 —— 我们用轻量的 Zustand 管理用户、地图和帖子三个 store； 还会学习 OAuth 弹窗登录、用 react-leaflet 集成地图、render props 与 Hook 的取舍，以及乐观更新。

本章目标

  • 理解 Context 的局限，掌握 Zustand 的 store、selector 和 action
  • 在组件之外（请求层、路由）读写 store
  • 用 OAuth 弹窗 + postMessage 实现第三方登录
  • 用 react-leaflet 声明式地使用地图，理解它“哪些属性只在初始化时生效”
  • 写一个 render props 组件，再改写成自定义 Hook，比较两者
  • 处理请求竞态，实现评论的乐观更新
  • 用 Zustand 的 persist 中间件记住地图位置补充
  • 用 useSyncExternalStore 写 useMediaQuery，小屏幕上改用原生 <dialog> 弹窗补充
  • 帖子很多时：拆分订阅、memo、保持对象引用稳定、标记聚合补充

为什么需要状态管理库

上一章用 Context 共享了当前用户。这个项目里，共享的东西多得多：用户、地图中心、用户位置、帖子列表、草稿、选中的帖子……而且很多组件既要读又要改。 只用 Context 会遇到两个问题：

React 生态里常见的状态管理库：

库特点适合
Zustand极简：一个函数创建 store，无需 Provider，按 selector 订阅大多数中小型应用（本章使用）
Redux ToolkitRedux 的官方现代写法，结构严格，生态和调试工具最完善大型团队、需要严格约定的项目
Jotai“原子”式：很多个小状态自由组合状态零散、相互派生较多的场景
TanStack Query专门管理服务器数据（上一章用过）和以上任何一个搭配使用
ⓘ 不是每个项目都需要

原型、小组件、页面不多的应用，useState + 少量 Context 就够了。当很多组件开始共享复杂的状态和逻辑时，再引入状态管理库。

Zustand 入门

创建 store

import { create } from 'zustand'

// create 接收一个函数，返回一个 Hook：useUserStore
export const useUserStore = create((set, get) => ({
  // 状态
  user: null,

  // action：直接写在 store 里的函数
  login: (user) => set({ user }),     // set 会把对象“合并”进状态
  logout: () => set({ user: null }),
}))

在组件中使用：selector

// 只订阅 user：只有 user 变了，这个组件才会重新渲染
const user = useUserStore((s) => s.user)

// action 在 store 里是固定不变的函数，选取它不会导致额外渲染
const logout = useUserStore((s) => s.logout)
⚠ selector 不要返回新对象

useUserStore((s) => ({ user: s.user, logout: s.logout })) 每次都返回一个新对象，Zustand 用 Object.is 比较会认为“变了”，导致无限重新渲染。 要么分开写多个 selector，要么用 Zustand 提供的 useShallow 做浅比较： const { user, logout } = useUserStore(useShallow((s) => ({ user: s.user, logout: s.logout })))。

派生数据：写成 selector 函数

// 和 store 放在同一个文件里导出

// 组件里

弹窗 + postMessage

import { useEffect } from 'react'
import { useUserStore } from '../stores/user.js'

const SERVER_ORIGIN = 'http://localhost:3000'

export default function Login() {
  const login = useUserStore((s) => s.login)

  useEffect(() => {
    function handleMessage({ data, origin }) {
      if (origin !== SERVER_ORIGIN) return       // 安全：只接受来自我们服务器的消息
      if (data === 'success') login()
    }
    window.addEventListener('message', handleMessage)
    return () => window.removeEventListener('message', handleMessage)
  }, [login])

  function openGoogleSignin() {
    window.open(`${SERVER_ORIGIN}/auth/google`, 'google_login', 'width=500,height=600')
  }

  return (
    <div className="welcome">
      <h1>欢迎</h1>
      <div className="actions">
        <button onClick={openGoogleSignin}>使用 Google 登录</button>
      </div>
    </div>
  )
}
⚠ 永远检查 postMessage 的 origin

任何网页都能向你的窗口发送消息。不检查 origin，恶意页面就能伪造“登录成功”之类的消息。

完整的用户 store：在组件之外使用

import { create } from 'zustand'
import { $fetch } from '../api.js'
import { router } from '../router.jsx'
import { usePostsStore } from './posts.js'

export const useUserStore = create((set, get) => ({
  user: null,

  // 应用启动时调用：只检查是否已有会话
  async init() {
    try {
      set({ user: await $fetch('user') })
    } catch (e) {
      console.warn(e)
    }
  },

  // 弹窗登录成功后调用：获取用户，并跳回原本想去的页面
  async login() {
    try {
      const user = await $fetch('user')
      set({ user })
      if (user) {
        const redirect = new URLSearchParams(location.search).get('redirect')
        router.navigate(redirect || '/', { replace: true })   // 数据路由可以在组件外导航
        usePostsStore.getState().onLoggedIn()                  // 调用另一个 store 的 action
      }
    } catch (e) {
      console.warn(e)
    }
  },

  logout() {
    set({ user: null })
    $fetch('logout')
    usePostsStore.getState().reset()
  },
}))

声明式封装背后的命令式库

⚠ MapContainer 的属性是“非受控”的

为了性能，MapContainer 的 center、zoom 等属性只在创建地图时使用，之后改变它们不会有任何效果。 要在程序里移动地图（比如“回到我的位置”按钮），需要在地图内部的子组件里用 useMap() 拿到 Leaflet 实例，命令式地调用 map.setView()。

地图 store

import { create } from 'zustand'
import { usePostsStore } from './posts.js'

export const useMapStore = create((set, get) => ({
  // 只存普通的 { lat, lng }，不存 Leaflet 的类实例
  center: { lat: 48.8538302, lng: 2.2982161 },
  zoom: 15,
  userPosition: null,

  setView: (center, zoom) => set({ center, zoom }),

  setUserPosition(position) {
    const first = !get().userPosition
    set({ userPosition: position })
    if (first) get().centerOnUser()       // 第一次拿到位置时自动居中
  },

  centerOnUser() {
    const pos = get().userPosition
    if (pos) set({ center: { ...pos } })
  },

  // 地图移动结束：让帖子 store 加载可见范围内的帖子
  setBounds: (bounds) => usePostsStore.getState().fetchPosts({ mapBounds: bounds }),
}))

Zustand 中间件：记住地图位置补充

每次刷新页面，地图都回到埃菲尔铁塔。如果能回到用户上次看的位置和缩放级别就好了。 Zustand 的中间件可以包在 store 的创建函数外面，给它加上额外的能力，最常用的就是 persist： 

import { create } from 'zustand'
import { persist, devtools } from 'zustand/middleware'

export const useMapStore = create(
  devtools(                                   // 在 Redux DevTools 扩展里查看每一次状态变化
    persist(
      (set, get) => ({
        center: { lat: 48.8538302, lng: 2.2982161 },
        zoom: 15,
        userPosition: null,
        // ……action 和原来完全一样……
      }),
      {
        name: 'blog-map',                                         // localStorage 里的 key
        partialize: (s) => ({ center: s.center, zoom: s.zoom }),  // 只保存这两个字段
        version: 1,                                               // 将来数据结构变了，用 migrate 升级旧数据
      },
    ),
    { name: 'map' },
  ),
)

因为 localStorage 是同步读取的，BlogMap 里 useMapStore.getState().center 拿到的已经是恢复后的值，地图一出现就在上次的位置。 注意 setUserPosition 第一次定位时会自动居中，会覆盖恢复的位置，可以根据需要去掉这个行为。

ⓘ 中间件是怎么工作的

中间件就是一个“接收 store 创建函数、返回新的创建函数”的函数。persist 在里面包装了 set：先调用原来的 set，再把选中的字段写进存储。 多个中间件可以层层嵌套，devtools 一般放在最外层。用户、登录状态这类数据则不要持久化到 localStorage —— 它们应该以服务器为准。

地图组件

import { useEffect } from 'react'
import { MapContainer, TileLayer, Marker, useMap, useMapEvents } from 'react-leaflet'
import L from 'leaflet'
import { useMapStore } from '../stores/map.js'
import { usePostsStore, selectCurrentPost } from '../stores/posts.js'

const toLatLng = ({ lat, lng }) => ({ lat, lng })
const toBounds = (b) => ({ ne: toLatLng(b.getNorthEast()), sw: toLatLng(b.getSouthWest()) })

// 用 Material Icons 做图标（也避开了 Leaflet 默认图标在打包工具里的路径问题）
const icon = (name, cls = '') => L.divIcon({
  className: `map-marker ${cls}`,
  html: `<i class="material-icons">${name}</i>`,
  iconSize: [32, 32],
  iconAnchor: [16, 32],
})

// 地图事件 → store（这个组件不渲染任何东西，只负责“接线”）
function MapEvents() {
  const setView = useMapStore((s) => s.setView)
  const setBounds = useMapStore((s) => s.setBounds)
  const setUserPosition = useMapStore((s) => s.setUserPosition)
  const setDraftLocation = usePostsStore((s) => s.setDraftLocation)

  const map = useMapEvents({
    click: (e) => setDraftLocation({ position: toLatLng(e.latlng) }),
    moveend: () => {
      setView(toLatLng(map.getCenter()), map.getZoom())
      setBounds(toBounds(map.getBounds()))
    },
    locationfound: (e) => setUserPosition(toLatLng(e.latlng)),
  })

  useEffect(() => {
    map.locate({ watch: true })               // 浏览器会请求定位权限
    setBounds(toBounds(map.getBounds()))      // 首次加载帖子
    return () => map.stopLocate()
  }, [map, setBounds])

  return null
}

// store → 地图：center 变了就移动地图
function SyncCenter() {
  const map = useMap()
  const center = useMapStore((s) => s.center)
  useEffect(() => {
    const cur = map.getCenter()
    if (cur.lat !== center.lat || cur.lng !== center.lng) map.setView(center)   // 避免和 moveend 互相触发
  }, [map, center])
  return null
}

export default function BlogMap() {
  const initialCenter = useMapStore.getState().center    // 只用作初始值
  const zoom = useMapStore.getState().zoom
  const posts = usePostsStore((s) => s.posts)
  const draft = usePostsStore((s) => s.draft)
  const currentPost = usePostsStore(selectCurrentPost)
  const selectPost = usePostsStore((s) => s.selectPost)

  return (
    <MapContainer className="blog-map" center={initialCenter} zoom={zoom} zoomControl={false}>
      <TileLayer
        url="https://tile.openstreetmap.org/{z}/{x}/{y}.png"
        attribution="&copy; OpenStreetMap contributors"
        maxZoom={19}
      />
      <MapEvents />
      <SyncCenter />

      {posts.map((post) => (
        <Marker
          key={post._id}
          position={post.position}
          icon={icon('face', post._id === currentPost?._id ? 'selected' : '')}

帖子 store

import { create } from 'zustand'
import { $fetch } from '../api.js'
import { useUserStore } from './user.js'

let fetchPostsUid = 0

const sameBounds = (a, b) => a && b &&
  a.ne.lat === b.ne.lat && a.ne.lng === b.ne.lng && a.sw.lat === b.sw.lat && a.sw.lng === b.sw.lng

export const usePostsStore = create((set, get) => ({
  draft: null,                 // 正在创建的帖子
  mapBounds: null,             // 上次加载的地图范围
  posts: [],                   // 范围内的帖子
  selectedPostId: null,
  selectedPostDetails: null,   // 选中帖子的详情（含评论）

  // ---------- 草稿 ----------
  clearDraft: () => set({ draft: null }),

  setDraftLocation({ position, placeId = null }) {
    const draft = get().draft ?? { title: '', content: '' }
    set({ draft: { ...draft, position, placeId } })     // 不可变更新
  },

  updateDraft: (changes) => set((s) => ({ draft: { ...s.draft, ...changes } })),

  async createPost() {
    const result = await $fetch('posts/new', {
      method: 'POST',
      body: JSON.stringify(get().draft),
    })
    set((s) => ({ draft: null, posts: [...s.posts, result] }))
    get().selectPost(result._id)
  },

  // ---------- 加载帖子（防竞态） ----------
  async fetchPosts({ mapBounds, force = false }) {
    if (!force && sameBounds(get().mapBounds, mapBounds)) return
    const requestId = ++fetchPostsUid
    const query = new URLSearchParams({
      ne: `${mapBounds.ne.lat},${mapBounds.ne.lng}`,
      sw: `${mapBounds.sw.lat},${mapBounds.sw.lng}`,
    })
    const posts = await $fetch(`posts?${query}`)
    if (requestId === fetchPostsUid) {      // 期间又发起了新请求？那这个结果已过期
      set({ posts, mapBounds })
    }
  },

  // ---------- 选中 ----------
  async selectPost(id) {
    set({ selectedPostId: id, selectedPostDetails: null })
    const details = await $fetch(`posts/${id}`)
    if (get().selectedPostId === id) set({ selectedPostDetails: details })
  },

  unselectPost: () => set({ selectedPostId: null }),

  // ---------- 登录 / 登出 ----------
  reset: () => set({ posts: [], mapBounds: null, selectedPostDetails: null }),

  onLoggedIn() {
    const { mapBounds, selectedPostId } = get()
    if (mapBounds) get().fetchPosts({ mapBounds, force: true })
    if (selectedPostId) get().selectPost(selectedPostId)
  },
}))

// ---------- 派生数据 ----------
export const selectSelectedPost = (s) => s.posts.find((p) => p._id === s.selectedPostId)
export const selectCurrentPost = (s) => s.draft || selectSelectedPost(s)   // 草稿优先
ⓘ set 的两种写法

set({ draft: null })：直接给出要合并的新值。set((s) => ({ posts: [...s.posts, x] }))：基于当前状态计算，适合依赖旧值的更新。 和 React 的状态一样，Zustand 里也要做不可变更新（嫌麻烦可以用 Zustand 的 immer 中间件）。

      <input name="title" value={draft.title} placeholder="标题" required
             onChange={(e) => updateDraft({ title: e.target.value })} />
      <textarea name="content" value={draft.content} placeholder="内容" required
                onChange={(e) => updateDraft({ content: e.target.value })} />
      <div className="actions">
        <button type="button" className="secondary" onClick={clearDraft}>
          <i className="material-icons">delete</i> 丢弃
        </button>
        <button type="submit" disabled={!formValid}>
          <i className="material-icons">save</i> 发布
        </button>
      </div>
    </form>
  )
}

输入框直接受控于 store 里的草稿：用户输入 → updateDraft → store 更新 → 所有用到草稿的组件刷新。地图上草稿标记的位置和这里的表单，读的是同一份数据。

小屏幕上用弹窗显示内容补充

在手机上，地图和右侧面板并排放不下。常见的做法是：宽屏时面板固定在右侧；窄屏时地图占满屏幕，有内容要显示时弹出一个对话框。 CSS 媒体查询能改变布局，但这里连渲染的结构都不一样（一个是普通 div，一个是对话框），所以 JavaScript 也要知道当前屏幕宽度。

useMediaQuery：订阅浏览器的外部状态

屏幕宽度是浏览器里的“外部状态”，不归 React 管。React 专门为订阅这类外部数据源提供了 useSyncExternalStore： 告诉它怎么订阅变化和怎么读取当前值，它保证组件始终拿到一致的最新值（Zustand 内部也是用它实现的）。 

import { useCallback, useSyncExternalStore } from 'react'

export function useMediaQuery(query) {
  const subscribe = useCallback((onChange) => {
    const mql = matchMedia(query)
    mql.addEventListener('change', onChange)        // 跨过断点时通知 React
    return () => mql.removeEventListener('change', onChange)
  }, [query])

  return useSyncExternalStore(
    subscribe,
    () => matchMedia(query).matches,   // 读取当前值
    () => false,                       // 服务端渲染时的值（没有窗口）
  )
}

原生 <dialog> 弹窗

浏览器自带的 <dialog> 调用 showModal() 后会显示在页面最顶层，自带半透明背景（::backdrop）、按 Esc 关闭、把焦点限制在对话框内。 我们只需要把 React 的 open 状态同步给它： 

import { useEffect, useRef } from 'react'

export default function Modal({ open, onClose, children }) {
  const ref = useRef(null)

  useEffect(() => {
    const dialog = ref.current
    if (open && !dialog.open) dialog.showModal()
    else if (!open && dialog.open) dialog.close()
  }, [open])

  return (
    <dialog ref={ref} className="content-dialog"
            onClose={onClose}                                       // Esc 或 close() 都会触发
            onClick={(e) => e.target === ref.current && onClose()}>  {/* 点在背景上 */}
      {children}
    </dialog>
  )
}

地点信息：render props 与 Hook

面板顶部要显示帖子所在位置的地名和地址（“坐标 → 地址”叫反向地理编码，这里用 OpenStreetMap 的 Nominatim 服务）。 我们希望“获取地址”的逻辑和“怎么显示”分开，以便在不同地方以不同样式复用。React 里有两种做法。

做法一：render props

render props 是指：组件的 children（或某个 prop）是一个函数，组件把自己的数据作为参数传给它，由它决定渲染什么：

import { useState, useEffect } from 'react'

export default function ReverseGeocode({ position, children }) {
  const [result, setResult] = useState(null)
  const [loading, setLoading] = useState(false)

  useEffect(() => {
    const controller = new AbortController()       // 位置变了：取消上一次请求
    setLoading(true)
    setResult(null)
    const params = new URLSearchParams({
      format: 'jsonv2', lat: position.lat, lon: position.lng, 'accept-language': 'zh-CN',
    })
    fetch(`https://nominatim.openstreetmap.org/reverse?${params}`, { signal: controller.signal })
      .then((r) => r.json())
      .then(setResult)
      .catch((e) => { if (e.name !== 'AbortError') console.error(e) })
      .finally(() => { if (!controller.signal.aborted) setLoading(false) })
    return () => controller.abort()
  }, [position.lat, position.lng])

  return children({ result, loading })    // 自己不渲染任何外观，全部交给调用者
}

<ReverseGeocode position={post.position}>
  {({ result, loading }) =>
    loading ? <div className="hint">正在查询地址……</div>
    : result && <PlaceDetails name={result.name || '未命名地点'} address={result.display_name} />
  }
</ReverseGeocode>

做法二：自定义 Hook（更常用）

同样的逻辑写成 Hook，使用起来更直接，也不会产生额外的嵌套层级：

import { useState, useEffect } from 'react'

export function useReverseGeocode(position) {
  const [result, setResult] = useState(null)
  const [loading, setLoading] = useState(false)
  useEffect(() => {
    if (!position) return
    // ……和上面完全相同的请求逻辑……
  }, [position?.lat, position?.lng])
  return { result, loading }
}

★ Hook 出现后，render props 用得少了

在 Hooks 出现之前（2019 年），render props 和“高阶组件”是 React 复用有状态逻辑的主要手段，代价是组件层层嵌套。 现在复用逻辑首选自定义 Hook；render props 仍然有用，主要在需要让调用者控制某一小块渲染内容的场景，比如列表组件的 renderItem={(item) => …}。

ⓘ 注意 Hook 的调用位置

LocationInfo 里，useReverseGeocode 必须在 if (!position) return null 之前调用 —— Hooks 不能放在条件分支之后。 所以我们让 Hook 自己处理“position 为空”的情况。

发送评论时，如果等服务器返回再显示，用户会感到明显的延迟。乐观更新的做法是：先假设请求会成功，立即把评论显示出来，再在后台发请求。 React 19 专门提供了 useOptimistic： 

async sendComment(content) {
  const post = get().selectedPostDetails
  const user = useUserStore.getState().user
  await $fetch(`posts/${post._id}/comment`, {
    method: 'POST',
    body: JSON.stringify({ content }),
  })
  // 成功后再写入真实状态
  const comment = { content, date: new Date().toISOString(), user_id: user._id, author: user }
  set((s) => ({
    selectedPostDetails: { ...s.selectedPostDetails, comments: [...s.selectedPostDetails.comments, comment] },
  }))
},

import { useState, useOptimistic, startTransition } from 'react'
import { usePostsStore } from '../../stores/posts.js'
import { useUserStore } from '../../stores/user.js'
import { formatDate } from '../../utils/format.js'
import Comment from './Comment.jsx'
import Loading from '../Loading.jsx'

export default function PostContent() {
  const details = usePostsStore((s) => s.selectedPostDetails)
  const sendComment = usePostsStore((s) => s.sendComment)
  const unselectPost = usePostsStore((s) => s.unselectPost)
  const user = useUserStore((s) => s.user)
  const [text, setText] = useState('')

  // 乐观的评论列表：真实列表 + 正在发送的评论
  const [comments, addOptimistic] = useOptimistic(
    details?.comments ?? [],
    (current, newComment) => [...current, newComment],
  )

  function submitComment() {
    const content = text.trim()
    if (!content) return
    setText('')
    startTransition(async () => {
      addOptimistic({ content, date: new Date().toISOString(), author: user, pending: true })
      try {
        await sendComment(content)
      } catch {
        alert('评论发送失败')     // 乐观的那条会自动消失
      }
    })
  }

  if (!details) return <Loading />

  return (
    <div className="post-content">
      <div className="title">
        <img src={details.author.profile.photos[0].value} />
        <span>
          <span>{details.title}</span>
          <span className="info">
            <span className="name">{details.author.profile.displayName}</span>
            <span className="date">{formatDate(details.date)}</span>
          </span>
        </span>
      </div>
      <div className="content">{details.content}</div>

      <div className="comments">
        {comments.map((c, i) => (
          <div key={i} style={{ opacity: c.pending ? 0.5 : 1 }}>
            <Comment comment={c} />
          </div>
        ))}
      </div>

      <div className="actions">
        <button type="button" className="icon-button secondary" onClick={unselectPost}>
          <i className="material-icons">close</i>
        </button>
        <input value={text} placeholder="写一条评论" onChange={(e) => setText(e.target.value)}
               onKeyDown={(e) => e.key === 'Enter' && submitComment()} />
        <button type="button" className="icon-button" disabled={!text.trim()} onClick={submitComment}>
          <i className="material-icons">send</i>
        </button>
      </div>
    </div>
  )
}
ⓘ startTransition 是什么

useOptimistic 的乐观值只在一个“过渡（Transition）”进行期间有效。把异步操作包进 startTransition(async () => …)， React 就知道“这段时间要显示乐观值，结束后回到真实状态”。表单的 action 本身就运行在过渡中，所以在第 5 章那种表单 Action 里可以直接调用乐观更新函数。

帖子很多时：渲染性能补充

热门地区可能有上千个帖子。现在的 BlogMap 同时订阅了 posts、draft 和 currentPost： 用户在草稿标题里每打一个字，draft 就变一次，BlogMap 重新渲染，上千个 <Marker> 跟着重新渲染， 而且每个都拿到了新的 eventHandlers 对象和新的图标，react-leaflet 只好逐个更新 Leaflet 标记。输入开始卡顿。

第一步：拆分订阅，让 memo 生效

import { memo, useMemo } from 'react'

// 图标只创建一次，而不是每次渲染都 new 一个
const icons = { normal: icon('face'), selected: icon('face', 'selected'), draft: icon('add_circle', 'draft') }

const PostMarker = memo(function PostMarker({ post, selected }) {
  const selectPost = usePostsStore((s) => s.selectPost)          // store 里的函数引用永远不变
  const handlers = useMemo(() => ({ click: () => selectPost(post._id) }), [post._id, selectPost])
  return <Marker position={post.position} icon={selected ? icons.selected : icons.normal} eventHandlers={handlers} />
})

function PostMarkers() {
  const posts = usePostsStore((s) => s.posts)                     // 只订阅需要的数据
  const selectedId = usePostsStore((s) => s.selectedPostId)
  return posts.map((p) => <PostMarker key={p._id} post={p} selected={p._id === selectedId} />)
}

function DraftMarker() {
  const position = usePostsStore((s) => s.draft?.position)       // 改标题不会改变 position 的引用
  return position ? <Marker position={position} icon={icons.draft} opacity={0.75} interactive={false} /> : null
}

// BlogMap 里：<PostMarkers /> <DraftMarker />，自己不再订阅 posts 和 draft

现在输入草稿时，只有 DraftMarker 的 selector 被重新计算；它返回的 position 没变，连它也不会重新渲染。 切换选中的帖子时，PostMarkers 重新渲染，但 memo 让 props 没变的 998 个 PostMarker 直接跳过，只有新旧两个选中的标记更新。

第二步：重新加载时保持对象引用

拖动地图会重新请求帖子。服务器每次返回的都是全新的对象，哪怕内容一模一样，memo 的浅比较也会认为 post 变了。 可以在存进 store 时复用内容没变的旧对象： 

// 内容没变的帖子沿用旧对象，memo 就能继续生效
function reuseUnchanged(oldList, newList) {
  const old = new Map(oldList.map((p) => [p._id, p]))
  return newList.map((p) => {
    const prev = old.get(p._id)
    return prev && JSON.stringify(prev) === JSON.stringify(p) ? prev : p
  })
}

// fetchPosts 里：
if (requestId === fetchPostsUid) set((s) => ({ posts: reuseUnchanged(s.posts, posts), mapBounds }))

TanStack Query 默认就会这样做（它叫 structural sharing），这也是服务器数据交给它管理的好处之一。
