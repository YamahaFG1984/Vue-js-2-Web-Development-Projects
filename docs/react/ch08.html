Meteor 实时仪表盘

最后一个项目换一套全栈技术栈：Meteor。我们做一个监控产品生产情况的实时仪表盘 —— 在一个窗口里录入数据，另一个窗口里的图表会立刻跟着变化，而我们几乎不用写任何网络通信代码。 React 是 Meteor 支持最好的前端库之一，集成非常自然。

本章目标

  • 了解 Meteor 的架构：Minimongo、DDP、MongoDB 和“全栈响应式”
  • 用 Meteor 3 创建 React 项目，理解 Meteor 的目录约定
  • 用集合存数据，用方法修改数据并获得乐观更新
  • 用 useSubscribe 和 useFind 把实时数据接入 React 组件
  • 自己用 SVG 画一个半圆进度仪表

我们要做什么

Meteor 是什么

Meteor 是一个全栈 JavaScript 框架，它把前端、后端、数据库和两者之间的通信打包成一个整体：

  • 客户端：可以用 React、Vue、Svelte 等任何前端库，内置一个客户端数据库 Minimongo；
  • 服务器：基于 Node.js；
  • 数据库：MongoDB；
  • 通信被抽象掉了：客户端和服务器之间通过 WebSocket 上的 DDP 协议自动同步数据；
  • 还有命令行工具、构建系统、混合移动应用打包等。

整个栈都是响应式和实时的：一个客户端修改了数据，所有其他客户端都会收到新数据，界面自动更新。

ⓘ Meteor 3

Meteor 3（2024 年发布）移除了基于 Fibers 的同步写法，全面改用 async/await，并支持最新的 Node.js LTS： insert 变成 insertAsync、Meteor.call 变成 Meteor.callAsync。前端构建也支持接入现代打包工具，具体以 meteor create 生成的项目为准。

集合与方法

集合（Collection）

Meteor 集合是一个响应式的文档列表：在服务器上读写 MongoDB，在客户端读写 Minimongo 中的缓存副本。

方法（Method）与乐观更新

Meteor 方法在客户端调用时，会同时在客户端（操作 Minimongo，作为“模拟”）和服务器（操作 MongoDB，作为权威结果）执行。 客户端那份让界面瞬间更新，服务器完成后如果结果不同会自动纠正 —— 这就是 Meteor 内置的乐观更新。 

import { Meteor } from 'meteor/meteor'
import { Mongo } from 'meteor/mongo'
import { check } from 'meteor/check'

export const Measures = new Mongo.Collection('measures')

Meteor.methods({
  async 'measure.add'(measure) {
    // 方法可以被任何客户端调用：永远要校验参数
    check(measure, { value: Number, error: Boolean })
    await Measures.insertAsync({ ...measure, date: new Date() })
  },
})
⚠ 一定要校验方法参数

任何人都可以在浏览器控制台里调用 Meteor.callAsync('measure.add', { 随便什么 })。不校验的话，别人能往你的数据库里写入任意字段。

生成测量数据

import { Meteor } from 'meteor/meteor'

export default function ProductionGenerator() {
  async function generateMeasure(error) {
    const value = Math.round(Math.random() * 100)
    await Meteor.callAsync('measure.add', { value, error })
  }

  return (
    <div className="production-generator">
      <h1>生成测量数据</h1>
      <section className="actions">
        <button onClick={() => generateMeasure(false)}>生成测量值</button>
        <button onClick={() => generateMeasure(true)}>生成错误</button>
      </section>
    </div>
  )
}

在另一个终端运行 meteor mongo，输入 db.measures.find({})，可以看到点击按钮后写入的文档。

发布与订阅

数据在服务器的 MongoDB 里，客户端怎么拿到？服务器发布一个查询，客户端订阅它。订阅之后，查询结果会被同步到客户端的 Minimongo， 并持续保持同步 —— 服务器上数据的任何变化都会被自动推送过来。 

import { Meteor } from 'meteor/meteor'
import { Measures } from './measures.js'

Meteor.publish('measures', function () {
  return Measures.find({})
})

import '/imports/api/measures.js'
import '/imports/api/publications.js'   // 只有服务器需要发布
✓ 只发布需要的数据

真实项目要控制数据量（比如只发布最近 100 条：find({}, { sort: { date: -1 }, limit: 100 })）和权限（用 this.userId 只发布当前用户能看的数据）。

在 React 中使用：react-meteor-data

Meteor 官方的 react-meteor-data 包（React 模板已包含）提供了把 Meteor 响应式数据接入 React 的 Hooks：

Hook作用
useSubscribe(name, ...args)订阅一个发布，返回 isLoading() 函数；组件卸载时自动取消订阅
useFind(() => cursor, deps)执行一个集合查询，数据变化时组件自动重新渲染（只更新变化的文档，效率高）
useTracker(() => value, deps)通用版：在 Meteor 的响应式计算中运行任意函数，结果变化时重新渲染
 
import { useSubscribe, useFind } from 'meteor/react-meteor-data'
import { Measures } from '/imports/api/measures.js'
import ProductionIndicator from './ProductionIndicator.jsx'

export default function ProductionDashboard() {
  const isLoading = useSubscribe('measures')
  const measures = useFind(() => Measures.find({}, { sort: { date: -1 } }), [])

  // 之后就是普通的派生数据了
  const count = measures.length
  const average = count ? measures.reduce((sum, m) => sum + m.value, 0) / count : 0
  const errorRate = count ? measures.filter((m) => m.error).length / count : 0

  if (isLoading()) return <div className="loading">加载中……</div>

  return (
    <div className="production-dashboard">
      <h1>生产仪表盘</h1>
      <section className="indicators">
        <ProductionIndicator value={average / 100} title="平均值" info={Math.round(average)} />
        <ProductionIndicator className="danger" value={errorRate} title="错误率"
                             info={`${Math.round(errorRate * 100)}%`} />
      </section>
      <section className="list">
        {measures.map((item) => (
          <div key={item._id}>
            <div className="date">{item.date.toLocaleString()}</div>
            <div className="error">{item.error ? '错误' : ''}</div>
            <div className="value">{item.value}</div>
          </div>
        ))}
      </section>
    </div>
  )
}
🔍 两套响应式系统的“握手”

Meteor 有自己的响应式系统 Tracker，React 则是“状态变了就重新渲染”。useFind / useTracker 做的就是桥接： 在 Tracker 的计算中执行查询，Tracker 通知“数据变了”时，就触发组件重新渲染（内部基于 React 的 useSyncExternalStore 这类机制订阅外部数据源）。 这和第 6 章 Zustand 的 selector 订阅、react-leaflet 接入 Leaflet 事件，本质上是同一件事：把 React 之外的数据源接进 React。

仪表组件：用 SVG 画半圆进度条

const ARC = 'M10 90 A80 80 0 0 1 170 90'   // 半径 80 的上半圆

export default function ProductionIndicator({ value, title, info, className = '' }) {
  const v = Math.min(Math.max(value, 0), 1)   // 限制在 0~1
  return (
    <div className={`production-indicator ${className}`}>
      <svg viewBox="0 0 180 100">
        <path className="track" d={ARC} />
        <path className="bar" d={ARC} pathLength="1" strokeDasharray="1" strokeDashoffset={1 - v} />
      </svg>
      <div className="info">{info}</div>
      <div className="title">{title}</div>
    </div>
  )
}

.production-indicator .track,
.production-indicator .bar { fill: none; stroke-width: 12; stroke-linecap: round; }
.production-indicator .track { stroke: #e5e5e5; }
.production-indicator .bar { stroke: #087ea4; transition: stroke-dashoffset .6s ease; }
.production-indicator.danger .bar { stroke: #e53935; }
ⓘ SVG 属性在 JSX 里要驼峰

stroke-dasharray 写成 strokeDasharray，stroke-width 写成 strokeWidth。A80 80 0 0 1 170 90 表示画一段半径 80 的弧到 (170, 90)，起点和终点相距 160，正好是半圆。

不用 Meteor，怎么做实时？

以 SSE 为例，写一个自定义 Hook：

import { useState, useEffect } from 'react'

export function useMeasuresStream() {
  const [measures, setMeasures] = useState([])
  useEffect(() => {
    const source = new EventSource('/api/measures/stream')   // 服务器每产生一条就推送一条
    source.onmessage = (e) => setMeasures((list) => [JSON.parse(e.data), ...list])
    return () => source.close()                              // 卸载时断开
  }, [])
  return measures
}

动手练习

  1. 发布只返回最近 50 条测量，并在仪表盘上显示“共 N 条记录”。
  2. 加一个 measure.clear 方法清空数据（想一想：这个方法应该允许任何人调用吗？）。
  3. 给仪表组件加一个 max prop，并画出刻度。
  4. 让发布接收参数 onlyErrors，仪表盘加一个复选框：useSubscribe('measures', onlyErrors)，参数变化时会自动重新订阅。
  5. （进阶）不用 Meteor，用 Express + SSE 或 Supabase 实现同样的实时仪表盘。
