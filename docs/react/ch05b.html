返回列表时保留状态：<Activity>补充

假设工单很多，列表页上方有一个搜索框。用户输入关键字、点开一张工单、再点“查看所有工单”回来 —— 搜索框空了。 原因是路由切换时 Tickets 组件被卸载，它的状态随之销毁，回来时创建的是一个全新的组件。 （数据倒不用重新等待：TanStack Query 的缓存还在。丢掉的是组件自己的界面状态。）

React 19.2 新增的 <Activity> 可以把一棵子树“藏起来”而不是卸载：

import { Activity } from 'react'
import { Link, Outlet, useLocation } from 'react-router'
import Tickets from './Tickets.jsx'

export default function TicketsLayout() {
  const { pathname } = useLocation()
  const onList = pathname === '/tickets'
  return (
    <main className="tickets-layout">
      {/* ……标题和按钮…… */}
      <Activity mode={onList ? 'visible' : 'hidden'}>
        <Tickets />                    {/* 列表始终挂载，离开时只是隐藏 */}
      </Activity>
      {!onList && <Outlet />}          {/* 新建、详情照常渲染 */}
    </main>
  )
}

路由表里的 index 路由保留（让 /tickets 能匹配），只是不再渲染组件：{ index: true, Component: () => null }。

  • 隐藏时：子树用 display: none 隐藏；effect 会执行清理函数（计时器、订阅都停掉）；状态保留；它的更新被降到最低优先级，不和可见内容抢资源。
  • 重新可见时：effect 重新运行，组件带着原来的状态回来。
  • 还能预渲染：用户很可能下一步要去的页面，可以先在 hidden 模式下渲染好，切过去时立即显示。
✓ 先想想：状态是不是该放进 URL

搜索关键字、筛选条件、页码这类状态，更好的位置往往是 URL：const [params, setParams] = useSearchParams()，params.get('q')。 这样不仅返回时还在，刷新、分享链接、浏览器前进后退也都能保留。<Activity> 适合放不进 URL 的界面状态：展开的分组、编辑到一半的内容、组件内部的选中项。 被隐藏的组件仍然占用内存，不要把所有页面都包起来。

提交新工单：useMutation + 备份输入

修改服务器数据用 useMutation。成功后让 ['tickets'] 缓存失效，列表会自动重新获取：

import { Link, useNavigate } from 'react-router'
import { useQueryClient } from '@tanstack/react-query'
import { $fetch } from '../api.js'
import { useLocalStorageState } from '../hooks/useLocalStorageState.js'
import SmartForm from '../components/SmartForm.jsx'
import FormInput from '../components/FormInput.jsx'

export default function NewTicket() {
  // 自动备份到 localStorage：误刷新、会话过期被踢去登录，回来后内容还在
  const [title, setTitle] = useLocalStorageState('NewTicket.title', '')
  const [description, setDescription] = useLocalStorageState('NewTicket.description', '')
  const queryClient = useQueryClient()
  const navigate = useNavigate()

  async function operation() {
    const ticket = await $fetch('tickets/new', {
      method: 'POST',
      body: JSON.stringify({ title, description }),
    })
    setTitle('')
    setDescription('')
    await queryClient.invalidateQueries({ queryKey: ['tickets'] })   // 列表缓存失效
    navigate(`/tickets/${ticket._id}`)
  }

  return (
    <SmartForm title="新工单" operation={operation} valid={Boolean(title && description)}
               actions={<>
                 <Link className="button secondary" to="/tickets">返回</Link>
                 <button type="submit" disabled={!title || !description}>提交工单</button>
               </>}>
      <FormInput name="title" value={title} onChange={setTitle}
                 placeholder="简短描述（最多 100 字）" maxLength={100} required />
      <FormInput type="textarea" name="description" value={description} onChange={setDescription}
                 placeholder="详细描述你遇到的问题" rows={4} />
    </SmartForm>
  )
}

这里用 SmartForm 统一处理加载和错误；如果想用 TanStack Query 的 useMutation，它同样提供 isPending、error 和 onSuccess 回调。

import { useState, useEffect } from 'react'

// 和 useState 用法一样，但会自动存到 localStorage
export function useLocalStorageState(key, defaultValue) {
  const [value, setValue] = useState(() => {
    const saved = localStorage.getItem(key)
    return saved !== null ? JSON.parse(saved) : defaultValue
  })

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value))
  }, [key, value])

  return [value, setValue]
}

表单进阶：校验与复合组件补充

目前的表单只用了 required、maxLength 这样的 HTML 属性，并且在内容为空时禁用提交按钮。 真实项目的需求更多：标题至少 5 个字、两次密码必须一致、邮箱格式要对、错误信息要显示在对应的输入框下面、用户离开输入框后才提示…… 手写这些逻辑很快就会乱成一团。

📜

Zod

用代码描述“数据应该长什么样”，一份规则前后端共用，还能推导出 TypeScript 类型。

📝

React Hook Form

管理字段的值、是否碰过、错误信息、提交状态；输入时不会让整个表单重新渲染。

🧩

复合组件

把“标签 + 输入框 + 错误提示”组合成一组协作的组件，无障碍属性自动连好。

用 Zod 描述规则，用 React Hook Form 管理表单

npm i react-hook-form @hookform/resolvers zod

import { z } from 'zod'

export const ticketSchema = z.object({
  title: z.string().trim().min(5, '标题至少 5 个字').max(100, '标题最多 100 字'),
  description: z.string().trim().min(10, '请至少写 10 个字，把问题描述清楚'),
})

import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { ticketSchema } from '../schemas/ticket.js'

export default function NewTicket() {
  const { register, handleSubmit, setError, formState: { errors, isSubmitting } } = useForm({
    resolver: zodResolver(ticketSchema),
    defaultValues: { title: '', description: '' },
    mode: 'onTouched',            // 离开输入框后才开始提示，之后边输入边校验
  })
  const queryClient = useQueryClient()
  const navigate = useNavigate()

  async function onSubmit(values) {   // 只有校验通过才会被调用
    try {
      const ticket = await $fetch('tickets/new', { method: 'POST', body: JSON.stringify(values) })
      await queryClient.invalidateQueries({ queryKey: ['tickets'] })
      navigate(`/tickets/${ticket._id}`)
    } catch (e) {
      setError('root', { message: e.message })   // 服务器错误显示在表单底部
    }
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input {...register('title')} placeholder="简短描述"
             aria-invalid={!!errors.title} aria-describedby="title-error" />
      {errors.title && <p id="title-error" className="field-error">{errors.title.message}</p>}

      <textarea {...register('description')} rows={4}
                aria-invalid={!!errors.description} aria-describedby="desc-error" />
      {errors.description && <p id="desc-error" className="field-error">{errors.description.message}</p>}

      {errors.root && <div className="error">{errors.root.message}</div>}
      <button type="submit" disabled={isSubmitting}>提交工单</button>
    </form>
  )
}

register('title') 返回 name、ref、onChange、onBlur 四个属性，展开到输入框上就连好了。 它用的是非受控输入（值保存在 DOM 里，通过 ref 读取），所以在大表单里打字时不会让整个组件重新渲染； 需要实时读取某个字段时用 watch('title')。服务器端可以 import 同一个 ticketSchema 再校验一遍 —— 前端校验只是为了体验，不能代替后端校验。

🔍 不用表单库：useActionState + Zod（点击展开）

表单不大时，React 19 的表单 Action 加上 Zod 的 safeParse 也能做得很干净：

const [state, submit, isPending] = useActionState(async (prev, formData) => {
  const result = ticketSchema.safeParse(Object.fromEntries(formData))
  if (!result.success) {
    // { title: ['标题至少 5 个字'], ... }，同时保留用户的输入
    return { errors: z.flattenError(result.error).fieldErrors, values: Object.fromEntries(formData) }
  }
  await createTicket(result.data)
  return { errors: {} }
}, { errors: {} })

<form action={submit}>
  <input name="title" defaultValue={state.values?.title} />
  {state.errors.title && <p className="field-error">{state.errors.title[0]}</p>}
  ……
</form>

它在提交时才校验，没有“离开输入框就提示”的即时反馈，但不需要任何依赖。第 7 章的 Next.js Server Actions 也是这种写法。

复合组件：用 Context 让一组组件协作

上面每个字段都要手写 aria-invalid、aria-describedby、错误提示的 id，重复而且容易写错。 可以做一组复合组件：外层的 Field 通过 Context 提供字段名、id 和错误，里面的 Label、Input、Error 自动读取： 

import { createContext, use, useId } from 'react'
import { useFormContext } from 'react-hook-form'

const FieldContext = createContext(null)

export function Field({ name, children }) {
  const id = useId()                                        // 生成页面内唯一、服务端渲染也一致的 id
  const { register, formState: { errors } } = useFormContext()
  return (
    <FieldContext value={{ id, name, error: errors[name], register }}>
      <div className="row">{children}</div>
    </FieldContext>
  )
}

Field.Label = function Label({ children }) {
  const { id } = use(FieldContext)
  return <label htmlFor={id}>{children}</label>
}

Field.Input = function Input({ as: Tag = 'input', ...rest }) {
  const { id, name, error, register } = use(FieldContext)
  return <Tag id={id} {...register(name)} aria-invalid={!!error}
              aria-describedby={error ? `${id}-err` : undefined} {...rest} />
}

Field.Error = function Error() {
  const { id, error } = use(FieldContext)
  return error ? <p id={`${id}-err`} className="field-error">{error.message}</p> : null
}

在表单外面包一层 React Hook Form 的 <FormProvider {...methods}>，useFormContext() 就能拿到同一个表单。 这种“一组组件通过 Context 协作”的模式在组件库里非常常见：<Tabs> 和 <Tabs.Tab>、<Select> 和 <Select.Option>。

ⓘ 让父组件调用子组件的方法：useImperativeHandle

偶尔父组件需要“命令”子组件做一件事，比如提交失败后聚焦第一个出错的输入框、清空表单。React 19 里 ref 是普通 prop， 子组件用 useImperativeHandle(ref, () => ({ focus, reset })) 决定暴露哪些方法，父组件通过 formRef.current.reset() 调用。 这是逃生舱，能用 props 和状态表达的就不要用它。（React Hook Form 自带 setFocus 和 reset。）

错误处理补充

到目前为止，我们只在 SmartForm 和数据加载里处理了请求错误。但应用里还可能发生其他错误：组件渲染时访问了 undefined 的属性、 某个第三方库抛出异常、部署新版本后用户浏览器里的旧页面加载不到懒加载的代码块…… React 的规则很严格：渲染过程中抛出的错误如果没人接住，整个应用会被卸载，页面一片空白。 一个稳健的应用应该分层处理错误：

组件级：错误边界

错误边界目前只能用类组件实现，大家通常直接用 react-error-boundary： 

import { ErrorBoundary } from 'react-error-boundary'
import { Outlet, useLocation } from 'react-router'

function Fallback({ error, resetErrorBoundary }) {
  return (
    <div className="error-box" role="alert">
      <p>这部分内容出了点问题：{error.message}</p>
      <button onClick={resetErrorBoundary}>重试</button>
    </div>
  )
}

export default function AppLayout() {
  const { pathname } = useLocation()
  return (
    <div className="app-layout">
      <NavMenu />
      {/* 页面出错不影响菜单；resetKeys 变化（换页面）时自动重置错误状态 */}
      <ErrorBoundary FallbackComponent={Fallback} resetKeys={[pathname]}>
        <Outlet />
      </ErrorBoundary>
    </div>
  )
}
⚠ 错误边界接不住的错误

错误边界只捕获渲染过程（以及生命周期、effect）中抛出的错误。事件处理函数、setTimeout、await 之后抛出的错误不经过渲染， 边界看不到 —— 这些要自己 try/catch，或者用 react-error-boundary 提供的 const { showBoundary } = useErrorBoundary() 在 catch 里调用 showBoundary(error) 交给最近的边界。TanStack Query 的 useQuery({ ..., throwOnError: true }) 也会把请求错误抛给边界。

前面在路由上用过的 ErrorBoundary 选项是同一个思路，它还能区分“页面不存在”这类路由错误：

import { useRouteError, isRouteErrorResponse } from 'react-router'

function RouteError() {
  const error = useRouteError()
  if (isRouteErrorResponse(error)) return <h1>{error.status} {error.statusText}</h1>   // loader 里 throw 的响应
  return <h1>出错了：{error.message}</h1>
}

全局：createRoot 的错误回调

createRoot(document.getElementById('root'), {
  // 没有任何边界接住的错误（应用即将被卸载）
  onUncaughtError(error, info) {
    report(error, info.componentStack)
  },
  // 被错误边界接住的错误（界面已经显示了 Fallback，这里只负责上报）
  onCaughtError(error, info) {
    report(error, info.componentStack)
  },
}).render(<App />)

// 没人处理的 Promise 拒绝
window.addEventListener('unhandledrejection', (e) => report(e.reason))

// 发布新版本后，旧页面去加载已经不存在的代码块会失败：刷新一下拿到新版本
window.addEventListener('vite:preloadError', () => location.reload())

请求错误也可以集中处理：创建 QueryClient 时传入 queryCache: new QueryCache({ onError: (e) => toast(e.message) })， 所有查询失败都会弹出提示，而不用在每个组件里写一遍。

✓ 错误边界放在哪里

想一想“哪一块坏了，其他部分还应该能用”：整个页面区域（如上面的 Outlet）一个；侧边栏、评论区、第三方图表这类相对独立的部件各一个。 最外层再放一个兜底的，至少显示“出错了，请刷新”，而不是一片空白。
