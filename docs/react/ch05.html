客服支持中心（上）：路由与认证

第一个真正的单页应用：虚构网店“我的衬衫铺”的客服中心，有常见问题、注册登录、工单列表、提交工单和工单详情。 内容比较多，分成两篇：这一篇搭好骨架 —— React Router 7、加载数据（自定义 Hook → TanStack Query）、用 Context 共享登录状态、React 19 的表单 Actions 和守卫路由； 下篇完成工单功能，并深入表单校验、页面状态保留和错误处理。

本篇目标

  • 用 React Router 7 搭建多页面应用：路由表、<Outlet>、<NavLink>、编程式导航
  • 用自定义 Hook 复用“加载数据”的逻辑，再升级为 TanStack Query
  • 用 Context 共享当前用户，用“守卫路由”保护私有页面
  • 封装通用表单组件：受控输入、...rest 透传属性、useActionState
  • 写一个 useClickOutside Hook，做出可用键盘操作的用户下拉菜单补充
  • 处理登录跳转、会话过期，并理解 Session 与 JWT 的取舍补充

路由与页面

单页应用里，切换页面时浏览器并不会重新加载 HTML，而是由 JS 根据 URL 换掉页面上的组件。这个“URL → 组件”的映射就是路由。 React 本身不带路由，社区标准是 React Router（第 7 版与原来的 Remix 框架合并，包名统一为 react-router）。

ⓘ React Router 7 的三种用法

声明模式（<BrowserRouter> + <Routes>）最简单；数据模式（createBrowserRouter）用一张路由表描述路由，并支持数据加载、滚动恢复等； 框架模式则是完整的全栈框架。本章使用数据模式，它和“路由表”的思路最一致，也是官方推荐的单页应用写法。

常见问题页：加载数据

封装请求：api.js

所有请求都要拼基础地址、解析 JSON、检查错误。先写一个统一的 $fetch：

const baseUrl = '/api/'

export async function $fetch(url, options) {
  const response = await fetch(`${baseUrl}${url}`, {
    headers: { 'Content-Type': 'application/json' },
    credentials: 'include',            // 带上会话 Cookie
    ...options,
  })
  if (response.ok) {
    return await response.json()
  }
  // 服务器用纯文本返回错误信息
  const error = new Error(await response.text())
  error.status = response.status
  throw error
}

第一版：useState + useEffect

import { useState, useEffect } from 'react'
import { $fetch } from '../api.js'
import Loading from '../components/Loading.jsx'

export default function FAQ() {
  const [questions, setQuestions] = useState([])
  const [error, setError] = useState(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    let ignore = false                         // 组件卸载后不要再设置状态
    $fetch('questions')
      .then((data) => { if (!ignore) setQuestions(data) })
      .catch((e) => { if (!ignore) setError(e) })
      .finally(() => { if (!ignore) setLoading(false) })
    return () => { ignore = true }
  }, [])

  return (
    <main className="faq">
      <h1>常见问题</h1>
      {loading && <Loading />}
      {error && <div className="error">无法加载问题列表</div>}
      <section className="list">
        {questions.map((q) => (
          <article key={q._id}>
            <h2 dangerouslySetInnerHTML={{ __html: q.title }} />
            <p dangerouslySetInnerHTML={{ __html: q.content }} />
          </article>
        ))}
      </section>
    </main>
  )
}
🔍 为什么要 ignore 标志

请求是异步的。如果用户在数据回来之前就离开了这个页面（组件卸载），或者 effect 因为依赖变化而重新执行，旧请求的结果就不应该再写进状态。 清理函数把 ignore 设为 true，旧请求回来时就会被忽略。开发模式下 StrictMode 会故意“挂载两次”，正是为了帮你发现忘写这类清理的情况。

第二版：抽成自定义 Hook

工单列表、工单详情都要写一模一样的 loading / error / data 三件套。把它抽成一个自定义 Hook：

import { useState, useEffect } from 'react'
import { $fetch } from '../api.js'

export function useRemoteData(url) {
  const [data, setData] = useState(null)
  const [error, setError] = useState(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    let ignore = false
    setLoading(true)
    setError(null)
    $fetch(url)
      .then((d) => { if (!ignore) setData(d) })
      .catch((e) => { if (!ignore) setError(e) })
      .finally(() => { if (!ignore) setLoading(false) })
    return () => { ignore = true }
  }, [url])        // url 变了就重新请求（工单详情页会用到）

  return { data, error, loading }
}

import { useRemoteData } from '../hooks/useRemoteData.js'

export default function FAQ() {
  const { data: questions, error, loading } = useRemoteData('questions')
  // ……模板同上
}

第三版：TanStack Query

我们的 useRemoteData 还缺很多东西：两个组件请求同一个接口会发两次请求；离开页面再回来要重新等加载；新建工单后列表不会自动刷新；没有重试…… 这些问题有一个成熟的通用解法 —— TanStack Query（原 React Query）。它把服务器数据当作一份缓存来管理： 

import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

const queryClient = new QueryClient()

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <RouterProvider router={router} />
    </QueryClientProvider>
  </StrictMode>
)

import { useQuery } from '@tanstack/react-query'
import { $fetch } from '../api.js'
import Loading from '../components/Loading.jsx'

export default function FAQ() {
  const { data: questions, error, isPending } = useQuery({
    queryKey: ['questions'],                 // 缓存的“名字”
    queryFn: () => $fetch('questions'),      // 怎么获取
  })

  return (
    <main className="faq">
      <h1>常见问题</h1>
      {isPending ? <Loading />
        : error ? <div className="error">无法加载问题列表</div>
        : (
          <section className="list">
            {questions.map((q) => (
              <article key={q._id}>
                <h2 dangerouslySetInnerHTML={{ __html: q.title }} />
                <p dangerouslySetInnerHTML={{ __html: q.content }} />
              </article>
            ))}
          </section>
        )}
    </main>
  )
}
★ 区分“服务器状态”和“客户端状态”

从服务器取来的数据（工单、问题列表）本质上是远端数据的一份副本，会过期、需要同步 —— 交给 TanStack Query 这类工具。 只存在于浏览器里的数据（输入框内容、弹窗开关、当前用户偏好）才是真正的“客户端状态”，用 useState、Context 或第 6 章的 Zustand。 分清两者，能让状态管理简单很多。

用户认证

用 Context 共享当前用户

导航栏、守卫、登录页、请求层……很多地方都需要知道“当前是谁登录了”。这正适合 Context：

import { createContext, useContext, useState } from 'react'

const AuthContext = createContext(null)

export function AuthProvider({ initialUser, children }) {
  const [user, setUser] = useState(initialUser)
  return (
    <AuthContext value={{ user, setUser }}>
      {children}
    </AuthContext>
  )
}

// 自定义 Hook：组件里用 const { user, setUser } = useAuth()
export function useAuth() {
  const ctx = useContext(AuthContext)
  if (!ctx) throw new Error('useAuth 必须在 <AuthProvider> 内部使用')
  return ctx
}

如果先渲染再查，用户直接打开 /tickets 时，守卫在用户信息回来之前就运行了，会把已登录的用户误判为未登录、送去登录页。

通用表单组件 SmartForm

登录、注册、提交工单都是同一个模式：提交时执行一个异步操作，期间显示加载动画，失败时显示错误。React 19 新增的 useActionState 正好为此设计：

import { useActionState } from 'react'
import Loading from './Loading.jsx'

export default function SmartForm({ title, operation, valid, actions, children, className }) {
  // 返回：[状态, 传给 form 的 action, 是否进行中]
  const [error, submit, isPending] = useActionState(async () => {
    if (!valid) return null
    try {
      await operation()
      return null                // 成功：没有错误
    } catch (e) {
      return e.message           // 失败：错误信息成为新状态
    }
  }, null)

  return (
    <form action={submit} className={className}>
      <section className="content">
        <h2>{title}</h2>
        {children}                                 {/* 主要内容：输入框 */}
        <div className="actions">{actions}</div>  {/* 第二个“插槽”：按钮 */}
        {error && <div className="error">{error}</div>}
      </section>
      {isPending && <Loading className="overlay" />}
    </form>
  )
}
ⓘ 多个“插槽”怎么办

children 只有一个。需要第二块可定制内容（这里的按钮区）时，就再加一个 prop，直接传 JSX：actions={<button>…</button>}。 在 React 里，JSX 就是普通的值，可以作为任何 prop 传递。

输入框组件：受控 + 透传

表单里有很多结构相同的输入框，封装成 FormInput。React 里没有 v-model，“双向绑定”就是一对 props：value 和 onChange。 其他所有属性（name、type、placeholder、maxLength、rows……）用剩余参数 ...rest 收集起来，原样交给内部的元素： 

export default function FormInput({ value, onChange, invalid = false, type = 'text', ...rest }) {
  const Element = type === 'textarea' ? 'textarea' : 'input'   // 动态决定渲染哪个标签
  return (
    <div className="row">
      <Element
        className={`input ${invalid ? 'invalid' : ''}`}
        type={Element === 'input' ? type : undefined}
        value={value}
        onChange={(e) => onChange(e.target.value)}   // 只把值交给父组件，而不是整个事件
        {...rest}                                      // name、placeholder、rows、required……
      />
    </div>
  )
}

登录组件

import { useState } from 'react'
import { useNavigate, useSearchParams } from 'react-router'
import { useAuth } from '../auth/AuthContext.jsx'
import { $fetch } from '../api.js'
import SmartForm from '../components/SmartForm.jsx'
import FormInput from '../components/FormInput.jsx'

export default function Login() {
  const [mode, setMode] = useState('login')         // 'login' | 'signup'
  const [username, setUsername] = useState('')
  const [password, setPassword] = useState('')
  const [password2, setPassword2] = useState('')
  const [email, setEmail] = useState('')

  const { setUser } = useAuth()
  const navigate = useNavigate()
  const [searchParams] = useSearchParams()

  // 派生数据：校验
  const retypePasswordError = password2 !== '' && password !== password2
  const signupValid = password2 && email && !retypePasswordError
  const valid = Boolean(username && password && (mode !== 'signup' || signupValid))

  async function operation() {
    if (mode === 'login') {
      const user = await $fetch('login', {
        method: 'POST',
        body: JSON.stringify({ username, password }),
      })
      setUser(user)
      // 回到原本想去的页面（见后文的守卫）
      navigate(searchParams.get('redirect') || '/', { replace: true })
    } else {
      await $fetch('signup', {
        method: 'POST',
        body: JSON.stringify({ username, password, email }),
      })
      setMode('login')
    }
  }

  const actions = mode === 'login' ? (
    <>
      <button type="button" className="secondary" onClick={() => setMode('signup')}>注册</button>
      <button type="submit" disabled={!valid}>登录</button>
    </>
  ) : (
    <>
      <button type="button" className="secondary" onClick={() => setMode('login')}>返回登录</button>
      <button type="submit" disabled={!valid}>创建账号</button>
    </>
  )

  return (
    <main className="login">
      <h1>请先登录</h1>
      <SmartForm className="form" title={mode === 'login' ? '登录' : '创建新账号'}
                 operation={operation} valid={valid} actions={actions}>
        <FormInput name="username" value={username} onChange={setUsername} placeholder="用户名" />
        <FormInput name="password" type="password" value={password} onChange={setPassword} placeholder="密码" />
        {mode === 'signup' && (
          <>
            <FormInput name="verify-password" type="password" value={password2} onChange={setPassword2}
                       placeholder="再次输入密码" invalid={retypePasswordError} />
            <FormInput name="email" type="email" value={email} onChange={setEmail} placeholder="邮箱" />
          </>
        )}
      </SmartForm>
    </main>
  )
}

用户下拉菜单：useClickOutside补充

菜单栏里并排放着用户名和“登出”有点简陋。常见的做法是点击用户名弹出一个下拉菜单，点击菜单外面的任何地方、或者按 Esc，菜单自动关闭。 “点击外部关闭”在弹出层、下拉框、日期选择器里到处都要用，正好封装成一个自定义 Hook。 

import { useEffect, useEffectEvent } from 'react'

export function useClickOutside(ref, handler) {
  // useEffectEvent（React 19.2）：在 effect 里总能调用到最新的 handler，
  // 又不必把 handler 写进依赖数组（否则父组件每次渲染都会重新注册监听）
  const onOutside = useEffectEvent(handler)

  useEffect(() => {
    function onPointerDown(e) {
      if (ref.current && !ref.current.contains(e.target)) onOutside(e)
    }
    document.addEventListener('pointerdown', onPointerDown)
    return () => document.removeEventListener('pointerdown', onPointerDown)   // 卸载时移除
  }, [ref])
}

import { useState, useRef } from 'react'
import { Link } from 'react-router'
import { useClickOutside } from '../hooks/useClickOutside.js'

export default function UserMenu({ user, onLogout }) {
  const [open, setOpen] = useState(false)
  const menuRef = useRef(null)
  const buttonRef = useRef(null)
  useClickOutside(menuRef, () => setOpen(false))

  function handleKeyDown(e) {
    if (e.key === 'Escape' && open) {
      setOpen(false)
      buttonRef.current.focus()           // 关闭后把焦点还给按钮，键盘用户不会“迷路”
    }
  }

  return (
    <div className="user-menu" ref={menuRef} onKeyDown={handleKeyDown}>
      <button ref={buttonRef} aria-haspopup="menu" aria-expanded={open}
              onClick={() => setOpen((o) => !o)}>
        {user.username} ▾
      </button>
      {open && (
        <ul className="dropdown" role="menu">
          <li role="none"><Link role="menuitem" to="/tickets" onClick={() => setOpen(false)}>我的工单</Link></li>
          <li role="none"><button role="menuitem" onClick={onLogout}>登出</button></li>
        </ul>
      )}
    </div>
  )
}

在 NavMenu 里把原来的两个链接换成 {user ? <UserMenu user={user} onLogout={logout} /> : <NavLink to="/login">登录</NavLink>} 即可。

✓ 几个细节

监听 pointerdown 而不是 click：拖动选中文字后松开鼠标，click 可能落在菜单外，导致误关闭。 用真正的 <button> 当触发器，键盘的回车、空格天然可用；aria-expanded 让读屏软件知道菜单是开是关。 完整的菜单还应支持方向键在菜单项之间移动，第 10 章（组件库与设计系统）会讲怎么用现成的无障碍组件做到这些。

ⓘ 没有 useEffectEvent 时

React 19.2 之前，常见写法是用一个 ref 保存最新的回调：const handlerRef = useRef(handler); useEffect(() => { handlerRef.current = handler })， 在监听函数里调用 handlerRef.current(e)。效果相同，你会在很多现有代码和库里看到它。

保护私有页面

React Router 没有“全局前置守卫”这种钩子，React 的做法更“组件化”：写一个守卫组件作为布局路由，它检查登录状态， 没登录就渲染 <Navigate>（跳转），登录了就渲染 <Outlet>（放行）： 

import { Navigate, Outlet, useLocation } from 'react-router'
import { useAuth } from './AuthContext.jsx'

// 只允许已登录用户
export function RequireAuth() {
  const { user } = useAuth()
  const location = useLocation()
  if (!user) {
    const redirect = encodeURIComponent(location.pathname + location.search)
    return <Navigate to={`/login?redirect=${redirect}`} replace />
  }
  return <Outlet />
}

// 只允许游客（未登录）
export function GuestOnly() {
  const { user } = useAuth()
  return user ? <Navigate to="/" replace /> : <Outlet />
}

export const router = createBrowserRouter([
  {
    path: '/',
    Component: AppLayout,
    children: [
      { index: true, Component: Home },
      { path: 'faq', Component: FAQ },
      {
        Component: GuestOnly,                       // 没有 path 的布局路由：只负责“包一层”
        children: [{ path: 'login', Component: Login }],
      },
      {
        Component: RequireAuth,
        children: [{ path: 'tickets', Component: TicketsLayout }],
      },
    ],
  },
])
ⓘ 为什么把目标地址放进 URL 的查询参数

登录页需要知道“用户原本想去哪”。放在 ?redirect=/tickets 里，刷新登录页也不会丢失。登录成功后 navigate(redirect, { replace: true })， 用 replace 是为了让用户点“后退”时不会又回到登录页。

⚠ 校验 redirect

redirect 来自 URL，可以被伪造。交给 navigate 只会在站内跳转，相对安全；但不要用它做 location.href = redirect，那可能成为“开放重定向”漏洞。至少确认它以 / 开头。

🔍 另一种写法：在 loader 里重定向（点击展开）

数据模式下，每条路由可以有一个 loader 函数，在渲染之前执行，可以加载数据，也可以 throw redirect('/login')。 它的好处是在组件渲染前就决定去向；缺点是 loader 在 React 组件之外运行，拿不到 Context，需要从模块级的状态（或第 6 章的 Zustand store）读取登录信息。 两种写法都很常见，本章选择更直观的守卫组件。

会话过期

会话过期或服务器重启后，请求私有接口会返回 403。要在请求层统一处理：清空用户、跳转登录。但 $fetch 是普通函数，不能用 Hook 拿到 setUser。 解决办法是让 AuthProvider 在挂载时注册一个处理函数： 

let onUnauthorized = null
export function setUnauthorizedHandler(fn) {
  onUnauthorized = fn
}

export async function $fetch(url, options) {
  // ...
  if (response.status === 403) {
    onUnauthorized?.()
    throw new Error('会话已过期，请重新登录')
  }
  // ...
}

import { useEffect } from 'react'
import { setUnauthorizedHandler } from '../api.js'

export function AuthProvider({ initialUser, children }) {
  const [user, setUser] = useState(initialUser)

  useEffect(() => {
    setUnauthorizedHandler(() => setUser(null))   // 收到 403：登出
    return () => setUnauthorizedHandler(null)
  }, [])
  // ...
}

Session 还是 JWT？补充

这个项目用的是基于 Cookie 的会话（Session）：登录后服务器把会话 id 写进 Cookie，浏览器之后每次请求都自动带上它。 网上很多 React 教程用的是另一种方式 —— JWT 令牌：登录后服务器返回一个签名过的令牌，前端自己保存（常见的是 localStorage），每次请求放进 Authorization 头。 两者该怎么选？

★ 对普通网页应用的建议

前端和 API 在同一个站点下时，优先使用 HttpOnly + Secure + SameSite 的 Cookie 会话，它对 XSS 更有抵抗力，实现也更简单。 需要给第三方或移动端提供 API 时再考虑令牌方案；如果要在浏览器里用 JWT，也尽量把它放在 HttpOnly Cookie 里，而不是 localStorage。 无论哪种方式，前端的守卫路由都只是体验优化，真正的权限检查必须在服务器上做。

ⓘ React 的 XSS 防护有多可靠

JSX 里的 {变量} 默认会转义，React 应用天然比手写 innerHTML 安全得多。但漏洞仍可能来自 dangerouslySetInnerHTML、 未经校验就放进 href、src 的用户输入、第三方脚本和依赖包。所以“令牌放在 JS 读不到的地方”依然是值得的纵深防御。
