ⓘ react 和 react-dom 为什么是两个包

react 只包含组件、Hooks 等与平台无关的核心；react-dom 负责把它渲染到浏览器 DOM。 同样的 React 组件，配上 React Native 就能渲染成手机原生界面 —— 这就是分成两个包的原因。

JSX 的编译与 Fast Refresh

Vite 的 React 插件会把 JSX 编译成函数调用。新的“自动运行时”会自动导入需要的函数，所以组件文件里不必再写 import React：

你写的
export default function Hello({ name }) {
  return <h1 className="title">Hi {name}</h1>
}
编译后（示意）
import { jsxs } from 'react/jsx-runtime'
export default function Hello({ name }) {
  return jsxs('h1', { className: 'title',
                      children: ['Hi ', name] })
}

修改组件文件并保存，页面会立即更新，而且组件里的状态（比如输入框里打了一半的字）会被保留 —— 这叫 Fast Refresh。 为了让它正常工作，一个 .jsx 文件最好只导出组件；把常量、工具函数放到单独的 .js 文件里。

React 如何渲染：触发、渲染、提交

第 1 章说过“状态一变，React 就重新执行组件函数”。现在把这个过程看得更仔细一点。React 把一次界面更新分成三个阶段：

组件什么时候会重新渲染

有三种情况会让一个组件重新渲染：

  1. 它自己的状态变了（setState / dispatch）；
  2. 它读取的 Context 的值变了；
  3. 它的父组件重新渲染了 —— 默认情况下，父组件渲染时，所有子组件都会跟着渲染，不管 props 有没有变。
★ 不要害怕重新渲染

“渲染”只是调用函数，真正昂贵的 DOM 操作只发生在有差异的地方。绝大多数应用里，多余的渲染根本感觉不到。 只有当某个组件的渲染本身很重（大列表、复杂计算），并且被频繁触发时，才值得优化。

手动优化：memo、useMemo、useCallback

API作用例子
memo(Component)props 没变（浅比较）时跳过该组件的渲染const Header = memo(function Header(props) {...})
useMemo(fn, deps)缓存计算结果（上一章用过）useMemo(() => filter(list), [list])
useCallback(fn, deps)缓存函数本身，让它在多次渲染间保持同一个引用useCallback(() => save(id), [id])

为什么需要 useCallback？因为每次渲染，组件里的函数都是新创建的。如果把 onClick={() => ...} 传给一个 memo 组件， 它每次都会收到一个“新的”函数，浅比较永远不相等，memo 就失效了：

React Compiler：自动记忆化

React Compiler（2025 年 10 月发布 1.0）是一个构建期工具：它分析你的组件代码，自动插入相当于 memo、useMemo、useCallback 的缓存逻辑， 而且比手写更精细。启用它之后，绝大多数情况下你都不需要再手写这三个 API。 

npm install -D babel-plugin-react-compiler

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [
    react({
      babel: {
        plugins: ['babel-plugin-react-compiler'],   // 启用 React Compiler
      },
    }),
  ],
})
⚠ 编译器依赖“遵守规则”

Compiler 假设你的组件是纯的。如果代码在渲染时修改了外部变量、直接改了状态对象，编译器会跳过这个组件（或者优化后行为出错）。 第 7 章配置的 eslint-plugin-react-hooks 包含了编译器相关的检查规则，能提前发现这类问题。前两章反复强调的“纯函数”和“不可变更新”，在这里得到了回报。

StrictMode：开发时的“体检”

main.jsx 里的 <StrictMode> 只在开发环境生效。它会故意把组件函数调用两次、把 effect 挂载 → 清理 → 再挂载一次， 以暴露不纯的渲染和缺失的清理函数。所以开发时看到 console.log 打印两遍是正常的，生产环境不会这样。

ⓘ 怎么选？

学习阶段用普通 CSS 或 CSS Modules 就好，概念最少。团队项目中 Tailwind 很常见，好处是不用起类名、样式和结构放在一起、未使用的样式会被自动剔除。 本教程后面的项目沿用原书提供的样式文件（普通 CSS），以便聚焦在 React 本身。

组件的组织方式

  • 一个文件一个组件，文件名和组件名一致，用 PascalCase：MovieList.jsx。
  • 默认导出（export default function Movie）或具名导出（export function Movie）都可以，团队内统一即可。
  • 就近放置：组件的样式、测试、只在它这里用的小组件，放在同一个文件夹里。
  • 组件变得太大时就拆分：一个经验法则是，组件超过一屏、或者同时负责好几件互不相关的事情。
import { useState } from 'react'
import Movie from './Movie.jsx'

export default function Movies() {
  const [movies] = useState([
    { id: 0, title: 'Star Wars' },
    { id: 1, title: 'Blade Runner' },
  ])
  return (
    <ul className="movies">
      {movies.map((movie) => <Movie key={movie.id} movie={movie} />)}
    </ul>
  )
}

项目变大以后：按功能组织补充

小项目按“文件类型”分目录就够了；项目变大后，更推荐按功能（feature）组织，把一个功能相关的组件、Hook、store、API 放在一起：

组件嵌套深了以后，import X from '../../../shared/X.jsx' 这种相对路径很难维护。Vite 的 React 模板没有预设别名，自己加一个 @ 指向 src： 

import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
})

import Button from '@/shared/components/Button.jsx'   // 不管在哪个文件里，写法都一样

TypeScript 项目还要在 tsconfig.app.json 的 compilerOptions 里加上 "paths": { "@/*": ["./src/*"] }，编辑器才认识这个别名。第 11 章（进阶专题）会进一步讨论大型项目的边界和 monorepo。

在 React 中使用 TypeScript补充

React 社区里 TypeScript 已经非常普遍：组件库、招聘要求、大部分新项目都默认使用它。它在 React 里的价值特别直观 —— 给组件的 props 写上类型，使用组件时少传、传错一个属性，编辑器马上标红。

开启 TypeScript

npm create vite@latest my-app -- --template react-ts

组件文件改成 .tsx，普通模块是 .ts。package.json 里的构建命令变成 tsc -b && vite build： 先做类型检查，通过了再打包。

给 props 加类型

import type { ReactNode } from 'react'

type MovieProps = {
  movie: { id: number; title: string }
  highlighted?: boolean                  // 可选
  onSelect?: (id: number) => void        // 回调 prop 也要写清参数
  children?: ReactNode                   // 任何能渲染的东西
}

export default function Movie({ movie, highlighted = false, onSelect, children }: MovieProps) {
  return (
    <li className={highlighted ? 'hl' : ''} onClick={() => onSelect?.(movie.id)}>
      {movie.title} {children}
    </li>
  )
}

想复用原生元素的全部属性（比如封装一个按钮），用 ComponentProps：

import type { ComponentProps } from 'react'

type ButtonProps = ComponentProps<'button'> & { variant?: 'primary' | 'ghost' }

function Button({ variant = 'primary', ...rest }: ButtonProps) {
  return <button className={`btn btn-${variant}`} {...rest} />    // onClick、disabled、type 都有类型提示
}

状态、事件、ref 与 reducer

import { useState, useRef, useReducer, type ChangeEvent } from 'react'

type User = { id: string; name: string }

// 能从初始值推断的不用写；初始值是 null 时要写清楚“以后会是什么”
const [count, setCount] = useState(0)                   // number
const [user, setUser] = useState<User | null>(null)

// DOM ref：传入元素类型，初始值 null
const inputRef = useRef<HTMLInputElement>(null)

// 事件对象的类型
function handleChange(e: ChangeEvent<HTMLInputElement>) {
  setName(e.target.value)
}

// reducer 的 action 用“可辨识联合类型”：switch 里每个分支都能拿到对应的字段
type Action =
  | { type: 'added'; note: Note }
  | { type: 'removed'; id: string }

function notesReducer(notes: Note[], action: Action): Note[] {
  switch (action.type) {
    case 'added':   return [...notes, action.note]           // 这里 action.note 有类型
    case 'removed': return notes.filter((n) => n.id !== action.id)
  }
}
✓ 不要过度标注

TypeScript 能推断的地方（大多数 useState、useMemo、事件处理函数内联写在 JSX 上时的参数）就让它推断。 类型主要写在边界上：组件的 props、函数参数、API 返回的数据。也不必再用 React.FC，直接给参数加类型更简单。

环境变量与构建模式补充

真实项目几乎都有“不同环境不同配置”的需求：开发时 API 在 localhost:3000，生产环境在 https://api.example.com； 测试环境要打开调试日志，生产环境要关掉。把这些值写死在代码里，每次部署都得改代码。Vite 的做法是 .env 文件 + 构建模式。 

VITE_APP_TITLE=我的电影清单

VITE_API_BASE=/api/
VITE_DEBUG=true

VITE_API_BASE=https://api.example.com/
VITE_DEBUG=false

在代码里通过 import.meta.env 读取（注意：值都是字符串）：

const baseUrl = import.meta.env.VITE_API_BASE        // 开发时是 '/api/'，构建后是正式地址

if (import.meta.env.DEV) {                            // 内置变量：是否开发环境
  console.log('当前模式：', import.meta.env.MODE)     // 'development' / 'production' / 自定义
}

export default function App() {
  return <h1>{import.meta.env.VITE_APP_TITLE}</h1>
}
⚠ 前端没有秘密

只有以 VITE_ 开头的变量才会暴露给前端代码，这是 Vite 的保护措施。但请记住：暴露给前端的任何值，用户都能在浏览器里看到。 API 密钥、数据库密码、OAuth 客户端密钥绝不能放进 VITE_ 变量，它们只能留在服务器上（第 13 章的 AI 聊天会演示怎么做）。 含有真实密钥的 .env.local 一定要写进 .gitignore。

✓ 给环境变量加上类型提示

TypeScript 项目可以在 src/vite-env.d.ts 里声明 interface ImportMetaEnv { readonly VITE_API_BASE: string }，编辑器就能补全，拼错名字时会报错。

构建与部署

npm run build      # 输出到 dist/
npm run preview    # 本地预览
dist/ ├── index.html └── assets/ ├── index-BmT3xQk9.js # 文件名带内容哈希，可以永久缓存 └── index-D4fK2s1a.css

把 dist/ 上传到任何静态托管服务即可（GitHub Pages、Netlify、Vercel、Cloudflare Pages……）。两个常见的坑：

  • 子路径部署：比如 GitHub Pages 的 https://用户名.github.io/仓库名/，要在 vite.config.js 里设置 base: '/仓库名/'。
  • 前端路由刷新 404：下一章使用 React Router 后，直接访问 /tickets 这样的地址，服务器上并没有这个文件，需要配置“找不到就返回 index.html”。

依赖版本

package.json 里的 "^19.2.0" 表示“19.x.x 中不低于 19.2.0 的版本”（语义化版本：主版本.次版本.修订号）。 用 npm outdated 查看可更新的包，npm update 在允许范围内更新；跨主版本升级前先读更新日志。

小结

  • 新项目用 Vite（纯前端）或框架（React Router 框架模式、Next.js），不要再用 Create React App。
  • Vite 开发时按需编译、Fast Refresh 保留状态；vite build 负责生产打包。
  • 一次更新 = 触发 → 渲染（调用函数、比较）→ 提交（改 DOM、运行 effect）。
  • 组件在自身状态变化、读取的 Context 变化、父组件渲染时会重新渲染；这通常不是问题。
  • memo / useMemo / useCallback 可以手动优化，React Compiler 能自动完成大部分。
  • 样式：普通 CSS、CSS Modules、Tailwind 各有适用场景。
  • 项目变大后按功能组织代码，用别名 @ 代替很深的相对路径。补充
  • TypeScript：类型写在边界上（props、参数、API 数据），Vite 只转译，tsc 负责检查。补充
  • 环境变量放在 .env.[mode] 里，只有 VITE_ 开头的会暴露给前端，前端没有秘密。补充
