第 10 章 · 进阶专题

组件库与设计系统

书里的项目大多手写样式，这对学习很好。真实项目里，团队通常会选一个组件库来加速开发，或者在它的基础上搭一套自己的设计系统。 本章讨论怎么选组件库、怎么定制主题、怎么写出可复用而且人人都能用（无障碍）的基础组件，以及怎么用 Storybook 给组件写文档。

本章目标

  • 理解设计系统的层次：设计令牌 → 基础组件 → 业务组件 → 页面
  • 了解 MUI、Ant Design、Mantine、shadcn/ui、Radix / React Aria 的定位，学会选型
  • 理解样式方案对组件库的影响：运行时 CSS-in-JS、零运行时、服务端组件兼容
  • 用 CSS 变量做主题和暗色模式，并定制各家组件库的主题
  • 写一个带变体、属性透传和 asChild 的基础按钮组件
  • 掌握无障碍（a11y）的核心：语义化标签、键盘操作、焦点管理和 ARIA
  • 用 Storybook 开发和展示组件

设计系统的四层结构

“设计系统”听起来很大，其实就是一套大家共同遵守的规则 + 实现这些规则的组件。从下往上可以分成四层，下层越稳定，上层越容易保持一致：

组件库帮你解决的是第二层（再附带一套默认的第一层）。选组件库，本质上是在选“基础组件和设计令牌，我要自己掌控多少”。

组件库选型

React 生态里的组件库大致落在一条光谱上：一头是“开箱即用、样式全包”，另一头是“只给行为、样式全归你”。

库风格与特点适合
MUI（Material UI）最老牌、组件最全的 Material Design 实现；MUI X 提供数据表格、日期选择器等重型组件需要大量现成组件的企业应用
Ant Design蚂蚁集团出品的后台风格组件库，表单、表格极其完善，中文文档和社区资源丰富管理后台、内部系统
Mantine组件和 Hooks 都很全，样式基于 CSS Modules + CSS 变量（零运行时），文档好想要现代外观、上手快的项目
shadcn/ui不是依赖包，而是用 CLI 把组件源码复制进项目；基于 Radix + Tailwind，目前 React 社区最流行的方案之一品牌感强、要求完全掌控外观的产品
Radix UI无样式组件：只负责交互逻辑、键盘操作、焦点管理和 ARIA从零搭自己的设计系统
React AriaAdobe 出品，无障碍和国际化做得最细（屏幕阅读器、触屏、从右到左语言），既有 Hooks 也有组件对无障碍要求很高的产品
★ 选型时问自己三个问题

① 设计稿是贴近某个现成风格，还是有强烈的品牌设计？前者选样式全包的库，后者选 shadcn/ui 或 headless。
② 最复杂的组件是什么？大数据表格、树形选择、日期区间这类组件自己写成本很高，确认候选库里有，并且好用。
③ 团队会维护多久？看 GitHub 活跃度、React 新版本（服务端组件、React Compiler）的跟进速度、TypeScript 类型和无障碍支持。

组件库背后的样式方案

React 组件库都以 ES 模块发布，import { Button } from '@mui/material' 这样的具名导入在构建时会被摇树优化，不需要额外的按需引入插件。 选型时更值得关注的是：组件库的样式是怎么实现的。这会影响性能，也决定了它能不能用在服务端组件里。

方案原理代表注意
运行时 CSS-in-JS在浏览器里执行 JS 生成样式，插入 <style>MUI（Emotion）、Chakra UI v2有运行时开销；在服务端组件里不能用，需标记 'use client'
零运行时 / CSS 变量构建时生成 CSS 文件，主题通过 CSS 变量切换Mantine、Ant Design v5+（CSS 变量模式）、Panda CSS性能好，SSR 友好
工具类Tailwind 的类名直接写在 JSX 上shadcn/ui没有运行时；需要习惯 Tailwind 的写法
ⓘ 组件库和服务端组件

第 7 章说过，服务端组件里不能用状态和 effect。下拉菜单、对话框这类交互组件本来就是客户端组件，组件库会在文件里写好 'use client'； 但如果它的样式依赖运行时 CSS-in-JS，连一个纯展示的 <Card> 也只能在客户端渲染。在 Next.js 项目里选型时要留意这一点，MUI 也提供了零运行时的 Pigment CSS 作为迁移方向。

主题与设计令牌

设计令牌的三层

不要在组件里直接写 #3b82f6。把颜色、间距等值定义成令牌（token），再分层引用。 这样换品牌色、做暗色模式时，只需要改一处： 

:root {
  /* 原始令牌 */
  --blue-500: #3b82f6;
  --blue-400: #60a5fa;
  --gray-50: #f9fafb;
  --gray-900: #111827;

  /* 语义令牌 */
  --color-primary: var(--blue-500);
  --color-bg: var(--gray-50);
  --color-text: var(--gray-900);
  --radius: 8px;
}

/* 暗色模式：只改语义层 */
:root.dark {
  --color-primary: var(--blue-400);
  --color-bg: var(--gray-900);
  --color-text: var(--gray-50);
}

本教程网站的配色也是这么做的：所有颜色都是 CSS 变量，用 light-dark() 函数同时给出亮色和暗色的值，你可以在浏览器开发者工具里看到。 切换暗色模式只需要在 <html> 上切换 dark 类并记住用户的选择；Next.js 项目常用 next-themes，它还能避免页面加载时的“闪白”。

定制各家组件库

主流组件库都把自己的设计令牌暴露成了 CSS 变量或 JS 对象，覆盖它们就能换成你的品牌色：

import { createTheme, ThemeProvider } from '@mui/material/styles'

const theme = createTheme({
  cssVariables: true,                              // 令牌输出为 CSS 变量（--mui-palette-primary-main 等）
  colorSchemes: { light: true, dark: true },       // 同时生成亮色和暗色两套
  palette: { primary: { main: '#7c3aed' } },
  shape: { borderRadius: 8 },
})

<ThemeProvider theme={theme}><App /></ThemeProvider>

import { ConfigProvider, theme } from 'antd'

<ConfigProvider theme={{
  algorithm: isDark ? theme.darkAlgorithm : theme.defaultAlgorithm,   // 由算法推导出整套令牌
  token: { colorPrimary: '#7c3aed', borderRadius: 8 },               // 覆盖种子令牌
}}>
  <App />
</ConfigProvider>

@import "tailwindcss";

@theme {
  --color-brand: #7c3aed;     /* 自动生成 bg-brand、text-brand 等工具类 */
  --radius-card: 12px;
}

写一个基础组件

不管用不用组件库，你迟早要写自己的基础组件。下面这个按钮展示了一个好的基础组件应该具备的几个特征：

import type { ComponentProps, ReactNode } from 'react'
import { Slot } from '@radix-ui/react-slot'

type ButtonProps = ComponentProps<'button'> & {
  variant?: 'solid' | 'soft' | 'ghost'
  size?: 'sm' | 'md'
  loading?: boolean
  icon?: ReactNode
  asChild?: boolean           // 把样式和行为“套”在子元素上（比如一个 <Link>）
}

export function Button({
  variant = 'solid', size = 'md', loading = false, icon, asChild = false,
  className = '', disabled, children, ...rest        // 其余属性（type、onClick、aria-*、ref）原样透传
}: ButtonProps) {
  const Comp = asChild ? Slot : 'button'
  return (
    <Comp
      className={`btn btn-${variant} btn-${size} ${className}`}
      disabled={disabled || loading}
      aria-busy={loading || undefined}
      {...rest}
    >
      {loading ? <span className="spinner" aria-hidden="true" /> : icon}
      {children}
    </Comp>
  )
}

.btn {
  border-radius: var(--btn-radius, var(--radius));
  border: 1px solid var(--btn-color, var(--color-primary));
  padding: 6px 14px;
}
.btn-solid { background: var(--btn-color, var(--color-primary)); color: #fff; }
.btn-soft  { background: color-mix(in oklch, var(--btn-color, var(--color-primary)) 12%, transparent); }
.btn-ghost { background: transparent; }
.btn:focus-visible { outline: 3px solid var(--color-primary); outline-offset: 2px; }

<Button variant="soft" onClick={save}>保存</Button>

{/* asChild：渲染成路由链接，但外观和按钮一样 */}
<Button asChild><Link to="/tickets/new">新建工单</Link></Button>
🎨

变体而不是样式参数

用 variant="soft" 这样有限的选项，而不是让调用方传颜色、边框，保证全站一致。

🔗

属性透传

用 ...rest 收集没声明的属性，展开到 button 上。React 19 里 ref 也是普通 prop，同样会被透传。

🎯

样式钩子

组件内部只引用令牌，并留出 --btn-color 这样的组件级变量，特殊场景可以局部覆盖。

⌨

键盘友好

用真正的 <button>，保留 :focus-visible 焦点样式。下一节详细说。

✓ 变体多了，用 cva 管理类名

shadcn/ui 用 class-variance-authority（cva）把“变体 → 类名”写成一张表：cva('btn', { variants: { variant: { solid: '…', soft: '…' } } })， 再配合 tailwind-merge 合并调用方传入的 className，避免同类样式互相冲突。 asChild 也来自 Radix：Slot 会把 props 合并到唯一的子元素上，而不是多包一层 DOM。

无障碍：让每个人都能用

无障碍（accessibility，常缩写为 a11y）是指让使用屏幕阅读器、只用键盘、视力不佳的用户也能使用你的应用。 这不只是“照顾少数人”：手腕受伤的人、在阳光下看手机的人、喜欢键盘快捷操作的高级用户，都会受益。很多国家和地区对公共服务网站有无障碍的法律要求。

第一原则：优先用原生的语义化标签

✗ 看起来像按钮
<div className="btn" onClick={save}>保存</div>
{/* 不能用 Tab 聚焦，不能按回车触发，
     屏幕阅读器不知道它是按钮 */}
✓ 本来就是按钮
<button type="button" className="btn" onClick={save}>
  保存
</button>
{/* 焦点、键盘、读屏全部免费获得 */}

同理：跳转用 <a> / <Link>，输入框配 <label>，标题按层级用 h1~h6，列表用 ul/li。只有原生标签做不到时，才需要 ARIA。

复杂组件：把第 5 章的下拉菜单做完整

第 5 章的用户菜单处理了“点外面关闭”和 Esc。按照 WAI-ARIA 菜单按钮模式，一个完整的下拉菜单需要这样的键盘行为和 ARIA 属性：

把这套逻辑写成一个自定义 Hook，任何下拉菜单都能复用：

import { useState, useRef, useId, useEffect } from 'react'

export function useMenu(itemCount) {
  const [open, setOpen] = useState(false)
  const [focusIndex, setFocusIndex] = useState(0)
  const buttonRef = useRef(null)
  const itemRefs = useRef([])           // 在 JSX 里用 ref 回调收集
  const menuId = useId()                // SSR 安全的唯一 id

  // 菜单打开或焦点项变化后（DOM 已更新），把焦点移过去
  useEffect(() => {
    if (open) itemRefs.current[focusIndex]?.focus()
  }, [open, focusIndex])

  const wrap = (i) => (i + itemCount) % itemCount          // 首尾循环
  const show = (index = 0) => { setFocusIndex(wrap(index)); setOpen(true) }
  const hide = (returnFocus = true) => {
    setOpen(false)
    if (returnFocus) buttonRef.current?.focus()
  }

  const buttonProps = {
    ref: buttonRef, type: 'button',
    'aria-haspopup': 'menu', 'aria-expanded': open, 'aria-controls': menuId,
    onClick: () => (open ? hide() : show()),
    onKeyDown: (e) => {
      if (['Enter', ' ', 'ArrowDown'].includes(e.key)) { e.preventDefault(); show(0) }
      if (e.key === 'ArrowUp') { e.preventDefault(); show(-1) }
    },
  }

  const menuProps = {
    id: menuId, role: 'menu',
    onKeyDown: (e) => {
      const actions = {
        ArrowDown: () => setFocusIndex((i) => wrap(i + 1)),
        ArrowUp: () => setFocusIndex((i) => wrap(i - 1)),
        Home: () => setFocusIndex(0),
        End: () => setFocusIndex(itemCount - 1),
        Escape: () => hide(),
        Tab: () => hide(false),         // 不阻止默认行为，让焦点自然移走
      }
      if (actions[e.key]) {
        if (e.key !== 'Tab') e.preventDefault()
        actions[e.key]()
      }
    },
  }

  const itemProps = (i) => ({
    role: 'menuitem', tabIndex: -1,
    ref: (el) => { itemRefs.current[i] = el },
  })

  return { open, hide, buttonProps, menuProps, itemProps }
}

import { useRef } from 'react'
import { useMenu } from '../hooks/useMenu.js'
import { useClickOutside } from '../hooks/useClickOutside.js'

const items = [{ label: '个人资料', to: '/profile' }, { label: '设置', to: '/settings' }, { label: '退出登录', action: 'logout' }]

export default function UserMenu() {
  const { open, hide, buttonProps, menuProps, itemProps } = useMenu(items.length)
  const wrapRef = useRef(null)
  useClickOutside(wrapRef, () => open && hide(false))      // 第 5 章写的 Hook

  return (
    <div className="user-menu" ref={wrapRef}>
      <button {...buttonProps}>我的账户</button>
      {open && (
        <ul {...menuProps}>
          {items.map((item, i) => (
            <li key={item.label} {...itemProps(i)}
                onClick={() => select(item)}
                onKeyDown={(e) => e.key === 'Enter' && select(item)}>
              {item.label}
            </li>
          ))}
        </ul>
      )}
    </div>
  )
}

这种“Hook 返回一组 props，组件负责展开”的写法叫 prop getters，React Aria、Downshift 等无障碍库都是这样设计的：逻辑归 Hook，结构和样式归你。

弹窗的焦点管理

第 3 章用 createPortal 做过浮层。一个合格的模态对话框还需要：

  1. 打开时把焦点移到对话框里（第一个可聚焦元素或标题），关闭时把焦点还给打开它的按钮；
  2. 焦点陷阱：按 Tab 时焦点只在对话框内循环，不会跑到背后的页面上；
  3. 按 Esc 关闭；背后的内容对读屏软件隐藏。

最省事的办法是直接用浏览器原生的 <dialog> 元素：showModal() 打开的对话框天然具备焦点陷阱、Esc 关闭和背景隔离：

import { useEffect, useRef, useId } from 'react'

export function Dialog({ open, onClose, title, children }) {
  const ref = useRef(null)
  const titleId = useId()

  useEffect(() => {
    const dialog = ref.current
    if (open && !dialog.open) dialog.showModal()
    else if (!open && dialog.open) dialog.close()
  }, [open])

  return (
    // onClose 在按 Esc 或调用 close() 时都会触发，让父组件的状态保持同步
    <dialog ref={ref} aria-labelledby={titleId} onClose={onClose}>
      <h2 id={titleId}>{title}</h2>
      {children}
      <button type="button" onClick={onClose}>关闭</button>
    </dialog>
  )
}

浏览器原生对话框关闭后，会自动把焦点还给打开它之前聚焦的元素。第 6 章的小屏幕弹窗就是这样实现的。

需要更复杂的交互（组合框、日期选择器、树形控件）时，不要从零实现键盘和 ARIA 逻辑，直接用 Radix、React Aria 这类 headless 库，它们已经按 WAI-ARIA 规范做好了。

无障碍检查清单与工具

检查项怎么做
只用键盘能完成所有操作拔掉鼠标走一遍主要流程；焦点样式要清晰可见（不要随手 outline: none）
图片有替代文字有意义的图片写 alt，装饰性图片 alt=""
表单控件有标签<label for> 或 aria-label；错误信息用 aria-describedby 关联到输入框
颜色对比度足够正文至少 4.5:1；不要只靠颜色传达信息（错误除了变红还要有文字）
动态内容会被读出Toast、表单提交结果放进 aria-live="polite" 的区域
路由切换后焦点合理单页应用换页后，把焦点移到新页面的 h1，并更新 document.title

用 Storybook 开发组件

基础组件多了以后，需要一个地方集中展示“每个组件有哪些状态”：给设计师验收、给同事查用法、给自己单独调试。 Storybook 就是这样一个独立运行的组件工作台，React + Vite 是它支持得最好的组合： 

npm create storybook@latest    # 自动识别 React + Vite 项目并完成配置
npm run storybook              # 在 6006 端口打开

每个组件写一个 .stories.js 文件，导出若干个“故事”，每个故事就是组件的一种状态：

import { Button } from './Button'

export default {
  title: 'Base/Button',
  component: Button,
  tags: ['autodocs'],                  // 根据 props 自动生成文档页
  args: { children: '保存' },
  argTypes: {
    variant: { control: 'select', options: ['solid', 'soft', 'ghost'] },
  },
}

export const Solid = { args: { variant: 'solid' } }
export const Soft = { args: { variant: 'soft' } }
export const Loading = { args: { loading: true } }
✓ 更轻量的选择

Storybook 功能强大但依赖较多。如果只想要一个简单的组件展示页，可以看看基于 Vite 的 Ladle（兼容 Storybook 的故事格式），或者干脆在项目里建一个仅开发环境可访问的 /playground 路由。

小结

主题要点
设计系统令牌 → 基础组件 → 业务组件 → 页面，下层越稳定越好
选型贴近现成风格选 MUI / Ant Design / Mantine；品牌感强选 shadcn/ui 或 Radix / React Aria
样式方案运行时 CSS-in-JS 有开销且只能在客户端；零运行时 / CSS 变量 / Tailwind 对 SSR 更友好
主题原始 / 语义 / 组件三层令牌；暗色模式只改语义层；用组件库的 Theme / ConfigProvider 覆盖
基础组件有限的变体、...rest 透传、asChild、只引用令牌
无障碍优先原生标签；复杂组件按 WAI-ARIA 模式实现键盘和焦点（prop getters）；用原生 <dialog>；工具 + 真实读屏测试
文档Storybook：每个状态一个故事，自动生成文档和无障碍检查
