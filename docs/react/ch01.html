第 1 章

初识 React 19

React 是一个用来构建用户界面的 JavaScript 库。这一章不装任何工具，只用一个 HTML 文件， 就让页面跟着数据自动变化，顺便弄清 React 最核心的一句话：界面是状态的函数。

本章目标

  • 理解“声明式 UI”和 UI = f(state) 的含义
  • 知道 React 是“库”，以及一个完整应用还需要哪些配套工具
  • 认识 JSX：它长得像 HTML，其实是 JavaScript
  • 用 createRoot 渲染第一个组件，用 useState 让它动起来
  • 理解“受控输入框”：React 里双向绑定是怎么实现的

为什么需要 React

先看一个最普通的需求：输入框里打什么，下面那行字就显示什么。不用任何框架，你得这样写：

<input id="box">
<p id="out"></p>

<script>
  const box = document.getElementById('box')
  const out = document.getElementById('out')
  box.addEventListener('input', () => {
    out.textContent = box.value     // 每次都要自己去改 DOM
  })
</script>

两个元素还好。真实页面有几百个元素、几十种数据，某个数据一变，要记得同步修改好几处 DOM，漏掉一处就是 bug。 React 的思路是：你不要去“改”界面，你只需要描述“在某个状态下，界面应该长什么样”，剩下的交给 React。

这种写法叫声明式（描述结果），与之相对的手动改 DOM 叫命令式（描述步骤）。React 的核心特点：

🧩

组件

界面由一个个组件拼成。组件就是一个返回界面描述的 JavaScript 函数。

📝

JSX

在 JS 里直接写类似 HTML 的标记，逻辑和结构放在一起，可以使用 JS 的全部能力。

➡️

单向数据流

数据从父组件流向子组件，状态的变化路径清晰可追踪。

🌐

庞大的生态

路由、状态管理、动画、测试、服务端渲染……几乎每个方向都有成熟的方案，React Native 还能做原生 App。

React 是“库”，不是“全家桶”

React 本身只负责一件事：把状态变成界面。路由、数据请求、状态管理、构建工具都不在 React 里，需要从社区选择。 这既是它灵活的原因，也是初学者常感到“选择困难”的原因。本教程会为每一项给出一个当下主流、稳妥的选择：

React 的成长史

⚠ 网上的老资料要小心

你会搜到大量用 class App extends React.Component、this.setState 写的教程，以及用 create-react-app 创建项目的教程。 class 组件仍然能用但已不推荐；Create React App 已在 2025 年被官方弃用。本教程全部使用函数组件 + Hooks，项目用 Vite 创建。

ⓘ 读过本站 Vue 版的话

两个框架要解决的问题相同，但思路不同：Vue 会自动追踪你用了哪些数据，数据一变就精确更新；React 则是状态一变就重新执行组件函数，再比较前后两次结果。 这个差异会贯穿整本教程。附录有一份逐项对照表。

一分钟上手

React 的组件通常用 JSX 编写，而浏览器不认识 JSX，正式项目会用构建工具（第 3 章起使用 Vite）把它编译成普通 JS。 为了让你第一时间看到效果，本章和下一章先用一个“学习专用”的办法：在浏览器里用 Babel 即时编译 JSX。 

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <title>React 上手</title>

  <!-- ① import map：告诉浏览器 'react' 这些名字去哪里下载 -->
  <script type="importmap">
  {
    "imports": {
      "react": "https://esm.sh/react@19.2.0",
      "react-dom/client": "https://esm.sh/react-dom@19.2.0/client?external=react"
    }
  }
  </script>

  <!-- ② Babel：在浏览器里把 JSX 编译成 JS（仅用于学习） -->
  <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
</head>
<body>
  <div id="root"></div>

  <!-- ③ type="text/babel"：交给 Babel 编译；data-type="module"：支持 import -->
  <script type="text/babel" data-type="module" data-presets="react">
    import React from 'react'
    import { createRoot } from 'react-dom/client'

    console.log('React 版本：', React.version)
  </script>
</body>
</html>
⚠ 浏览器内编译只适合学习

Babel 有好几 MB，而且每次打开页面都要现场编译，非常慢。它也只能编译页面里内联的脚本，没法编译被 import 的其他 .jsx 文件。 所以第 3 章做多文件的游戏时，我们会换成 Vite。正式项目永远在构建阶段编译 JSX。

ⓘ React 19 不再提供 UMD 文件

老教程里常见的 <script src=".../react.development.js"> 会提供一个全局变量 React。React 19 移除了这种 UMD 构建， 在浏览器里直接使用需要通过 ES 模块（比如 esm.sh 这类 CDN）。这也是上面用 import map 的原因。

第一个组件

在 text/babel 脚本里写一个组件，并把它渲染到 #root：

import React from 'react'
import { createRoot } from 'react-dom/client'

// 组件：一个首字母大写、返回 JSX 的函数
function App() {
  const message = 'Hello React!'
  return <p>{message}</p>
}

// 在 #root 上创建一个 React 根节点，并渲染 App
const root = createRoot(document.getElementById('root'))
root.render(<App />)

页面上会显示 Hello React!。这几行代码里有三个关键点：

  1. 组件就是函数：名字必须大写开头（App），返回要显示的内容。
  2. 花括号 { }：在 JSX 里嵌入任意 JS 表达式，比如 {message}、{1 + 1}、{user.name.toUpperCase()}。
  3. createRoot(...).render(...)：React 接管 #root 元素，从此它里面的 DOM 都由 React 管理。

JSX：看起来像 HTML 的 JavaScript

JSX 不是模板语言，它会被编译成普通的函数调用。下面两段代码完全等价：

你写的 JSX
<button className="primary" onClick={save}>
  保存 {count} 项
</button>
编译后的 JS
jsx('button', {
  className: 'primary',
  onClick: save,
  children: ['保存 ', count, ' 项'],
})

因为它本质是 JS，所以有几条和 HTML 不同的规则，初学者最容易踩：

规则HTMLJSX
CSS 类名class="a"className="a"（class 是 JS 关键字）
label 的 forfor="x"htmlFor="x"
属性命名onclick、tabindex驼峰：onClick、tabIndex
内联样式style="font-size:14px"对象：style={{ fontSize: 14 }}
标签闭合<img>、<br>必须闭合：<img />、<br />
根元素随意必须只返回一个根；多个元素用 <>…</>（Fragment）包起来
注释<!-- -->{/* 注释 */}
✓ 花括号里只能放表达式

{ok ? '是' : '否'}、{list.length}、{format(date)} 都可以；{if (ok) {...}}、{for (...)} 这种语句不行。 需要条件就用三元运算或 &&，需要循环就用 map —— 下一章会大量用到。

🔍 为什么要用 JSX？

React 认为，“渲染逻辑”和“界面结构”本来就是紧密耦合的（按钮显不显示、列表怎么排，都依赖数据），与其把它们拆进模板和脚本两个文件， 不如都放在 JS 里，用 JS 本身的 if、map、变量和函数来组织。代价是要习惯这些和 HTML 不同的写法。

状态：useState

上面的 message 是个普通变量，改了它界面也不会变。要让界面能“变”，需要状态。 useState 是 React 最基础的 Hook（以 use 开头的特殊函数）： 

import React, { useState } from 'react'

function Counter() {
  // useState(初始值) 返回一对：[当前值, 修改它的函数]
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      点了 {count} 次
    </button>
  )
}
★ 理解“重新渲染”

每次状态改变，React 都会重新调用整个组件函数，得到一份新的界面描述，再和上一次比较，只把差异应用到真实 DOM 上。 组件函数里的普通变量每次都会重新创建，只有用 useState 存的值会被 React 记住。这是理解 React 的钥匙。

⚠ 不要直接改状态变量

count = count + 1 不会有任何效果：React 不知道它变了，也不会重新渲染。永远通过 setCount 修改。 另外，调用 setCount 之后，当前这次渲染里的 count 依然是旧值，新值要到下一次渲染才看得到。

Hooks 的两条规则

  • 只在组件（或自定义 Hook）的顶层调用：不要放在 if、循环或普通嵌套函数里。React 靠调用顺序来区分每个 useState。
  • 只在 React 函数组件或自定义 Hook 中调用：普通函数里不能用。

受控输入框

现在实现开头那个“输入框 → 文字”的例子。React 里没有自动的双向绑定，而是把输入框的值交给状态控制： value 来自状态，用户输入时在 onChange 里更新状态。这叫受控组件： 

function App() {
  const [message, setMessage] = useState('Hello React!')

  return (
    <div>
      <p>{message}</p>
      <input
        value={message}                                 // 状态 → 输入框
        onChange={(e) => setMessage(e.target.value)}   // 输入框 → 状态
      />
    </div>
  )
}
ⓘ 为什么不做自动双向绑定

受控写法多写了一行，但好处是所有修改都经过你的代码：可以顺手做校验、格式化（比如自动转大写），也能清楚地知道数据是在哪里改的。 只写 value 不写 onChange，输入框会变成“只读”，React 还会在控制台给出警告。

✓ 为什么要 import React

浏览器里的 Babel 默认把 JSX 编译成 React.createElement(...)，所以作用域里需要有 React 这个变量。 用 Vite 等构建工具时会使用新的“自动 JSX 运行时”，就不再需要这一行了。

小结

  • React 是一个负责“把状态变成界面”的库，核心思想是 UI = f(state)。
  • 组件是返回 JSX 的函数；JSX 会被编译成普通的 JS 函数调用。
  • createRoot(el).render(<App />) 启动应用。
  • useState 保存状态；调用 setter 会让组件重新执行一遍并更新 DOM。
  • 表单用“受控组件”：value + onChange。
  • 浏览器内用 Babel 编译 JSX 只适合学习；从第 3 章开始使用 Vite。
