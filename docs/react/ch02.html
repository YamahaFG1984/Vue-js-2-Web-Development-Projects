第 2 章 · 项目一

Markdown 笔记本

第一个完整应用：一个能实时预览 Markdown、支持多条笔记、刷新后自动恢复的笔记本。 做完它，你就掌握了 React 日常开发里最常用的那批基本功：状态、派生数据、副作用、列表、条件渲染，以及最重要的“不可变更新”。

本章目标

  • 区分“状态”和“可以算出来的数据”，知道什么时候用 useMemo
  • 用 useEffect 把状态同步到 localStorage，理解依赖数组
  • 用 map + key 渲染列表，用 && 和三元运算做条件渲染
  • 掌握数组和对象的不可变更新
  • 知道 dangerouslySetInnerHTML 的风险以及如何安全地显示 HTML
  • 理解“状态是快照”，避开连续更新、过期闭包、Strict Mode 双重执行这些常见陷阱补充
  • 用 useRef 和 ref 回调操作 DOM，实现编辑器自动聚焦补充

我们要做什么

  • 用户可以用 Markdown 写笔记，右侧实时预览；
  • 可以创建多条笔记，可以重命名、删除、收藏（收藏的排在前面）；
  • 底部状态栏显示创建时间、行数、词数、字符数；
  • 刷新页面后，笔记和上次选中的那条都还在。

先做单条笔记的“编辑器 + 预览”，再扩展成多条笔记的笔记本。

笔记编辑器

编辑器就是一个受控的 <textarea>：

import React, { useState } from 'react'
import { createRoot } from 'react-dom/client'

function Notebook() {
  const [content, setContent] = useState('这是一条笔记。')

  return (
    <div className="notebook">
      <section className="main">
        <textarea value={content} onChange={(e) => setContent(e.target.value)} />
      </section>
    </div>
  )
}

createRoot(document.getElementById('root')).render(<Notebook />)
ⓘ 复选框、下拉框也一样

所有表单元素都用“值 + onChange”受控：文本框和下拉框用 value，复选框用 checked 读 e.target.checked。 注意 React 的 onChange 在每次输入时都会触发（和原生 input 事件一样），而不是像原生 change 那样失去焦点才触发。

预览面板

派生数据：直接在渲染时计算

预览的 HTML 完全由 content 决定。初学者常犯的错误是再开一个状态存它，然后想办法同步。在 React 里， 能由现有状态算出来的东西，就不要放进状态，直接在渲染时算： 

import { marked } from 'marked'

function Notebook() {
  const [content, setContent] = useState('这是一条笔记。')

  // 每次渲染都会重新算一遍：content 变了，它自然跟着变
  const notePreview = marked.parse(content)
  // ...
}

useMemo：缓存昂贵的计算

组件每次重新渲染（比如以后修改了别的状态）都会重新解析一次 Markdown。笔记很长时，这可能有点浪费。 useMemo 可以缓存计算结果，只有依赖变化时才重新计算： 

import React, { useState, useMemo } from 'react'

const notePreview = useMemo(
  () => marked.parse(content),   // 计算函数
  [content],                     // 依赖：只有 content 变了才重新计算
)
✓ 不要过早优化

大多数计算都很便宜，直接算就好。只有确实昂贵（解析大段文本、处理上千条数据）时才需要 useMemo。 第 4 章会介绍 React Compiler，它能在构建时自动帮你加上这类缓存，以后连 useMemo 都很少需要手写了。

显示 HTML：dangerouslySetInnerHTML

先试着直接显示 {notePreview}，你会发现预览区显示的是带标签的原始文本：

<p>我是 <strong>粗体</strong>！</p>

这是 React 故意的：JSX 中的 { } 总会转义 HTML，以防止 XSS（跨站脚本）攻击。 要把字符串当 HTML 插入，必须用一个名字很吓人的属性 —— dangerouslySetInnerHTML： 

<aside className="preview" dangerouslySetInnerHTML={{ __html: notePreview }} />
⚠ 用户写的 Markdown 必须先消毒

Markdown 允许内嵌原始 HTML，marked 也不会帮你过滤危险标签。笔记一旦可以分享给别人看，这就是一个真实的 XSS 漏洞。 正确做法是先用 DOMPurify 消毒： 

import DOMPurify from 'dompurify'

const notePreview = useMemo(
  () => DOMPurify.sanitize(marked.parse(content)),
  [content],
)
✓ 工程化项目里的更好选择

第 3 章起使用 Vite 后，可以用 react-markdown：它把 Markdown 直接转换成 React 元素， 根本不经过 HTML 字符串，默认就是安全的：<Markdown>{content}</Markdown>。

保存笔记：useEffect

现在刷新页面笔记就没了。我们要在 content 变化时把它写进 localStorage。 写 localStorage 不是“计算界面”，而是和 React 之外的世界打交道 —— 这叫副作用（effect）。 

import React, { useState, useMemo, useEffect } from 'react'

useEffect(() => {
  localStorage.setItem('content', content)
}, [content])   // 依赖数组：content 变化后执行

打开开发者工具的 Application（或“存储”）面板，在 Local Storage 下能看到 content 条目随着输入实时更新。

⚠ 依赖数组要写全

effect 里用到的所有来自组件的值（状态、props、函数）都应该写进依赖数组，否则 effect 会读到“过期”的旧值。 第 4 章配置的 ESLint 插件 eslint-plugin-react-hooks 会自动检查这一点，不要凭感觉删依赖。

清理函数与组件的“一生”

effect 可以返回一个清理函数，React 会在下一次执行 effect 之前、以及组件被移除时调用它。用于取消订阅、清除定时器等：

useEffect(() => {
  const timer = setInterval(() => console.log('滴答'), 1000)
  return () => clearInterval(timer)    // 清理：防止组件消失后定时器还在跑
}, [])
🔍 你可能不需要 effect（点击展开）

effect 是 React 里最常被滥用的 Hook。判断标准：这段代码是因为“组件显示出来了”而要执行，还是因为“用户做了某个操作”而要执行？ 如果是后者，直接写在事件处理函数里更好。比如保存笔记，也可以写成： 

function handleChange(e) {
  setContent(e.target.value)
  localStorage.setItem('content', e.target.value)   // 用户输入时保存
}

本章用 effect，是因为后面会有很多地方修改笔记（编辑、改名、收藏、删除），用一个 effect 统一“保持 localStorage 和状态同步”更省事。 官方文档有一篇专门的文章《你可能不需要 Effect》，非常值得一读。

加载已保存的笔记

打开页面时，从 localStorage 读出上次的内容作为初始值：

const [content, setContent] = useState(
  () => localStorage.getItem('content') || '你可以用 **Markdown** 写作'
)
ⓘ 为什么传一个函数？

useState(初始值) 的初始值只在第一次渲染时使用，但如果写成 useState(localStorage.getItem(...))， 这个读取操作每次渲染都会执行（只是结果被丢弃）。传一个函数（惰性初始化），React 只会在第一次调用它。 a || b 在 a 为 falsy（null、空字符串等）时取 b，第一次打开时 getItem 返回 null，于是用默认文字。

多条笔记

数据结构

每条笔记是一个对象，所有笔记放在 notes 数组里，另外用 selectedId 记录选中的是哪一条：

const [notes, setNotes] = useState(() => JSON.parse(localStorage.getItem('notes')) || [])
const [selectedId, setSelectedId] = useState(() => localStorage.getItem('selected-id'))

// 派生：渲染时直接查
const selectedNote = notes.find((note) => note.id === selectedId)

不可变更新：React 最重要的习惯

新建一条笔记。初学者的第一反应是 notes.push(note) —— 但这在 React 里不会触发更新：

常用的不可变操作速查：

目的✗ 会修改原数据✓ 返回新数据
添加arr.push(x)[...arr, x]
删除arr.splice(i, 1)arr.filter(n => n.id !== id)
修改某一项arr[i].title = 't'arr.map(n => n.id === id ? { ...n, title: 't' } : n)
排序arr.sort(fn)arr.toSorted(fn)
修改对象属性obj.a = 1{ ...obj, a: 1 }
 
function addNote() {
  const time = Date.now()
  const note = {
    id: crypto.randomUUID(),       // 浏览器内置的随机唯一 id
    title: '新笔记 ' + (notes.length + 1),
    content: '**你好！** 这个笔记本支持 [Markdown](https://commonmark.org/help/) 格式！',
    created: time,
    favorite: false,
  }
  setNotes([...notes, note])
  setSelectedId(note.id)
}

事件与属性

按钮的点击用 onClick，鼠标悬停提示用 title 属性，值可以是任意表达式：

<aside className="side-bar">
  <div className="toolbar">
    <button onClick={addNote} title={`已有 ${notes.length} 条笔记`}>
      <i className="material-icons">add</i> 新建笔记
    </button>
  </div>
</aside>
⚠ 传函数，不要调用函数

onClick={addNote} 是把函数交给 React，点击时才调用；onClick={addNote()} 则是渲染时就立刻调用了， 还会把返回值（undefined）当作处理函数。需要传参时写成箭头函数：onClick={() => selectNote(note.id)}。

渲染列表：map + key

JSX 里没有循环语句，列表用数组的 map 把每条数据变成一个元素：

<div className="notes">
  {notes.map((note) => (
    <div key={note.id} className="note" onClick={() => setSelectedId(note.id)}>
      {note.title}
    </div>
  ))}
</div>
★ key 的规则
  • 同一个列表里的 key 必须唯一，且对同一条数据保持稳定。用数据里的 id，不要用数组下标（排序或删除后下标会变，导致状态错乱）。
  • key 写在 map 直接返回的那个元素上。忘写时 React 会在控制台警告。
  • key 不会作为 prop 传给组件，组件内部读不到它。

动态 class 与条件渲染

选中的笔记要加上 selected 类。className 就是一个字符串，用模板字符串拼出来即可：

<div
  key={note.id}
  className={`note ${note.id === selectedId ? 'selected' : ''}`}
  onClick={() => setSelectedId(note.id)}
>
✓ 类名多了用 clsx

工程化项目中常用小工具 clsx：className={clsx('note', { selected: isSel, favorite: note.favorite })}，写法类似对象形式的条件类名。

没有选中笔记时，编辑器和预览都不应该显示（否则 selectedNote.content 会报错）。JSX 中的条件渲染有三种常用写法：

写法用途
{cond && <A />}条件成立才显示
{cond ? <A /> : <B />}二选一
if (!cond) return null在组件开头提前返回，整个组件不渲染
 
{selectedNote && (
  <>
    <section className="main">
      <textarea value={selectedNote.content} onChange={...} />
    </section>
    <aside className="preview" dangerouslySetInnerHTML={{ __html: notePreview }} />
  </>
)}
⚠ && 左边别放数字

{notes.length && <List />} 在没有笔记时会在页面上渲染出一个 0（因为 0 && … 的结果是 0，React 会显示数字）。 写成 {notes.length > 0 && …}。<>…</> 是 Fragment，用来把多个元素包成一个而不产生额外的 DOM。

编辑选中的笔记

编辑器修改的是数组中某一条笔记的 content，用 map 生成新数组。我们写一个通用的更新函数，后面改标题、收藏都能复用：

// 修改选中笔记的某些字段
function updateSelected(changes) {
  setNotes(notes.map((note) =>
    note.id === selectedId ? { ...note, ...changes } : note
  ))
}

<textarea
  value={selectedNote.content}
  onChange={(e) => updateSelected({ content: e.target.value })}
/>

预览也改成基于选中的笔记：

const notePreview = useMemo(
  () => selectedNote ? DOMPurify.sanitize(marked.parse(selectedNote.content)) : '',
  [selectedNote],
)

保存笔记列表和选中状态

useEffect(() => {
  localStorage.setItem('notes', JSON.stringify(notes))
}, [notes])

useEffect(() => {
  if (selectedId) localStorage.setItem('selected-id', selectedId)
  else localStorage.removeItem('selected-id')   // 不要把 null 存成字符串 "null"
}, [selectedId])
ⓘ 不需要“深度侦听”

因为我们每次修改都会创建新的 notes 数组，所以只要依赖 [notes]，任何修改（新增、改内容、改标题、删除）都能被 effect 察觉。 不可变更新让“检测变化”变得非常简单 —— 只需比较引用。

状态更新的几个常见陷阱补充

我们已经用了好几次 setNotes、setSelectedId。初学者遇到的“值明明改了却不对”“点了三次只加了一”，几乎都来自同一个误解： 以为调用 setX 会立刻修改变量 x。实际上，每一次渲染拿到的状态都是一张快照， setX 只是“预约”下一次渲染时使用的新值。

陷阱 1：基于旧值连续更新

新值依赖旧值时，传一个更新函数，React 会把最新的值作为参数传进来。我们的笔记本里也是一样：

// 能用，但依赖的是本次渲染的 notes 快照
setNotes([...notes, note])

// 更稳妥：不管之前排了多少次更新，都基于最新的数组
setNotes((prev) => [...prev, note])

在普通的点击事件里两种写法结果相同；但当更新发生在 setTimeout、await 之后，或同一个事件里要更新好几次时，更新函数才不会出错。养成习惯：新值由旧值算出来，就写更新函数。

陷阱 2：过期的闭包

函数会“记住”它被创建那次渲染里的变量。下面这个计时器永远停在 1：

✗ 闭包里的 seconds 永远是 0
useEffect(() => {
  const id = setInterval(() => {
    setSeconds(seconds + 1)   // 0 + 1，一直是 1
  }, 1000)
  return () => clearInterval(id)
}, [])   // 只在挂载时运行一次
✓ 用更新函数，不读外面的变量
useEffect(() => {
  const id = setInterval(() => {
    setSeconds((s) => s + 1)
  }, 1000)
  return () => clearInterval(id)
}, [])

另一种修法是把 seconds 写进依赖数组，但那样每秒都会清除并重建计时器。 第 4 章会配置 eslint-plugin-react-hooks，它会检查依赖数组，提醒你漏掉的变量。

陷阱 3：直接修改对象或数组

前面“不可变更新”一节说过：note.title = 'x'; setNotes(notes) 不会触发更新，因为数组的引用没变。 对象嵌套很深时，展开语法会写得很长，可以借助 Immer：在“草稿”上直接修改，它替你生成新对象。 

import { produce } from 'immer'

setNotes(produce((draft) => {
  const note = draft.find((n) => n.id === selectedId)
  note.title = '新标题'          // 看起来是修改，实际得到的是新数组和新对象
}))

陷阱 4：开发模式下 effect 跑了两次

用 Vite 创建的项目（第 4 章）会把应用包在 <StrictMode> 里。开发模式下，React 会故意挂载 → 卸载 → 再挂载一次组件， 所以你会看到 effect 执行了两次、请求发了两遍。这不是 bug，而是在检查你的 effect 有没有写好清理函数： 如果“执行、清理、再执行”之后行为和只执行一次一样，说明 effect 是正确的。生产构建不会重复执行。

✓ 一句话记住

读状态读到的是这次渲染的快照；想基于最新值更新，就给 setX 传函数；想改对象，就换一个新的。 如果你需要一个“改了不触发渲染、但随时能读到最新值”的变量，那是下一节的 useRef。

排序：收藏的排前面

排序结果也是派生数据。注意要用不修改原数组的 toSorted：

const sortedNotes = notes
  .toSorted((a, b) => a.created - b.created)        // 按创建时间
  .sort((a, b) => (a.favorite === b.favorite) ? 0   // 收藏优先（作用在新数组上，可以原地排）
                  : a.favorite ? -1 : 1)
⚠ 千万别在渲染时修改状态

如果写成 notes.sort(...)，就是在渲染过程中原地修改了状态数组。React 要求组件是“纯函数”：同样的输入，同样的输出，不改动任何外部数据。 违反这一点会导致难以追踪的 bug。toSorted、toReversed、with 这些 ES2023 新方法都返回新数组，正好适合 React。

列表改用 sortedNotes，并给收藏的笔记加上星标：

{sortedNotes.map((note) => (
  <div key={note.id}
       className={`note ${note.id === selectedId ? 'selected' : ''}`}
       onClick={() => setSelectedId(note.id)}>
    {note.favorite && <i className="icon material-icons">star</i>}
    {note.title}
  </div>
))}

状态栏

创建时间用浏览器自带的 Intl.DateTimeFormat 格式化；行数、词数、字符数都是派生数据：

// 放在组件外面：只创建一次
const dateFormatter = new Intl.DateTimeFormat('zh-CN', { dateStyle: 'short', timeStyle: 'short' })
const segmenter = new Intl.Segmenter('zh', { granularity: 'word' })

function StatusBar({ note }) {
  const text = note.content
  const lines = text.split(/\r\n|\r|\n/).length
  const words = [...segmenter.segment(text)].filter((s) => s.isWordLike).length
  const chars = [...text].length   // 展开后 emoji 也只算一个字符

  return (
    <div className="toolbar status-bar">
      <span className="date"><span className="label">创建于</span><span className="value">{dateFormatter.format(note.created)}</span></span>
      <span className="lines"><span className="label">行</span><span className="value">{lines}</span></span>
      <span className="words"><span className="label">词</span><span className="value">{words}</span></span>
      <span className="characters"><span className="label">字符</span><span className="value">{chars}</span></span>
    </div>
  )
}

这是我们第一个“子组件”：它接收一个 note 参数（叫 props），在父组件里这样使用：<StatusBar note={selectedNote} />。 function StatusBar({ note }) 用的是参数解构。下一章会系统地讲组件和 props。

🔍 为什么用 Intl.Segmenter 数词？

英文可以按空格切分单词，但中文没有空格，“我爱学习 React”会被数成 2 个词。Intl.Segmenter 是浏览器内置的分词器， 会把它切成“我 / 爱 / 学习 / React”共 4 个词。另外 '😀'.length 是 2，[...'😀'].length 才是 1。

自动聚焦：useRef 与 ref 回调补充

一个体验上的小改进：新建笔记后，光标应该直接落在编辑器里，用户可以立刻开始打字。 这需要拿到 <textarea> 的真实 DOM 元素，调用它的 focus() 方法。React 用 ref 把 DOM 元素交给你。

useRef：一个跨渲染保存的盒子

useRef(初始值) 返回一个对象 { current: 初始值 }。它和状态有两点不同： 修改 current 不会触发重新渲染，而且你读到的永远是最新值（不是快照）。 把它传给元素的 ref 属性，React 会在提交 DOM 后把元素放进 current，卸载时再设回 null。

在 effect 或事件处理函数里使用 ref（渲染过程中 DOM 还没更新，不要在那里读 current）：

import { useRef, useEffect } from 'react'

const editorRef = useRef(null)

// 选中的笔记变了 → DOM 更新完之后聚焦编辑器
useEffect(() => {
  editorRef.current?.focus()
}, [selectedId])

<textarea ref={editorRef} value={selectedNote.content} onChange={...} />

为什么放在 effect 里，而不是直接写在 addNote 的 setSelectedId 后面？ 因为如果之前没有选中任何笔记，编辑器还不存在，editorRef.current 是 null； 调用 setSelectedId 只是预约了下一次渲染，DOM 要等渲染提交后才出现。effect 正好在那之后运行。

ref 回调：把 DOM 行为做成可复用的小工具

ref 属性也可以接收一个函数：元素挂到页面上时，React 以元素为参数调用它。 React 19 起，这个函数还可以返回一个清理函数，在元素卸载时调用 —— 很适合封装“给元素加一点 DOM 行为”： 

// 定义在组件外面：函数引用保持不变，React 只会在挂载时调用它
const autoFocus = (el) => el?.focus()

// 带清理的例子：元素存在期间监听一个事件
function logScroll(el) {
  const onScroll = () => console.log(el.scrollTop)
  el.addEventListener('scroll', onScroll)
  return () => el.removeEventListener('scroll', onScroll)   // React 19：卸载时调用
}

<textarea key={selectedNote.id} ref={autoFocus} ... />

注意那个 key：切换笔记时，<textarea> 默认会被复用（只是内容变了），ref 回调不会再次调用。 给它一个随笔记变化的 key，每次切换都会创建一个新元素，于是每次都会自动聚焦 —— “改变 key 来强制重新创建”是 React 里很常用的技巧。

⚠ 别把 ref 回调写成内联箭头函数

ref={(el) => el?.focus()} 每次渲染都是一个新函数，React 会先用 null 调用旧函数、再用元素调用新函数 —— 结果是每次渲染都聚焦一次，用户在标题输入框里打字时，焦点会被抢回编辑器。所以要么定义在组件外面，要么用 useCallback 保持引用稳定。 简单场景也可以直接用 autoFocus 属性，效果相同。

ⓘ 把 ref 传给自己写的组件

React 19 之前，函数组件要用 forwardRef 包一层才能接收 ref。现在 ref 就是一个普通的 prop： function Editor({ ref, ...props }) { return <textarea ref={ref} {...props} /> }，父组件写 <Editor ref={editorRef} /> 即可。

把逻辑稍作拆分：Notebook 持有所有状态，StatusBar 只负责显示。

import React, { useState, useMemo, useEffect } from 'react'
import { createRoot } from 'react-dom/client'
import { marked } from 'marked'
import DOMPurify from 'dompurify'

const dateFormatter = new Intl.DateTimeFormat('zh-CN', { dateStyle: 'short', timeStyle: 'short' })
const segmenter = new Intl.Segmenter('zh', { granularity: 'word' })
// ref 回调：编辑器出现时自动获得焦点（定义在组件外，引用保持不变）
const autoFocus = (el) => el?.focus()

function StatusBar({ note }) {
  const text = note.content
  const lines = text.split(/\r\n|\r|\n/).length
  const words = [...segmenter.segment(text)].filter((s) => s.isWordLike).length
  const chars = [...text].length
  return (
    <div className="toolbar status-bar">
      <span className="date"><span className="label">创建于</span><span className="value">{dateFormatter.format(note.created)}</span></span>
      <span className="lines"><span className="label">行</span><span className="value">{lines}</span></span>
      <span className="words"><span className="label">词</span><span className="value">{words}</span></span>
      <span className="characters"><span className="label">字符</span><span className="value">{chars}</span></span>
    </div>
  )
}

function Notebook() {
  // ---------- 状态（只存无法推导的数据） ----------
  const [notes, setNotes] = useState(() => JSON.parse(localStorage.getItem('notes')) || [])
  const [selectedId, setSelectedId] = useState(() => localStorage.getItem('selected-id'))

  // ---------- 派生数据 ----------
  const selectedNote = notes.find((note) => note.id === selectedId)
  const sortedNotes = notes
    .toSorted((a, b) => a.created - b.created)
    .sort((a, b) => (a.favorite === b.favorite) ? 0 : a.favorite ? -1 : 1)
  const notePreview = useMemo(
    () => selectedNote ? DOMPurify.sanitize(marked.parse(selectedNote.content)) : '',
    [selectedNote],
  )

  // ---------- 副作用：与 localStorage 同步 ----------
  useEffect(() => {
    localStorage.setItem('notes', JSON.stringify(notes))
  }, [notes])

  useEffect(() => {
    if (selectedId) localStorage.setItem('selected-id', selectedId)
    else localStorage.removeItem('selected-id')
  }, [selectedId])

  // ---------- 事件处理 ----------
  function addNote() {
    const note = {
      id: crypto.randomUUID(),
      title: '新笔记 ' + (notes.length + 1),
      content: '**你好！** 这个笔记本支持 [Markdown](https://commonmark.org/help/) 格式！',
      created: Date.now(),
      favorite: false,
    }
    setNotes((prev) => [...prev, note])
    setSelectedId(note.id)
  }

  function updateSelected(changes) {
    setNotes((prev) => prev.map((note) => note.id === selectedId ? { ...note, ...changes } : note))
  }

  function removeNote() {
    if (selectedNote && confirm('确定删除这条笔记吗？')) {
      setNotes(notes.filter((note) => note.id !== selectedId))
      setSelectedId(null)
    }
  }

  // ---------- 界面 ----------
  return (
    <div id="notebook">
      <aside className="side-bar">
        <div className="toolbar">
          <button onClick={addNote} title={`已有 ${notes.length} 条笔记`}>
            <i className="material-icons">add</i> 新建笔记
          </button>
        </div>
        <div className="notes">
          {sortedNotes.map((note) => (
            <div key={note.id}
                 className={`note ${note.id === selectedId ? 'selected' : ''}`}
                 onClick={() => setSelectedId(note.id)}>
              {note.favorite && <i className="icon material-icons">star</i>}
              {note.title}
            </div>
          ))}
        </div>
      </aside>

      {selectedNote && (
        <>
          <section className="main">
            <div className="toolbar">
              <input value={selectedNote.title} placeholder="笔记标题"
                     onChange={(e) => updateSelected({ title: e.target.value })} />
              <button onClick={() => updateSelected({ favorite: !selectedNote.favorite })} title="收藏">
                <i className="material-icons">{selectedNote.favorite ? 'star' : 'star_border'}</i>
              </button>
              <button onClick={removeNote} title="删除笔记">
                <i className="material-icons">delete</i>
              </button>
            </div>
            <textarea key={selectedNote.id} ref={autoFocus} value={selectedNote.content}
                      onChange={(e) => updateSelected({ content: e.target.value })} />
            <StatusBar note={selectedNote} />
          </section>
          <aside className="preview" dangerouslySetInnerHTML={{ __html: notePreview }} />
        </>
      )}
    </div>
  )
}

createRoot(document.getElementById('root')).render(<Notebook />)
🔍 进阶：用 useReducer 整理状态逻辑（点击展开）

事件处理函数越来越多，而且它们都在“计算下一个 notes 数组”。useReducer 可以把这些逻辑集中到一个纯函数里： 组件只描述发生了什么（dispatch 一个 action），reducer 负责计算新状态。下一章的游戏会正式使用它。 

function notesReducer(notes, action) {
  switch (action.type) {
    case 'added':   return [...notes, action.note]
    case 'updated': return notes.map((n) => n.id === action.id ? { ...n, ...action.changes } : n)
    case 'removed': return notes.filter((n) => n.id !== action.id)
    default: throw new Error('未知的 action：' + action.type)
  }
}

const [notes, dispatch] = useReducer(notesReducer, null, () => JSON.parse(localStorage.getItem('notes')) || [])

dispatch({ type: 'updated', id: selectedId, changes: { title: '新标题' } })

小结

概念写法一句话
状态useState只存无法推导的数据；初始值昂贵时传函数
派生数据渲染时直接计算不要放进状态
缓存计算useMemo(fn, deps)只在确实昂贵时使用
副作用useEffect(fn, deps)与外部系统同步；可返回清理函数
不可变更新[...a, x]、map、filter、{ ...o }改了就换一个新的
事件onClick={fn}传函数，不要调用函数
列表arr.map(x => <li key={x.id}>)key 用稳定唯一的 id
条件&&、三元、提前 return null小心 0 &&
原始 HTMLdangerouslySetInnerHTML用户内容务必先消毒
更新函数 补充setX(prev => …)状态是快照；新值依赖旧值时传函数
操作 DOM 补充useRef + effect，或 ref 回调ref 改了不触发渲染
