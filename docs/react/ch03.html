第 3 章 · 项目二

城堡决斗：浏览器卡牌游戏

这次做一个双人回合制卡牌游戏：两位玩家各守一座城堡，用行动卡把对手的粮食或生命打到零。 借这个项目，我们系统学习 React 的组件：props、回调、children，再用 useReducer 管理复杂的游戏状态， 用 Motion 做进出场和列表动画，用 SVG 画会动的旗帜。

本章目标

  • 把界面拆成组件树；父传子用 props，子传父用回调函数
  • 用 children 让组件接收任意内容，用“组件映射表”动态切换组件
  • 用 useReducer + Immer 管理复杂状态，理解 reducer 为什么必须是纯函数
  • 用 Motion 的 AnimatePresence 和 layout 做进出场与列表动画，再次理解 key
  • 写自定义 Hook；用 useRef 直接操作 DOM，做不触发重新渲染的高频动画

游戏规则

  • 两位玩家轮流行动，每人开局有 10 点生命、10 点粮食和 5 张手牌；生命和粮食都不能超过 10。
  • 粮食或生命降到 0 即失败；两人可能同时失败。
  • 每个回合，当前玩家必须且只能打出一张牌，打出的牌进入弃牌堆。
  • 每个回合开始时抽一张牌（每人的第一回合除外），所以回合开始时手里总是 5 张。抽牌堆空了就把弃牌堆洗回去。
  • 卡牌可以改变双方的生命和粮食，有的还能让某个玩家跳过回合。

三种浮层会轮流盖住手牌：“轮到你了”（提醒两人交换设备）、“对手出了什么”、“游戏结束”（点击重新开始）。

组件与组件树

组件是 React 应用的积木。一个组件应该小、职责单一、可复用。整个游戏会是这样一棵组件树：

第一个组件：顶栏

顶栏要显示两位玩家的名字和回合数，还有一个箭头指向当前玩家。组件需要的数据通过 props 从父组件传入。 props 就是组件函数的第一个参数（一个对象），通常直接解构： 

export default function TopBar({ players, currentPlayerIndex, turn }) {
  return (
    <div className={`top-bar player-${currentPlayerIndex}`}>
      <div className="player p0">{players[0].name}</div>
      <div className="turn-counter">
        <img className="arrow" src="/svg/turn.svg" />
        <div className="turn">第 {turn} 回合</div>
      </div>
      <div className="player p1">{players[1].name}</div>
    </div>
  )
}

父组件像写 HTML 属性一样传值，花括号里是任意 JS 表达式：

<TopBar players={state.players} currentPlayerIndex={state.currentPlayerIndex} turn={state.turn} />
⚠ props 是只读的

组件绝不能修改自己的 props（props.turn = 4）。React 要求组件像纯函数一样：相同的 props，渲染出相同的结果。 子组件想改变数据，就调用父组件传下来的回调，由拥有这份状态的组件去改。

卡牌组件：回调让子组件“通知”父组件

每个卡牌定义有 id、type（决定颜色）、title、description（HTML 文本）、可选的 note，以及出牌时调用的 play(player, opponent)。

export default function GameCard({ def, onPlay }) {
  return (
    <div className={`card type-${def.type}`} onClick={onPlay}>
      <div className="title">{def.title}</div>
      <img className="separator" src="/svg/card-separator.svg" />
      <div className="description">
        <div dangerouslySetInnerHTML={{ __html: def.description }} />
      </div>
      {def.note && (
        <div className="note">
          <div dangerouslySetInnerHTML={{ __html: def.note }} />
        </div>
      )}
    </div>
  )
}
ⓘ 这里用 dangerouslySetInnerHTML 是安全的

卡牌文字是我们自己写在 cards.js 里的，不来自用户输入。多套一层 div 是为了用 flexbox 垂直居中。

onPlay 是一个回调 prop。卡牌组件不关心“出牌之后发生什么”，它只负责在被点击时通知父组件。 将来要加“键盘选中 + 回车出牌”，也只需在卡牌组件内部再调用一次 onPlay。

✓ 命名约定

回调 prop 以 on 开头（onPlay、onClose），父组件里处理它的函数常以 handle 开头（handlePlayCard）。

游戏状态：useReducer

游戏有很多相互关联的状态：回合数、两位玩家的数值和手牌、当前玩家、牌堆、当前浮层……如果全用 useState，每个事件处理函数都要同时修改好几个状态，很容易出错。 这正是 useReducer 的用武之地：把所有“状态如何变化”的规则集中到一个函数里。

状态的形状

import { produce } from 'immer'
import { cardsById, pile } from './cards.js'

export const maxHealth = 10
export const maxFood = 10
const handSize = 5

function createPlayer(name) {
  return {
    name,
    food: 10,
    health: 10,
    skipTurn: false,       // 下回合是否要被跳过
    skippedTurn: false,    // 上回合是否被跳过了
    hand: [],              // [{ uid, id, def }]
    lastPlayedCardId: null,
    dead: false,
  }
}

// 创建开局状态：两位玩家各抽 5 张
// （初始化函数里用随机数没问题：即使 StrictMode 调用它两次，React 也只采用其中一次的结果）
export function createInitialState() {
  return produce({
    turn: 1,
    players: [createPlayer('克里维斯的安妮'), createPlayer('秃头威廉')],
    currentPlayerIndex: Math.round(Math.random()),  // 随机决定先手
    activeOverlay: 'player-turn',
    drawPile: { ...pile },                          // { 卡牌id: 张数 }
    discardPile: {},
    canPlay: false,
    playingCard: null,
    pendingDraw: false,                             // 是否等待抽牌（见后文）
    nextUid: 0,
  }, (draft) => {
    for (const player of draft.players) {
      for (let i = 0; i < handSize; i++) drawCard(draft, player, Math.random())
    }
  })
}

// 两个辅助函数：当前玩家、对手
export const currentPlayer = (s) => s.players[s.currentPlayerIndex]
export const currentOpponent = (s) => s.players[1 - s.currentPlayerIndex]

Immer：用“修改”的写法得到不可变的结果

上一章我们手写 { ...note, ...changes } 做不可变更新。游戏状态嵌套很深（玩家 → 手牌数组），而且 cards.js 里每张牌的 play 函数都是这样写的： player.food -= 1; opponent.health -= 1 —— 直接修改对象。手写不可变更新会非常痛苦。

Immer 解决了这个问题：你在一个“草稿（draft）”上随便修改，它会自动生成一份新的不可变状态，没改动的部分保持原样（结构共享）：

把 reducer 包进 produce，就能在里面直接写修改语句。先写两个牌堆相关的辅助函数：

function pileCount(p) {
  return Object.values(p).reduce((sum, n) => sum + n, 0)
}

// 从抽牌堆按张数加权随机抽一张，放进玩家手牌。random 是 0~1 的随机数，由外部传入
function drawCard(draft, player, random) {
  if (pileCount(draft.drawPile) === 0) {
    draft.drawPile = draft.discardPile          // 抽牌堆空了：把弃牌堆倒回来
    draft.discardPile = {}
  }
  let choice = Math.floor(random * pileCount(draft.drawPile))
  for (const id in draft.drawPile) {
    choice -= draft.drawPile[id]
    if (choice < 0) {
      draft.drawPile[id]--
      player.hand.push({ uid: draft.nextUid++, id, def: cardsById[id] })
      return
    }
  }
}

function clampStats(player) {
  player.health = Math.min(Math.max(player.health, 0), maxHealth)
  player.food = Math.min(Math.max(player.food, 0), maxFood)
}

reducer 必须是纯函数

★ 为什么随机数要从外面传进来

reducer 必须是纯函数：同样的 state 和 action，永远得到同样的结果，不能有副作用（不能发请求、不能设定时器、也不能调用 Math.random()）。 开发模式下 StrictMode 会故意把 reducer 调用两次来检查这一点 —— 如果里面有 Math.random()，两次结果不同，你会看到奇怪的 bug。 所以抽牌需要的随机数放进 action，由事件处理函数生成：dispatch({ type: 'cardDrawn', random: Math.random() })。 这样做还有个好处：测试时传入固定的数，结果就可以预测。

现在写 reducer。每种 action 对应游戏里的一个事件：

export const gameReducer = produce((draft, action) => {
  const player = currentPlayer(draft)
  const opponent = currentOpponent(draft)

  switch (action.type) {
    // 玩家点击了一张牌：从手牌移到弃牌堆（会触发离开动画）
    case 'cardPlayed': {
      if (!draft.canPlay) return              // 不许作弊：一回合只能出一张
      draft.canPlay = false
      const index = player.hand.findIndex((c) => c.uid === action.card.uid)
      player.hand.splice(index, 1)
      draft.discardPile[action.card.id] = (draft.discardPile[action.card.id] ?? 0) + 1
      draft.playingCard = action.card
      return
    }

    // 出牌动画结束：结算效果
    case 'cardApplied': {
      const card = draft.playingCard
      player.lastPlayedCardId = card.id
      card.def.play(player, opponent)         // cards.js 里的函数直接修改草稿
      draft.players.forEach(clampStats)
      return
    }

    // 稍等片刻后：判断胜负，或者进入下一回合
    case 'turnEnded': {
      draft.playingCard = null
      for (const p of draft.players) p.dead = p.health === 0 || p.food === 0
      if (draft.players.some((p) => p.dead)) {
        draft.activeOverlay = 'game-over'
      } else {
        nextTurn(draft)
      }
      return
    }

    // 点击浮层
    case 'overlayClosed': {
      if (draft.activeOverlay === 'player-turn' && draft.turn > 1) {
        draft.activeOverlay = 'last-play'      // 先看看对手出了什么
      } else {
        newTurn(draft)
      }
      return
    }

    // 回合开始后的抽牌
    case 'cardDrawn': {
      drawCard(draft, player, action.random)
      draft.pendingDraw = false
      draft.canPlay = true
      return
    }

    case 'restarted':
      return createInitialState()             // 返回一个全新的状态，替换掉草稿
  }
})

function nextTurn(draft) {
  draft.turn++
  draft.currentPlayerIndex = 1 - draft.currentPlayerIndex
  draft.activeOverlay = 'player-turn'
}

function newTurn(draft) {
  draft.activeOverlay = null
  const player = currentPlayer(draft)
  if (player.skipTurn) {                       // 被卡牌效果跳过
    player.skippedTurn = true
    player.skipTurn = false
    nextTurn(draft)
  } else {
    player.skippedTurn = false
    if (draft.turn > 2) draft.pendingDraw = true   // 抽牌要延迟 800ms，交给组件里的 effect
    else draft.canPlay = true
  }
}
ⓘ 延时怎么办？

原书在游戏逻辑里直接写 setTimeout。reducer 里不能有定时器，所以我们把“需要延时做的事”变成状态（pendingDraw: true）， 由组件里的 useEffect 负责等待 800ms 后 dispatch。后面组装 Game 组件时会看到。

手牌与列表动画

先不加动画

import GameCard from './GameCard.jsx'

export default function CardHand({ cards, onCardPlay }) {
  return (
    <div className="hand">
      <div className="wrapper">
        <div className="cards">
          {cards.map((card) => (
            <GameCard key={card.uid} def={card.def} onPlay={() => onCardPlay(card)} />
          ))}
        </div>
      </div>
    </div>
  )
}

注意 onPlay={() => onCardPlay(card)}：手牌组件本来就知道是哪张牌（map 的循环变量），所以卡牌组件不需要把自己传上来。 key 用 uid 而不是卡牌 id：同一种牌可能有两张，id 不唯一。

React 没有内置过渡组件

元素被移除时做离开动画，难点在于：React 一旦不再渲染某个元素，就会立刻把它从 DOM 删掉，根本没有机会播放动画。 React 本身没有内置的过渡组件，社区最主流的动画库是 Motion（原名 Framer Motion）。

Motion 提供 motion.div、motion.img 等“会动的”元素，用 initial（起始）、animate（目标）、exit（离开）三个属性描述动画； 再用 <AnimatePresence> 包裹，它会在子元素被移除时把它暂时留在 DOM 里，播放完 exit 动画再删除：

列表动画：key 与 layout

给手牌加上三种动画：抽牌时从右侧滑入、出牌时向上放大飞走、其余的牌平滑地移动补位。

import { motion, AnimatePresence } from 'motion/react'
import GameCard from './GameCard.jsx'

export default function CardHand({ cards, onCardPlay, onCardLeaveEnd }) {
  return (
    <div className="hand">
      <div className="wrapper">
        <div className="cards">
          {/* popLayout：离开的元素立刻脱离布局，其余的牌马上开始补位 */}
          <AnimatePresence mode="popLayout" onExitComplete={onCardLeaveEnd}>
            {cards.map((card) => (
              <motion.div
                key={card.uid}
                layout                                            // 位置变化时自动平滑移动
                initial={{ opacity: 0, x: 100, scale: 0.8 }}      // 进入：从右边滑进来
                animate={{ opacity: 1, x: 0, scale: 1 }}
                exit={{ opacity: 0, y: -300, scale: 1.5,          // 离开：向上放大飞走
                        transition: { duration: 1 } }}
                transition={{ duration: 0.3 }}
              >
                <GameCard def={card.def} onPlay={() => onCardPlay(card)} />
              </motion.div>
            ))}
          </AnimatePresence>
        </div>
      </div>
    </div>
  )
}
🔍 layout 动画是怎么实现的

layout 属性用的是 FLIP 技术：React 更新 DOM 后，Motion 测量元素的新位置（Last），和之前的位置（First）比较， 立刻用 transform 把它“推回”旧位置（Invert），再动画到 transform: none（Play）。 因为只动画 transform，性能很好。

✓ 纯 CSS 也能做简单动画

只是进入动画的话，用 CSS 的 @keyframes 或 transition 就够了；难的是离开动画和列表补位，这才是 Motion 的价值所在。 另外，浏览器原生的 View Transitions API 也越来越成熟，React 也在为它提供官方支持，值得关注。

浮层：children 与动态组件

children：让组件接收任意内容

三种浮层的布局和点击行为相同，只是内容不同。我们希望这样使用：

<GameOverlay onClose={...}>
  <PlayerTurn player={...} />
</GameOverlay>

写在组件标签中间的内容，会作为一个特殊的 prop —— children —— 传给组件：

import { motion } from 'motion/react'

export default function GameOverlay({ children, onClose }) {
  return (
    <motion.div
      className="overlay"
      onClick={onClose}
      initial={{ opacity: 0, scale: 0.7 }}
      animate={{ opacity: 1, scale: 1 }}
      exit={{ opacity: 0, scale: 0.7 }}
      transition={{ duration: 0.3 }}
    >
      <div className="content">{children}</div>
    </motion.div>
  )
}

三种浮层内容

import GameCard from './GameCard.jsx'
import { cardsById } from '../cards.js'

export function PlayerTurn({ player }) {
  return (
    <div>
      <div className="big">
        {player.name}，<br />{player.skipTurn ? '你的回合被跳过了！' : '轮到你了！'}
      </div>
      <div>点击继续</div>
    </div>
  )
}

export function LastPlay({ opponent }) {
  if (opponent.skippedTurn) return <div>{opponent.name} 的回合被跳过了！</div>
  return (
    <div>
      <div>{opponent.name} 刚刚打出了：</div>
      <GameCard def={cardsById[opponent.lastPlayedCardId]} />
    </div>
  )
}

function PlayerResult({ player }) {
  const result = player.dead ? 'defeated' : 'victorious'
  return (
    <div className={`player-result ${result}`}>
      <span className="name">{player.name}</span>
      <span className="result">{player.dead ? '战败' : '胜利'}</span>
    </div>
  )
}

export function GameOver({ players }) {
  return (
    <div>
      <div className="big">游戏结束</div>
      {players.map((p) => <PlayerResult key={p.name} player={p} />)}
    </div>
  )
}

LastPlay 直接复用了 GameCard 组件；它在这里不需要 onPlay，不传就是 undefined，点击时什么也不发生。

动态组件：用一个映射表

根据 activeOverlay 显示不同的内容。与其写三个条件判断，不如用一个“名字 → 组件”的对象，把组件赋给一个首字母大写的变量：

import { PlayerTurn, LastPlay, GameOver } from './overlays.jsx'

const overlays = {
  'player-turn': PlayerTurn,
  'last-play': LastPlay,
  'game-over': GameOver,
}

// 在 Game 组件里：
const OverlayContent = overlays[state.activeOverlay]   // 大写开头，JSX 才会把它当组件

<AnimatePresence>
  {state.activeOverlay && (
    <GameOverlay key={state.activeOverlay} onClose={handleOverlayClose}>
      <OverlayContent player={player} opponent={opponent} players={state.players} />
    </GameOverlay>
  )}
</AnimatePresence>
★ 又见 key：强制“换一个新的”

<GameOverlay key={state.activeOverlay}> 的 key 很关键：从 “player-turn” 切到 “last-play” 时 key 变了， React 会把它当成两个不同的元素 —— 旧浮层播放离开动画，新浮层播放进入动画。没有 key，React 只会就地更新内容，不会有切换动画。 “改变 key 来重置一个组件”是 React 里很常用的技巧。

半透明背景单独放在外面淡入淡出，否则会跟着浮层一起缩放：

<AnimatePresence>
  {state.activeOverlay && (
    <motion.div key="bg" className="overlay-background"
                initial={{ opacity: 0 }} animate={{ opacity: 1 }} exit={{ opacity: 0 }} />
  )}
</AnimatePresence>

游戏世界

自定义 Hook：窗口缩放比例

场景中所有尺寸都要乘以一个随窗口宽度变化的比例。这需要监听 resize 事件 —— 一个典型的副作用。 把“状态 + effect”打包成一个以 use 开头的函数，就是自定义 Hook： 

import { useState, useEffect } from 'react'

const getWorldRatio = () => window.innerWidth / 1920

export function useWorldRatio() {
  const [ratio, setRatio] = useState(getWorldRatio)

  useEffect(() => {
    const onResize = () => setRatio(getWorldRatio())
    window.addEventListener('resize', onResize)
    return () => window.removeEventListener('resize', onResize)   // 清理！
  }, [])

  return ratio
}
ⓘ 自定义 Hook 共享的是逻辑，不是状态

每个调用 useWorldRatio() 的组件都会得到自己的一份状态和监听器。自定义 Hook 只是复用了“怎么做”。 要让多个组件共享同一份数据，要么由父组件传 props，要么用 Context（下面马上用到）或状态管理库（第 6 章）。

Context：跨层级传递数据

比例要用在很深的 StatBubble 组件里。一层层通过 props 传（Game → World → Castle → CastleBanners → StatBubble），中间的组件根本不关心它，这叫“prop drilling”。 Context 可以让祖先组件直接“广播”一个值，任意深度的后代都能读取： 

import { createContext, useContext } from 'react'

export const WorldRatio = createContext(1)       // 参数是默认值

export const useRatio = () => useContext(WorldRatio)

const ratio = useWorldRatio()

return (
  <WorldRatio value={ratio}>      {/* React 19：直接用 Context 本身作为 Provider */}
    ...
  </WorldRatio>
)
✓ 别滥用 Context

Context 的值一变，所有读取它的组件都会重新渲染。适合“很多地方都要用、但不常变”的数据：主题、语言、当前用户、这里的缩放比例。频繁变化的复杂状态更适合状态管理库。

会伸缩的旗帜：动态 SVG + 自定义动画 Hook

旗帜的长度随数值变化，所以直接在 JSX 里写 SVG，路径由数据生成：

为了让旗帜平滑伸缩，我们写一个自定义 Hook：输入目标值，输出一个“逐帧逼近目标”的当前值：

import { useState, useEffect, useRef } from 'react'

const easeInOutCubic = (t) => t < .5 ? 4 * t * t * t : 1 - (-2 * t + 2) ** 3 / 2

// 当 target 变化时，在 duration 毫秒内把返回值平滑地过渡到新目标
export function useTween(target, duration = 500) {
  const [value, setValue] = useState(target)
  const valueRef = useRef(target)          // 记住“当前显示到哪了”，不触发渲染

  useEffect(() => {
    const from = valueRef.current
    const start = performance.now()
    let frame
    function tick(now) {
      const t = Math.min((now - start) / duration, 1)
      const v = from + (target - from) * easeInOutCubic(t)
      valueRef.current = v
      setValue(v)
      if (t < 1) frame = requestAnimationFrame(tick)
    }
    frame = requestAnimationFrame(tick)
    return () => cancelAnimationFrame(frame)   // target 又变了或组件卸载：停掉旧动画
  }, [target, duration])

  return value
}

import { useTween } from '../hooks.js'

export default function BannerBar({ color, ratio, className }) {
  const height = Math.round(useTween(220 * ratio + 40))
  return (
    <svg className={className} viewBox="0 0 20 260">
      <path d={`m 0,0 20,0 0,${height} -10,-10 -10,10 z`} style={{ fill: color, stroke: 'none' }} />
    </svg>
  )
}
✓ 用 Motion 一行搞定

Motion 可以直接对 SVG 路径做补间：<motion.path animate={{ d: path }} transition={{ duration: 0.5 }} />， 只要前后路径的结构（命令和数字个数）相同即可。自己写一遍 useTween，是为了理解“动画 = 每帧算一个中间值”。

飘动的云：useRef 与高频动画

云要从左到右匀速飘动，每秒更新 60 次位置。如果每一帧都 setState，组件每秒要重新渲染 60 次 —— 十朵云就是 600 次，完全没有必要。 更好的办法是用 useRef 拿到 DOM 元素，直接修改它的 style，完全绕过 React 的渲染： 

import { useRef, useEffect } from 'react'

const durations = { min: 10000, max: 50000 }   // 10 ~ 50 秒飘过屏幕

export default function Cloud({ type }) {
  const el = useRef(null)    // 渲染后 el.current 就是那个 div

  useEffect(() => {
    const node = el.current
    let frame, start, duration, top

    function startAnimation(delay) {
      duration = Math.random() * (durations.max - durations.min) + durations.min
      top = Math.random() * window.innerHeight * 0.3
      node.style.zIndex = Math.round(durations.max - duration)   // 越快越靠前
      start = performance.now() + delay
      frame = requestAnimationFrame(tick)
    }

    function tick(now) {
      const width = node.clientWidth
      const t = Math.max((now - start) / duration, 0)
      const x = -width + (window.innerWidth + width) * t
      node.style.transform = `translate(${x}px, ${top}px)`
      if (t < 1) frame = requestAnimationFrame(tick)
      else startAnimation(Math.random() * 10000)                 // 飘出屏幕后，随机等一会儿再来
    }

    // 负的延迟 = 动画已经进行了一段时间，开局时云就分散在天空中
    startAnimation(-Math.random() * durations.min)
    return () => cancelAnimationFrame(frame)
  }, [])

  return (
    <div ref={el} className={`cloud cloud-${type}`}>
      <img src={`/svg/cloud${type}.svg`} />
    </div>
  )
}
★ ref 和 state 的区别

useRef 返回一个 { current } 盒子，在多次渲染之间保持不变。修改 ref.current 不会触发重新渲染。 用途有二：① 通过 ref={el} 拿到 DOM 元素；② 存一些“需要记住、但不影响界面”的值（定时器 id、上一次的值，比如上面 useTween 里的 valueRef）。 规则：不要在渲染过程中读写 ref.current，只在 effect 和事件处理函数里用。

组装：Game 组件

最后把所有东西拼起来。先看一遍回合流程中各个 action 的先后顺序：

import { useReducer, useEffect } from 'react'
import { motion, AnimatePresence } from 'motion/react'
import { gameReducer, createInitialState, currentPlayer, currentOpponent } from '../game.js'
import { useWorldRatio, WorldRatio } from '../hooks.js'
import TopBar from './TopBar.jsx'
import World from './World.jsx'
import CardHand from './CardHand.jsx'
import GameOverlay from './GameOverlay.jsx'
import { PlayerTurn, LastPlay, GameOver } from './overlays.jsx'

const overlays = { 'player-turn': PlayerTurn, 'last-play': LastPlay, 'game-over': GameOver }

export default function Game() {
  // 第三个参数是初始化函数：只在第一次渲染时调用
  const [state, dispatch] = useReducer(gameReducer, null, createInitialState)
  const ratio = useWorldRatio()

  const player = currentPlayer(state)
  const opponent = currentOpponent(state)
  const OverlayContent = overlays[state.activeOverlay]

  // 回合开始后延迟抽牌
  useEffect(() => {
    if (!state.pendingDraw) return
    const timer = setTimeout(() => dispatch({ type: 'cardDrawn', random: Math.random() }), 800)
    return () => clearTimeout(timer)
  }, [state.pendingDraw])

  function handlePlayCard(card) {
    dispatch({ type: 'cardPlayed', card })
  }

  function handleCardLeaveEnd() {
    if (!state.playingCard) return
    dispatch({ type: 'cardApplied' })
    setTimeout(() => dispatch({ type: 'turnEnded' }), 700)   // 让玩家看清发生了什么
  }

  function handleOverlayClose() {
    if (state.activeOverlay === 'game-over') dispatch({ type: 'restarted' })
    else dispatch({ type: 'overlayClosed' })
  }

  return (
    <WorldRatio value={ratio}>
      <div className={`game ${state.canPlay ? 'can-play' : ''}`}>
        <TopBar players={state.players} currentPlayerIndex={state.currentPlayerIndex} turn={state.turn} />
        <World players={state.players} />

        <AnimatePresence>
          {!state.activeOverlay && (
            <motion.div key="hand" style={{ transformOrigin: 'bottom center' }}
                        initial={{ opacity: 0, rotateX: 90 }} animate={{ opacity: 1, rotateX: 0 }}
                        exit={{ opacity: 0, rotateX: 90 }} transition={{ duration: 0.8 }}>
              <CardHand cards={player.hand} onCardPlay={handlePlayCard} onCardLeaveEnd={handleCardLeaveEnd} />
            </motion.div>
          )}
        </AnimatePresence>

        <AnimatePresence>
          {state.activeOverlay && (
            <motion.div key="bg" className="overlay-background"
                        initial={{ opacity: 0 }} animate={{ opacity: 1 }} exit={{ opacity: 0 }} />
          )}
        </AnimatePresence>

        <AnimatePresence>
          {state.activeOverlay && (
            <GameOverlay key={state.activeOverlay} onClose={handleOverlayClose}>
              <OverlayContent player={player} opponent={opponent} players={state.players} />
            </GameOverlay>
          )}
        </AnimatePresence>
      </div>
    </WorldRatio>
  )
}
ⓘ can-play 类名

样式表里，只有根元素带有 can-play 类时，手牌才响应鼠标。动画和等待期间 canPlay 为 false，玩家无法连点作弊 —— reducer 里也有一道同样的检查，双保险。

✓ 重新开始不用刷新页面

原书在游戏结束后用 location.reload() 重新开始。有了 reducer，只需 dispatch 一个 restarted action 返回全新的初始状态即可。
